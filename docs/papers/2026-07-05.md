### [Auto: The AGI Compiler](https://arxiv.org/abs/2607.04542v1)

**arXiv cs.AI** · 2026-07-05 · `arXiv:2607.04542v1`

Auto is a compiler that converts live LLM agent behavior into verified, deterministic programs and distilled specialists, significantly reducing inference cost and improving efficiency.

- Auto records LLM agent behavior, identifies deterministic segments, and extracts them into verified programs or distilled specialists.
- It emits cognition binaries as WebAssembly artifacts with measured guarantees and physically enforced capabilities.
- A tiered runtime executes compiled behavior, with guard trips deoptimizing to the reference agent and recompiling captured traces.
- On AUTO-BENCH, 87.1% of 560 recorded frontier-agent spans were witnessed-deterministic, with three task families at 100.0%.
- Auto reduced marginal cost from 59 to 2 micro-dollars per item (6.4x end-to-end) on a 300-item stream with distribution shifts, maintaining 96.9% parity.

**Why it matters:** This system offers a method to autonomously convert novel LLM agent experience into permanent, verified, and near-free skills, addressing the expense and slowness of frontier models.

### [Obey, Diverge, Collapse: Blind Obedience to Incorrect Instructions Drives Code LLMs to Irrecoverable Code Semantic Collapse](https://arxiv.org/abs/2607.04537v1)

**arXiv cs.AI** · 2026-07-05 · `arXiv:2607.04537v1`

This study reveals that code language models exhibit "Blind Obedience" to incorrect instructions, introducing unrecoverable errors and semantic corruption, even when models identify the instruction as wrong.

- Code LLMs, when given incorrect instructions, identify the instruction as wrong but follow it anyway, a behavior termed "Blind Obedience."
- Following incorrect instructions introduces "Ghost (Unknown) Errors" beyond the original bug, corrupting the code state.
- Subsequent self-guided iterative repair fails to converge, rendering the corrupted code state unrecoverable.
- The evaluation used the RunBugRun dataset of algorithmic Python problems with deterministic test cases, assessing single-pass and iterative repair settings.

**Why it matters:** This behavior has direct consequences for code language models deployed in production, as it can lead to irrecoverable code semantic collapse.

### [Transplanting, inverting, and preventing a misalignment persona: method-conditional emergent misalignment in Qwen2.5](https://arxiv.org/abs/2607.04510v1)

**arXiv cs.AI** · 2026-07-05 · `arXiv:2607.04510v1`

Emergent misalignment in Qwen2.5 models is mediated by a latent persona direction, which can be transplanted, inverted, and prevented, with recruitment depending on fine-tuning method and capacity.

- A latent persona direction in Qwen2.5 models mediates emergent misalignment (EM) and is causal in open weights.
- Transplanting this persona direction into a pretraining-shared model induces broad EM (2.83% misaligned vs. 1.1% random floor), while ablating a model's own direction halves an overt inducer's broadcast (21% to 10%).
- Low-rank LoRA on insecure code recruits the persona (3.4% misaligned) on Qwen2.5-32B, whereas full SFT on identical data does not (0.3%) and moves against the persona axis.
- Steering a bad-medical SFT run away from the persona direction during training increases broadcast from 24% to 51%, indicating that removing the direction is not a universal solution.
- Inoculation removes persona recruitment selectively (4.75% to 0.0%), and fine-tuning orthogonal to the behavior-derived axis reduces persona-specific misalignment.

**Why it matters:** Understanding and controlling this persona direction allows for targeted prevention and mitigation of emergent misalignment in large language models, especially in cost-effective fine-tuning regimes.

### [Uncertainty-Aware Abstention in Large Language Models with Provable Alignment Guarantees](https://arxiv.org/abs/2607.04430v1)

**arXiv cs.CL** · 2026-07-05 · `arXiv:2607.04430v1`

CIC is a confidence-interval-based calibration framework that converts arbitrary uncertainty scores into risk-controlled selective answering rules for LLMs, providing provable alignment guarantees.

- CIC uses a held-out calibration set to evaluate LLM responses with an application-specific alignment criterion, associating each with an uncertainty score and a binary error label.
- For each candidate uncertainty threshold, CIC estimates the acceptance-conditioned error rate and constructs a high-probability upper confidence bound using Hoeffding-style or Clopper-Pearson confidence intervals.
- CIC selects the largest threshold whose upper bound is below a user-specified risk level α, maximizing the answering rate subject to a finite-sample reliability constraint.
- Under exchangeability, CIC guarantees with probability at least 1-δ that the selected threshold controls the error rate among accepted answers at level α.
- Evaluated across seven LLMs and multiple uncertainty estimators on closed-ended and open-ended QA benchmarks, CIC consistently achieves valid risk control and strong answering efficiency.

**Why it matters:** This framework offers a statistically grounded mechanism for deploying LLMs in reliability-sensitive QA workflows by controlling error rates among accepted answers.

**arXiv cs.AI** · 2026-07-05 · `arXiv:2607.04528v1`

This paper introduces a belief-rollout diagnostic and BIWM protocol to measure and align multi-step belief divergence in LLM agents caused by harness variations, even when terminal success is preserved.

- Harnesses, controlling agent visibility, actions, repairs, verification, and logging, can alter an LLM agent's multi-step beliefs despite fixed task, environment, and base LLM.
- A belief-rollout diagnostic elicits structured K-step trajectories covering progress, risk, recoverability, constraints, failure mode, uncertainty, future success, repair cost, and next action under different harnesses.

**Why it matters:** Harness design significantly impacts LLM agent evaluation, suggesting it is an experimental variable rather than an implementation detail, which is crucial for reliable benchmark interpretation.
