### [Daedalus-150M: A Convolution-Attention Hybrid Designed for CPU Inference](https://arxiv.org/abs/2608.20210)

**Why it matters:** By restricting attention to a fraction of layers, hybrid architectures can drastically reduce the memory and compute overhead of long context lengths on standard CPUs.

- Assigns an active-presence coefficient p_i = \|\|h_i\|\|^2 / (tau + \|\|h_i\|\|^2) to token carriers, gating emitted information and weighting shared computations.

- A two-block ablation confirmed that OAttention requires the full OTransformer path to preserve NULL states through host model components.

**Why it matters:** It enables mathematically exact null-token dynamics and inert zero-vector insertions without altering standard attention scoring or requiring retraining from scratch.

### [Don't Solve, Just Compare: Tiny Advisors for Runtime Intervention in LLM Agents](https://arxiv.org/abs/2608.21027v1)

**arXiv cs.AI** · 2026-08-21 · `arXiv:2608.21027v1`

Comparison-Only Tiny Advisor (COTA) improves LLM agent reliability by using a small model to compare candidate continuations and supply non-binding advice without needing full task-solving capabilities.

- COTA replaces expert solvers and heavy task-capable critics with a small comparator that evaluates whether sampled alternative steps outperform the actor's initial proposal.
- The comparator is trained via pairwise supervision derived from same-prefix counterfactual execution branches.
- When intervention is triggered through repeated comparisons, preferred alternatives are provided as non-binding advice to let the original actor replan.
- Evaluated across WebShop, ALFWorld, and tau^3-Retail using three different base actors, COTA improved performance across all nine test configurations compared to baselines.

**Why it matters:** It demonstrates that runtime intervention can enhance LLM agent performance using lightweight auxiliary models that possess significantly less task-solving capacity than the primary actor.

### [Utility Under Attack: Agent Memory Poisoning and the Limits of Content Screening and Provenance Ranking](https://arxiv.org/abs/2608.21230v1)

**arXiv cs.AI** · 2026-08-21 · `arXiv:2608.21230v1`

A study demonstrates that unoptimized false assertions in 1.2% of a agent memory corpus reduce retrieval accuracy from 0.850 to 0.300, while bypassing content screening and breaking additive provenance ranking.

- Poisoning 1.2% of a LongMemEval corpus with single-pass, unoptimized false assertions drops task accuracy from 0.850 to 0.300.
- A four-stage write-time screening pipeline that achieved 0.832 recall on indirect prompt injection failed completely, rejecting 0 out of 360 poisoned memories.
- Additive provenance weighting fails (p=0.80): weights strong enough to suppress query-shaped poison also suppress valid untrusted evidence, dropping accuracy to 0.0417 when answers rely on untrusted sources.
- Authors advocate for bounded occupancy constraints during retrieval rather than content-only screening or additive provenance penalties.

**Why it matters:** Simple memory poisoning attacks easily bypass standard safety guardrails and reveal fundamental flaws in relying on additive provenance weights to secure persistent LLM memory.

### [Personalized Privacy Control in LLMs via Attention Head Intervention](https://arxiv.org/abs/2608.21209v1)

**arXiv cs.AI** · 2026-08-21 · `arXiv:2608.21209v1`

Researchers introduce personalized privacy for LLMs, evaluate prompt failures via P3Bench, and propose REPAIR, an inference-time attention head intervention method to enforce user-specific disclosure preferences.

- P3Bench extends contextual privacy policies by adding user-specific disclosure preferences to evaluate LLM privacy control.
- Standard prompt-based policies fail to enforce personalized privacy, yielding policy ignorance ratios of 51.25% in Qwen2.5-7B and 74.28% in Gemma3-4B.
- REPAIR applies robust inference-time interventions on attention heads to adjust model behavior toward policy-consistent outputs without retraining.

**Why it matters:** System prompts alone are insufficient to prevent LLM agents from leaking sensitive user data, making internal mechanistic interventions like REPAIR necessary for reliable privacy enforcement.

<small>Junseok Kim, Nakyeong Yang, Kyomin Jung</small>
