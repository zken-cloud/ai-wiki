### [Benchmarking LLM Inference at Scale with AIPerf](https://developer.nvidia.com/blog/benchmarking-llm-inference-at-scale-with-aiperf/)

**NVIDIA Developer Blog** · 2026-09-18

AIPerf provides a standardized benchmarking framework to address the performance and concurrency limits of single-process, Python-based LLM load generators.

- Ad-hoc benchmarking methods like curl commands and custom asyncio scripts suffer from Python Global Interpreter Lock (GIL) concurrency bottlenecks.
- Single-process load generators fail to provide accurate scaling measurements for LLM inference systems under heavy load.
- AIPerf introduces a structured approach to measure LLM inference throughput and latency without single-process performance caps.

**Why it matters:** Standardized, multi-process load testing enables engineers to accurately assess and optimize production LLM inference scaling without hitting client-side runtime bottlenecks.

### [Introducing Amazon SageMaker HyperPod Inference Gateway](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-sagemaker-hyperpod-inference-gateway/)

**AWS Machine Learning Blog** · 2026-09-18

AWS announced Amazon SageMaker HyperPod Inference Gateway, an EKS-managed addon providing GPU-aware, L7 request routing to reduce first-token latency by up to 82% without application code changes.

- Deploys as an EKS managed addon ('amazon-sagemaker-hyperpod-inference') using Envoy Gateway, Body-Based Router (BBR), and Endpoint Picker (EPP) components based on the open-source Gateway API Inference Extension.
- EPP uses weighted, configurable scoring based on real-time Prometheus metrics including KV cache utilization, queue depth, LoRA adapter residency, prefix cache hit rate, and running request counts.
- Body-Based Router parses OpenAI-compatible request bodies to direct traffic to appropriate model pools for multi-model serving.
- Reduces first-token latency from over 4.4 seconds down to under 800 ms during traffic bursts by eliminating naive round-robin/least-connections routing bottlenecks.

**Why it matters:** It improves LLM inference resource utilization and latency on Kubernetes GPU clusters without requiring sidecars, service meshes, or model server code modifications.
