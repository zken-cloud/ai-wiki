### [F3 Lightning: How Meta Accelerates Ads ML Features to Production at Scale](https://engineering.fb.com/2026/11/03/ml-applications/f3-lightning-how-meta-accelerates-ads-ml-features-to-production/)

**Meta Engineering** · 2026-11-03

Meta introduced F3 Lightning, an infrastructure layer for its ads ranking feature framework that decouples feature releases from shared graph execution to enable independent deployment without increasing CPU overhead.

- F3 Lightning replaces the legacy all-or-nothing release model, allowing features to be compiled, validated, deployed, and rolled back independently.
- The system prevents compute inefficiencies using stable computation identifiers, a single shared execution plan, a unified memory buffer, and dense index mapping for direct array access.
- Extraction features reach production approximately 3.6x faster compared to the previous F3 system while maintaining identical infrastructure compute costs.

**Why it matters:** By eliminating release blockages caused by bad feature definitions, engineering teams can iterate and ship machine learning models significantly faster at scale.

### [Building ultra-low-latency voice AI applications on AWS](https://aws.amazon.com/blogs/machine-learning/building-ultra-low-latency-voice-ai-applications-on-aws/)

**AWS Machine Learning Blog** · 2026-11-03

AWS partner Cartesia is utilizing State Space Model (SSM) architectures on AWS infrastructure to deliver sub-100ms speech-to-text and text-to-speech for real-time voice applications.

- State Space Models (SSMs) process sequences step-by-step with a fixed-size hidden state, avoiding quadratic computational growth and heavy token caching found in transformer architectures.
- SSMs use structured linear recurrences to preserve information across long audio sequences without the long-range signal decay common in traditional LSTMs.
- Cartesia implemented SSM architecture in two production voice models: Sonic for speech generation and Ink for speech transcription.
- The step-by-step recurrent structure provides native, token-by-token streaming capabilities without requiring architectural modifications.

**Why it matters:** Replacing transformer models with SSMs removes the trade-off between speech quality and latency, enabling sub-100ms conversational AI responses that match natural human turn-taking.

### [Introducing India-based inference for Kimi K3 on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/introducing-india-based-inference-for-kimi-k3-on-amazon-bedrock/)

**AWS Machine Learning Blog** · 2026-11-03

Amazon Bedrock now supports in-country cross-Region inference in India for Moonshot AI's Kimi K3 multi-modal open-weight model using the `in.moonshotai.kimi-k3` profile.

- The India geographic inference profile (`in.moonshotai.kimi-k3`) restricts data processing strictly to the Mumbai (ap-south-1) and Hyderabad (ap-south-2) AWS Regions.
- Data transmitted via cross-Region inference profiles is encrypted in transit and stays on the internal AWS network without routing over the public internet.
- Prompt caching with Kimi K3 on Bedrock reduced LLM costs by 80 percent and accelerated multi-turn chat performance by 85 percent for production workloads.
- Supports direct multi-modal reasoning over Indic-language scanned documents, eliminating the need for standalone OCR or translation pipelines.

**Why it matters:** Enables organization in India to deploy Kimi K3 for complex multi-modal and Indic-language workloads while adhering to strict local data residency compliance requirements.
