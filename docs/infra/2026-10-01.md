### [From Upstream Changes to Downstream Confidence: Inside Torch Spyre’s Integration with PyTorch CRCR](https://pytorch.org/blog/from-upstream-changes-to-downstream-confidence-inside-torch-spyres-integration-with-pytorch-crcr/)

**PyTorch Blog** · 2026-09-30

Torch Spyre achieved L2 integration with PyTorch's Cross-Repository CI Relay (CRCR) using an agentic test-selection pipeline, declarative YAML test adaptation, and reliable workflow patterns for out-of-tree accelerators.

- PyTorch's Cross-Repository CI Relay (CRCR) uses repository_dispatch events and composite callbacks to trigger downstream CI on upstream changes and report results to the PyTorch CI CRCR HUD.
- CRCR offers four integration levels (L1-L4), allowing out-of-tree (OOT) backends to progress from basic dispatch notifications to reporting results and participating in upstream PR validation.
- Torch Spyre implements an agentic pipeline to select and re-bucket tests using code and execution evidence alongside a declarative YAML framework that adapts CUDA-written upstream tests without patching or forking them.
- The integration addresses three moving target candidates in testing: the OOT accelerator backend codebase (e.g., Torch Spyre via privateuse1), PyTorch core, and the evolving PyTorch test suite.

**Why it matters:** It provides a reusable, non-forking framework for out-of-tree hardware accelerators to automatically validate upstream PyTorch changes and report regressions directly to PyTorch maintainers.
