### [Announcing Humming: Fast, Flexible Kernels for Quantized Inference](https://vllm.ai/blog/2026-10-21-humming)

**vLLM Blog** · 2026-10-21

Ant Group and the vLLM community have open-sourced Humming, a unified, high-performance CUDA kernel library designed for quantized model inference across dense and MoE architectures.

- Supports multiple quantization schemes including WnA16, W8A8, W4A8, and W4A4 across INT4 and NVFP4 numeric formats.
- Decouples quantization descriptions from execution choices by converting export formats into a standardized Humming format with unified scales, zero points, and weight layouts.
- Utilizes workload-specific tuning, JIT compilation, and shared CUDA components to optimize memory bandwidth and compute efficiency for prefill, decode, and MoE expert execution.
- Addresses large-scale deployment constraints, such as storing 671B parameter MoE models like DeepSeek-V3 while maintaining low dequantization and scheduling overhead.

**Why it matters:** Humming eliminates the maintenance burden of writing dedicated CUDA kernels for every quantization format while delivering high-throughput, low-latency quantized inference on GPUs.

### [Introducing TorchTPU](https://pytorch.org/blog/introducing-torchtpu/)

**PyTorch Blog** · 2026-10-20

TorchTPU is a native, open-source PyTorch backend for Google TPUs developed by Google and Meta, offering eager execution, torch.compile support, and code compatibility via device assignment like .to("tpu").

- Replaces PyTorch/XLA's Lazy Tensor model with a native backend using Torch Dynamo for torch.compile() and a new DeferAndFuse eager execution mode.
- Eliminates JAX runtime dependencies while supporting low-level PyTorch distributed primitives, including DDP, FSDP, DTensor, and the Process Group API.
- Implements forward and backward passes for ~450 core ATen operators required for major deep learning architectures.
- Introduces TPU compilation optimizations to handle bounded dynamism, preventing XLA recompilation caused by dynamic shape changes.

**Why it matters:** It allows PyTorch workloads to run on Google TPUs out-of-the-box with minimal code changes, providing an alternative to GPU infrastructure without sacrificing native PyTorch idioms or performance.

### [From KTIR to SpyreCode: An MLIR Dataflow Backend for IBM Spyre](https://pytorch.org/blog/from-ktir-to-spyrecode-an-mlir-dataflow-backend-for-ibm-spyre/)

**PyTorch Blog** · 2026-10-20

IBM and PyTorch introduced KTIR and DataflowIR, open-source MLIR dialects that translate Torch-Inductor layout and tiling decisions into dataflow pipelines and binary launch plans for the IBM Spyre accelerator.

- KTIR (Kernel Tile IR) serves as an MLIR contract capturing Inductor's data-parallel mapping, work division, and global-memory views across multi-core scratchpads.
- An open-source Dataflow Scheduler consumes KTIR to build nested, double-buffered pipelines by decoupling memory access and compute via FIFOs.
- The Dataflow Scheduler produces DataflowIR, which device-specific stages lower into SpyreCode—a symbolic SpyreBinary and job plan populated with shapes and addresses at runtime.
- The scheduler and its intermediate representations are open-sourced under Apache-2.0 and rely on standard MLIR dialects like linalg, scf, memref, and tensor.

**Why it matters:** It establishes an open-source, MLIR-native compilation pipeline that allows PyTorch Inductor and DSLs like Triton to efficiently lower dataflow schedules onto specialized accelerator hardware.

### [Introducing vLLM TorchTPU](https://vllm.ai/blog/2026-10-20-vllm-torchtpu)

**vLLM Blog** · 2026-10-20

vLLM TorchTPU is a new out-of-tree platform plugin that enables serving unmodified vLLM model definitions on Google Cloud TPUs using Google's TorchTPU stack.

- Compiles models lowered to XLA via torch.compile(backend="tpu") while dedicating a worker process per TPU device managed via torch.distributed.
- Integrates JAX/Pallas custom kernels directly inside the compiled graph for hand-tuned complex TPU operations.
- Supports all six vLLM parallelism dimensions across both single-host and multi-host TPU slices.
- Installs via `pip install vllm-torchtpu` on Python 3.12 Cloud TPU VMs, automatically linking via the vllm.platform_plugins entry point.

**Why it matters:** It allows developers to run standard vLLM models, API features, and scheduling on Google Cloud TPU infrastructure without altering model code.
