### [Extending LLDB to Debug Applications That Span CPUs and GPUs](https://engineering.fb.com/2026/11/09/developer-tools/extending-lldb-to-debug-applications-that-span-cpus-and-gpus/)

**Meta Engineering** · 2026-11-09

Meta and ecosystem engineers built a vendor-neutral accelerator plugin architecture in lldb-server to debug applications spanning CPUs and GPUs within a single debugging session.

- Separates shared LLDB debugger infrastructure from hardware-specific device control by representing the CPU and GPU as separate processes.
- Implements a vendor-neutral plugin interface inside lldb-server that coordinates with GPU runtimes and translates device debugging APIs into standard LLDB concepts.
- Addresses CPU and GPU architectural differences, including divergent instruction sets, independent memory address spaces, distinct register contexts, and massively parallel GPU execution lanes.
- Uses the standard GDB remote protocol between the LLDB client and lldb-server, avoiding unified process models that require conditional hardware checks for memory reads, breakpoints, and stepping.

**Why it matters:** It enables developers to debug cross-boundary CPU-GPU workloads in a unified LLDB session without relying on vendor-siloed debugging tools like ROCgdb or CUDA-GDB.

**AWS Machine Learning Blog** · 2026-11-09

Anthropic's Claude Fable 5.2 and Mythos 5.2 models are now available on AWS, offering enhanced autonomous multi-step reasoning, improved alignment, and specific domain capabilities for technical, coding, and scientific workloads.

- Claude Fable 5.2 supports long-running, multi-day agentic workflows across large codebases, science, math, financial analysis, and 3D design.
- Claude Mythos 5.2 is restricted to verified programs for advanced cyber security (red teaming, penetration testing) and life sciences (biomolecular design).

- Developers can invoke Fable 5.2 programmatically using the Anthropic Messages API, or the standard AWS Bedrock Invoke and Converse APIs via Boto3 and AWS CLI.

**Why it matters:** These models enable enterprises to run highly autonomous, long-duration software engineering and scientific agents on AWS infrastructure while maintaining specialized compliance and prompt-caching cost controls.

### [Pluggable Agentic AI Framework: A seven-layer composable enterprise agentic AI reference architecture on Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/pluggable-agentic-ai-framework-a-seven-layer-composable-enterprise-agentic-ai-reference-architecture-on-amazon-bedrock-agentcore/)

**AWS Machine Learning Blog** · 2026-11-09

AWS introduced the Pluggable Agentic AI Framework, a seven-layer composable reference architecture built on Amazon Bedrock AgentCore to scale enterprise multi-agent applications from prototype to production.

- The architecture defines seven decoupled layers with distinct responsibilities to handle routing, guardrails, observability, and data retrieval without hardwiring application logic.
- The Data and Knowledge layer manages structured/unstructured retrieval using tools like Amazon Bedrock Knowledge Base, OpenSearch Serverless Vector Engine, Amazon S3 Vectors, and Amazon DynamoDB.
- The Model and Inference layer utilizes a proxy like LiteLLM to decouple agents from model providers, enabling dynamic routing based on cost, latency, and reasoning needs.
- The Orchestration layer advocates for specialized agents led by a supervisor over single monolithic agents to avoid tool sprawl, expanded context windows, increased latency, and safety failures.

**Why it matters:** It prevents AI development teams from repeatedly rebuilding custom infrastructure by providing a standardized blueprint for security, governance, and scale.
