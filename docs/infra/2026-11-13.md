### [Fast by Default: Compile-Time Heuristics for Helion Kernels](https://pytorch.org/blog/fast-by-default-compile-time-heuristics-for-helion-kernels/)

**PyTorch Blog** · 2026-11-12

Helion now uses compile-time heuristics that analyze kernel IR and dataflow to configure block sizes, warps, and stages, delivering high performance without autotuning overhead.

- Analyzes device IR to classify kernels into broad families—matmul, reduction, or pointwise—based on contained operations like hl.dot or torch.baddbmm.
- Eliminates autotuning compilation overhead, adding only tens of milliseconds of analysis time while generating near-autotuned configs.
- Achieves 1.18x higher forward pass performance than hand-written Triton in Flash Linear Attention (FLA) on H100 GPUs across 96 shape cells.
- Outperforms vLLM's handwritten CUDA/C++ reduction kernels by 1.27x on H100 GPUs across 153 kernel-and-shape cells.
- Generates a high-performing default config when autotuning is disabled, or emits 5–20 targeted seed configs to accelerate search when autotuning is enabled.

**Why it matters:** It eliminates multi-hour autotuning bottlenecks for custom ML kernels while outperforming hand-written CUDA and Triton implementations out of the box.

### [Deploy frontier AI models on AWS Trainium with SGLang-Neuron](https://aws.amazon.com/blogs/machine-learning/deploy-frontier-ai-models-on-aws-trainium-with-sglang-neuron/)

**AWS Machine Learning Blog** · 2026-11-12

AWS, RadixArk, and Annapurna Labs released SGLang-Neuron, an out-of-tree plugin allowing SGLang serving and RL rollout workloads to run on AWS Trainium chips using native PyTorch.

- Uses an out-of-tree plugin architecture registered via SGLANG_PLATFORM=neuron to allow independent development from SGLang core.
- Executes models via native PyTorch operations, Neuron Kernel Interface (NKI) kernels, and torch.compile inside a dedicated graph runner.
- Supports Prefill-Decode (PD) disaggregation, transferring the KV cache from prefill to decode servers using NIXL over Elastic Fabric Adapter (EFA).
- Provides a Deep Learning Container (pytorch-inference-sglang-neuron) supporting features like RadixAttention, FP8 KV-caching, MoE, and chunked prefill.

**Why it matters:** Developers can deploy large language models on lower-cost AWS Trainium hardware while preserving their existing SGLang serving workflows, APIs, and performance optimizations.

### [DeepSeek-V4.1-Flash on Vera Rubin NVL72: 58x Throughput vs. GB300 NVL72 at 387 tokens/s](https://vllm.ai/blog/2026-11-12-deepseek-v41-flash-vera-rubin)

**vLLM Blog** · 2026-11-12

vLLM optimized DeepSeek-V4.1-Flash on a NVIDIA Vera Rubin NVL72 rack, achieving up to 1.7M tokens/s per GPU at 387 tokens/s per user, representing a 58x throughput improvement over GB300 NVL72.

- Achieves a peak throughput of 2.52M tokens/s per GPU and up to 1,810 tokens/s for a single user under the SemiAnalysis AgentX benchmark.
- Prefill kernel optimizations (Mega-mHC die-local residual, MegaAttn pipelining, MegaGate contender filtering) reduced 32K-token DEP2 prefill step time by ~28%.
- Decode step time was reduced by ~25% using specialized low-latency decode kernels and Wide-EP dispatch.
- Hardware optimizations leverage Rubin's split memory domains, SM107 FP4 tensor cores, and rack-wide shared memory pools (KV cache and Engram tables) over NVLink.

**Why it matters:** The architectural and kernel-level optimizations significantly increase serving throughput and lower latency for agentic LLM workloads on next-generation rack-scale compute systems.

**vLLM Blog** · 2026-11-12

vLLM has added day-0 support for Thinking Machines' Inkling 2 Small, a 594B total (17B active) parameter multimodal MoE model, featuring specialized kernel fusions and native DSpark speculative decoding.

- Inkling 2 Small utilizes a 5:1 sliding-window to full GQA ratio with learned relative bias, block attention residuals, gated attention, and a 23-layer ViT image encoder.
- Employs mixed-precision MoE using NVFP4 with 'Four-Over-Six' dual-candidate block scaling for the first 40 layers and MXFP8 for the final 8 layers.
- Fuses memory-bound operations into an allreduce_conv_mix kernel operating over NVLink multicast and uses Programmatic Dependent Launch (PDL) to overlap kernel prologues and tails.
- Integrates a 5-layer DSpark speculator with an RNN head to draft 7 tokens per step, achieving up to 630 TPS/user at TP4 with an acceptance length of 3.5.
- Supports sequence parallelism for prefill, inline expert activation quantization during routing/activation steps, and LoRA serving.

**Why it matters:** The day-0 integration enables immediate, highly optimized inference and speculative decoding for a complex 594B multimodal MoE architecture directly within the vLLM framework.

### [Four Amazon Bedrock inference choices that affect cost](https://aws.amazon.com/blogs/machine-learning/four-amazon-bedrock-inference-choices-that-affect-cost/)

**AWS Machine Learning Blog** · 2026-11-12

Amazon Bedrock API request parameters—including prompt cache TTL, service tier, reasoning effort, and maxTokens—directly affect token billing metrics and overall inference costs.

- Prompt caching for supported Anthropic models offers 5-minute (billed at 1.25x input token price) and 1-hour (billed at 2.0x) TTL options, while cache reads cost 0.1x.
- A 1-hour TTL cache becomes more cost-effective than a 5-minute TTL starting from the second reused request within that hour.
- Cache evaluation occurs in the order of tools, system instructions, and messages; altering any earlier section invalidates subsequent cached checkpoints and triggers a new cache write.
- Prompt caching requires on-demand inference and does not function with batch inference.
- Reasoning tokens generated during model execution are billed as standard output tokens.

**Why it matters:** Engineers can optimize Amazon Bedrock billing without altering underlying prompts or models by structuring API payloads to leverage prompt caching pricing thresholds and minimize cache invalidations.

### [Automating AWS Agent Registry updates with push-based architecture](https://aws.amazon.com/blogs/machine-learning/automating-aws-agent-registry-updates-with-push-based-architecture/)

**AWS Machine Learning Blog** · 2026-11-11

AWS details an event-driven, push-based architecture using CloudTrail, EventBridge, and Lambda to automatically synchronize AWS Agent Registry metadata whenever Model Context Protocol (MCP) server schemas update.

- AWS CloudTrail detects MCP server updates by capturing management events from the UpdateAgentRuntime API call.
- Amazon EventBridge routes and forwards events across accounts from an MCP server runtime account (Account B) to a central registry account (Account A).
- AWS Lambda extracts the runtime ARN, queries the updated MCP server for tool schemas, diffs the changes against the registry, and executes the updates.
- AgentCore Identity handles OAuth token exchanges to authenticate the Lambda sync function without storing hardcoded secrets.

**Why it matters:** Automating metadata synchronization prevents stale schemas in the AWS Agent Registry, avoiding runtime errors and ensuring consumer applications discover new MCP server capabilities instantly.
