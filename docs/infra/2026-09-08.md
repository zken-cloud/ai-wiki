### [GLM 5.3 Optimizations, Part 1: Hybrid HiSparse Offloading in vLLM](https://vllm.ai/blog/2026-09-08-glm53-part1-hybrid-sparse-offloading)

**vLLM Blog** · 2026-09-08

vLLM introduced Hybrid HiSparse offloading for GLM 5.3, enabling 1M context lengths on an 8x H200 node by offloading non-selected sparse-MLA KV cache pages to CPU only under memory pressure.

- Leverages GLM 5.3's IndexShare architecture (one indexer layer per four sparse-MLA layers) to keep small indexer KVs GPU-resident while offloading non-top-K tokens to CPU.
- Operates dynamic three-state page residency tracked per page, leasing hot buffer pages directly from vLLM's Hybrid Memory Allocator (HMA) block pool.
- Proactively queues copies of completed cacheable prefix pages to CPU memory, allowing instant release of GPU blocks when memory pressure rises.

**Why it matters:** It eliminates memory bottlenecks on tightly constrained hardware, allowing single-node deployments to serve high-concurrency agentic workloads at massive context lengths.
