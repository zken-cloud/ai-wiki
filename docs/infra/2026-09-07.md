### [Serving LLMs on Tenstorrent Hardware: Inside the vLLM TT Plugin](https://vllm.ai/blog/2026-09-07-vllm-tt-plugin)

**vLLM Blog** · 2026-09-07

Tenstorrent accelerators are now integrated into vLLM via an out-of-tree platform plugin that uses hand-written TTNN implementations from TT-Metal.

- Registers models via a TT-prefixed architecture convention (e.g., TTQwen3_5ForConditionalGeneration) that resolves directly to implementations in TT-Metal.
- Supports custom model loading without source edits using the EXTRA_MODELS_DIR environment variable and a vllm_metadata.json configuration.
- Supports multimodal and text models out-of-the-box, including Llama 3.2 Vision, Qwen-VL, Qwen 3.6, Mistral 3, and Gemma 3.
- Targets hardware setups ranging from small on-card core meshes (n150, n300) up to 32-chip Wormhole Galaxy systems using FABRIC_1D, FABRIC_2D, and FABRIC_1D_RING mesh topologies.

**Why it matters:** Users can serve LLMs on Tenstorrent mesh architectures using standard OpenAI-compatible vLLM APIs without modifying core vLLM code.

`vllm` `tenstorrent` `hardware` `llm-serving` `tt-metal`
