### [vLLM Sessions at PyTorch Conference North America 2026](https://pytorch.org/blog/vllm-sessions-at-pytorch-conference-north-america-2026/)

**PyTorch Blog** · 2026-08-28

PyTorch Conference NA 2026 will feature technical sessions on vLLM, highlighting native tiered KV cache offloading, disaggregated prefill/decode serving, and Elastic Expert Parallelism.

- Native tiered KV cache offloading is integrated directly into vLLM, utilizing CPU memory as a universal transport hub to minimize GPU overhead without external dependencies.
- Disaggregated serving features bidrectional KV transfer, a KV Push connector, and KV cache leases, which reduce time to first token and Pareto-dominate co-located serving on Nemotron.
- Elastic Expert Parallelism allows vLLM runtime environments to dynamically add or remove workers and redistribute experts across available nodes.
- A model-customized KV Cache Planner introduces model-specific planners to handle distinct KV cache requirements for architectures like MLA, SWA, Eagle, and DeepSeek-V4.
- LMCache offers cluster-wide prompt caching across vLLM, SGLang, and TensorRT-LLM, interfacing with backends like Mooncake, Redis, and AWS S3.

**Why it matters:** These architectural updates in vLLM enhance memory efficiency, lower latency, and enable dynamic scaling for high-throughput production LLM serving.

### [Batch write and discover records in Amazon SageMaker Feature Store](https://aws.amazon.com/blogs/machine-learning/batch-write-and-discover-records-in-amazon-sagemaker-feature-store/)

**AWS Machine Learning Blog** · 2026-08-28

Amazon SageMaker Feature Store has launched the BatchWriteRecord and ListRecords APIs to enable multi-record batch ingestion and record enumeration across storage tiers.

- BatchWriteRecord allows writing up to 25 records across multiple feature groups in a single API call with partial-success semantics and per-record TTL control.
- BatchWriteRecord maintains EventTime-based ordering guarantees, writing newer records to the online store as the latest version and older ones as historical versions in the offline store.
- ListRecords enables paginated enumeration of record identifiers within a feature group for both Standard (DynamoDB-backed) and In-Memory (Redis-backed) storage tiers.
- Minimum IAM permissions for the new capabilities require actions for sagemaker:BatchWriteRecord, sagemaker:PutRecord, and sagemaker:ListRecords.

**Why it matters:** These APIs reduce API call overhead and tail latency for high-throughput feature ingestion pipelines while preventing unrecoverable data loss in In-Memory storage tiers.
