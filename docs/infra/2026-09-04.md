### [Migrate agentic workloads to Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/migrate-agentic-workloads-to-amazon-bedrock-agentcore/)

**AWS Machine Learning Blog** · 2026-09-03

AWS details a framework-agnostic migration path for agentic workloads to Amazon Bedrock AgentCore, offloading operational burdens like compute patching, tool authorization, and state management.

- Stage 1 migrates existing LangGraph agents unchanged onto AgentCore Runtime, Gateway, and Memory to eliminate server management and state storage burdens.
- Stage 2 replaces hardcoded graph routing with model-driven planning using Strands Agents and Model Context Protocol (MCP) tools hosted on Gateway via AWS Lambda.
- AgentCore Runtime isolates sessions using one microVM per session, with options to run on AWS-managed infrastructure or attach to a customer-owned VPC.
- AgentCore Memory manages durable conversation state keyed on actor_id and session, replacing local state options like LangGraph's MemorySaver.

**Why it matters:** Developers can decouple agentic reasoning from infrastructure management, allowing them to offload compute scaling, tool authentication, and session persistence to fully managed AWS services.
