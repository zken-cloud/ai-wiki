### [Spreading the load: How Salesforce met Multi-AZ HA with SageMaker Inference Components](https://aws.amazon.com/blogs/machine-learning/spreading-the-load-how-salesforce-met-multi-az-ha-with-sagemaker-inference-components/)

**AWS Machine Learning Blog** · 2026-08-28

Salesforce used Amazon SageMaker's SchedulingConfig parameter in the CreateInferenceComponent API to achieve Multi-AZ high availability while preserving an 8x infrastructure cost reduction.

- Default SageMaker Inference Component (IC) placement optimizes operations independently, risking uneven model copy distribution across Availability Zones (AZs) and instances.
- The SchedulingConfig parameter introduces AvailabilityZoneBalance to control cross-AZ copy distribution via EnforcementMode and MaxImbalance parameters.
- PlacementStrategy offers SPREAD to distribute copies across maximum instances for fault isolation or BINPACK to maximize compute utilization efficiency within an AZ.
- Scaling operations (CopyCount adjustments) automatically preserve configured AZ balance by symmetrically adding or removing copies across zones.

**Why it matters:** It allows enterprise workloads to combine the cost savings of co-hosting multiple models on shared GPUs with strict Multi-AZ compliance and fault isolation requirements.

### [Introducing OpenAI models on Amazon Bedrock for in-country inferencing in India](https://aws.amazon.com/blogs/machine-learning/introducing-openai-models-on-amazon-bedrock-for-in-country-inferencing-in-india/)

**AWS Machine Learning Blog** · 2026-08-27

Amazon Bedrock now supports OpenAI GPT-5.6 Terra and Luna models in India via local geographic cross-Region inference between the Mumbai and Hyderabad AWS Regions.

- Supports OpenAI GPT-5.6 Terra (in.openai.gpt-5.6-terra) and Luna (in.openai.gpt-5.6-luna) models featuring a 1-million-token context window for text and image inputs.
- India geographic cross-Region inference strictly routes workloads between ap-south-1 (Mumbai) and ap-south-2 (Hyderabad) to meet local data residency requirements.
- Requests can be submitted using the OpenAI Responses API, OpenAI Chat Completions API, or the Amazon Bedrock Converse API via the bedrock-runtime endpoint.
- Uses a Zero Data Retention (ZDR) model by default, with encrypted transit between India Regions, though content flagged by automated abuse-detection classifiers is retained for offline review.
- Billing, CloudWatch monitoring, CloudTrail logs, and quotas are recorded exclusively within the source Region.

**Why it matters:** Organizations with strict Indian data sovereignty regulations in healthcare, finance, and the public sector can now scale deployment of OpenAI's GPT-5.6 models without data leaving the country.
