### [Encoder Disaggregation in vLLM: Scaling Multimodal Serving with EPD](https://vllm.ai/blog/2026-11-11-encoder-disaggregation-epd)

**vLLM Blog** · 2026-11-11

vLLM has expanded Encoder/Prefill/Decode (EPD) disaggregation, introducing metadata-only multimodal requests to eliminate duplicate media preprocessing downstream.

- EPD disaggregates multimodal serving into E+PD or E/P/D deployment patterns using EC connectors for embeddings and KV connectors for prefill-to-decode transfer.
- Metadata-only EPD forwards structural references (placeholder lengths, image grids, feature lengths) instead of raw media to prevent downstream instances from re-processing inputs.
- Core EPD capabilities were released in vLLM v0.32.0, with metadata-only support for DeepSeek V4.1 Flash added on main via PR #62802.

**Why it matters:** Operators can scale encoder, prefill, and decode compute resources independently to optimize heterogeneous multimodal workloads while avoiding redundant GPU media processing.

### [ExecuTorch WebGPU: PyTorch Models on the GPU, in the Browser](https://pytorch.org/blog/executorch-webgpu-pytorch-models-on-the-gpu-in-the-browser/)

**PyTorch Blog** · 2026-11-10

PyTorch's ExecuTorch framework now features a WebGPU backend, enabling models exported via torch.export to run directly in browsers on the GPU without format conversion.

- Models are exported once to a .pte file via torch.export() and WebGPUPartitioner, running through WGSL compute shaders.
- The C++ runtime compiles to WebAssembly via Emscripten and emdawnwebgpu, using allocate-at-max buffers to handle dynamic shapes.
- Benchmarks on Apple M1 Pro show WebGPU delivers 4–7× faster prefill and 2–10× faster decode speeds compared to ExecuTorch's XNNPACK Wasm CPU backend.
- Cross-platform support translates WGSL to Metal Shading Language, SPIR-V, or HLSL across macOS, Linux, Android, and Windows.
- Supports varied architectures out-of-the-box, including LLMs (Llama 3.2, Qwen3), vision-language (SmolVLM), segmentation, and speech-to-text (Whisper).

**Why it matters:** It eliminates the need to convert PyTorch models to third-party formats like ONNX, GGUF, or TFLite for browser-based, client-side GPU inference.

### [Optimizing Muse Spark Open on TPU v7 with SGLang-TorchTPU](https://pytorch.org/blog/optimizing-muse-spark-open-on-tpu-v7-with-sglang-torchtpu/)

**PyTorch Blog** · 2026-11-10

Meta's 816B-parameter Muse Spark Open model was optimized on a four-chip TPU v7 host using SGLang-TorchTPU and a 62-layer Pallas megakernel.

- Executes all 62 decode or verify layers in a single Pallas megakernel, pipelining weight loads, KV reads, and cross-device transfers behind compute.
- Serves an 816B parameter MoE architecture (42B active, FP8 compute with NVFP4 expert weights) across 8 tensor-parallel TPU v7 chiplets.
- Achieves verify speeds within 1.5–1.7× of pure HBM weight streaming limits and halves time-per-output-token at low concurrency.
- Achieves 433 to 95 output tokens/sec per request across a range of 6,101 to 25,906 tokens/sec per chip on the 1M-context AgentX benchmark.

**Why it matters:** It demonstrates that full-network Pallas megakernels and pipeline optimizations allow large MoE models with 1M-token contexts to run efficiently on small-scale TPU v7 hardware.

### [How We Built TLX: A Hardware-Native GPU Compiler for Production ML at Scale](https://engineering.fb.com/2026/11/10/open-source/tlx-a-hardware-native-gpu-compiler-for-production-ml/)

**Meta Engineering** · 2026-11-10

Meta introduced Triton Low-Level Extensions (TLX), an extension to Triton providing explicit warp-group and cluster-level GPU execution orchestration to optimize performance for RecSys and LLM production workloads.

- TLX adds explicit control over execution-oriented hardware features including warp specialization, asynchronous memory movement, tensor memory, and cluster-level execution.
- The extension addresses hardware capabilities introduced in NVIDIA Hopper (TMA, warp specialization) and Blackwell architectures (TMEM, cluster-level execution, paired-CTA execution).
- TLX aims to bridge the gap between low-level GPU control models and high-level productive programming models across NVIDIA and AMD GPUs.
- Over a 10-month period at Meta, production Triton kernel count grew approximately 3.8x compared to 2.0x for CUDA.

**Why it matters:** TLX allows machine learning engineers to harness advanced hardware-level GPU execution features directly in Triton without needing to write low-level CUDA code.
