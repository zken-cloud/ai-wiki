### [Improve TTFT for multi-turn agentic workloads with bi-directional KV transfer in vLLM](https://aws.amazon.com/blogs/machine-learning/improve-ttft-for-multi-turn-agentic-workloads-with-bi-directional-kv-transfer-in-vllm/)

**AWS Machine Learning Blog** · 2026-10-19

AWS contributed a bi-directional KV transfer mechanism to vLLM via an enhanced NIXL KV connector, allowing prefill nodes to retrieve decode node KV caches in multi-turn agentic workloads.

- Conventional prefill-decode disaggregation only transfers KV cache from prefill to decode nodes, forcing prefill nodes to recompute KV projections for previously generated model tokens and conversation history on subsequent turns.
- Bi-directional KV transfer enables decode nodes to pass stored KV blocks back to prefill nodes, avoiding redundant context recomputation.
- The implementation leverages NIXL KV connector enhancements and AWS Elastic Fabric Adapter (EFA) for direct remote memory access (GPUDirect RDMA / Neuron Direct RDMA) across nodes.
- Benchmarking on Amazon EC2 P5en instances (1P1D setup) demonstrated TTFT reductions of up to 1.6x for Qwen3-32B and up to 3.3x for zai-org/GLM-5-FP8.

**Why it matters:** It significantly reduces time to first token (TTFT) and prevents redundant accelerator computation as conversation histories expand in multi-turn LLM agent deployments.

`vllm` `kv-cache` `llm-inference` `aws` `rdma`
