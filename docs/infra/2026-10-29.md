### [PyTorch 2.15 Release Blog](https://pytorch.org/blog/pytorch-2-15-release-blog/)

**PyTorch Blog** · 2026-10-28

PyTorch 2.15 defaults to a rewritten NCCL backend with hang flight recording, adds NVFP4 support for NVIDIA Blackwell GPUs, and introduces FP8 and decode accelerations for Apple Silicon.

- Rewritten NCCL backend is now the default for distributed training, featuring eager communicator creation, shrink/grow fast-paths, and an automated flight-recorder that dumps state on collective hangs.
- Introduces one-sided transports using a NIXL backend with CUDA-graph-capturable transfers for torch.distributed.
- NVIDIA Blackwell GPUs gain faster 4-bit (NVFP4) LLM decoding via NVGEMM kernel launch optimizations.
- Apple Silicon receives FP8 support (float8_e4m3fn, _scaled_mm), public torch.mps.Stream APIs, and a new grouped_mm decode fast path yielding 1.32–1.34x tokens/sec on MoE decode.
- Expands platform support with ROCm 10.0 wheels, FlyDSL on AMD gfx950, Tensor Data Mover support for AMD gfx1250 (MI450), default CUDA 13.2 wheels, and torch.compile on Python 3.15.

**Why it matters:** PyTorch 2.15 delivers faster low-precision LLM inference across NVIDIA and Apple hardware while reducing large-cluster training downtime through automated distributed debugging and lower communication overhead.

### [Distributed training with Ray Train DLCs and EFA on EKS](https://aws.amazon.com/blogs/machine-learning/distributed-training-with-ray-train-dlcs-and-efa-on-eks/)

**AWS Machine Learning Blog** · 2026-10-28

AWS provides a pre-built Ray Train Deep Learning Container (DLC) that integrates PyTorch, Ray, CUDA, and the EFA networking stack to enable multi-node distributed GPU training on EKS without building custom container images.

- The Ray Train DLC (public.ecr.aws/deep-learning-containers/ray:train-ml-cuda-v1.1) pre-packages Ray 2.58.0, PyTorch 2.13.0, CUDA 13.0.2, NCCL 2.29.7, libfabric, and the AWS OFI NCCL plugin.
- KubeRay manages the cluster via a single RayCluster manifest on Amazon EKS, deploying both the Ray head and worker pods from the same tagged DLC image.
- Inter-node NCCL collective communications run over EFA across instances automatically when pods request EFA resources.
- The demonstration fine-tunes Qwen2.5-1.5B using PyTorch FSDP across eight NVIDIA L4 GPUs on two g6.12xlarge instances with zero custom image builds.

**Why it matters:** It eliminates the complex engineering overhead of manually building and maintaining aligned container stacks for PyTorch, Ray, NCCL, and EFA hardware acceleration on Kubernetes.

### [Building an Agentic AI Platform on Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/building-an-agentic-ai-platform-on-amazon-bedrock-agentcore/)

**AWS Machine Learning Blog** · 2026-10-28

AWS introduced an architecture and reference implementation for building an enterprise Agentic AI Platform using Amazon Bedrock and Amazon Bedrock AgentCore.

- Amazon Bedrock AgentCore provides modular runtime, gateway, identity, memory, policy, registry, and evaluation services.
- The platform separates operations using dedicated Model Context Protocol (MCP) gateways for tool access and inference gateways for model access.
- The design enforces workload identity, per-workstream token quotas, rate limits, Bedrock Guardrails, and least-privilege tool execution roles.
- Enterprise infrastructure-as-code blueprints automate independent workstream deployments, cost attribution via AWS Cost Explorer/CUR, and release evaluation gates.

**Why it matters:** Platform teams can standardize enterprise guardrails, access policies, and cost tracking across multiple workstreams without creating deployment bottlenecks.
