### [Adaptive Verification Without a Confidence Head](https://vllm.ai/blog/2026-10-14-adaptive-verification-online-estimator)

**vLLM Blog** · 2026-10-14

vLLM added an online-fitted acceptance estimator (PR #52228) that derives acceptance probabilities from draft model logits, enabling Adaptive Verification for draft models lacking a trained confidence head.

- Uses a lightweight logistic regression with K + 1 parameters (one shared slope and one intercept per draft position for a K-token drafter).
- Predicts target model acceptance using a scalar feature derived from the log-odds of the drafter's most likely token.
- Continuously fits estimator coefficients online using the target model's standard accept/reject verification outputs without requiring offline retraining.
- Enables Adaptive Verification optimizations for draft models like EAGLE, MTP, DFlash, and non-head DSpark checkpoints via the enable_adaptive_verification flag.

**Why it matters:** It allows existing, pre-trained draft model checkpoints to use Adaptive Verification speculative decoding, reducing GPU compute overhead during high-batch serving without requiring model retraining.

### [Push-Based KV Transfer to Improve TTFT and TPOT for Disaggregated Inference in vLLM](https://vllm.ai/blog/2026-10-14-nixl-push-connector)

**vLLM Blog** · 2026-10-14

vLLM added an accelerator-agnostic, push-based NIXL connector for prefill-decode disaggregation that writes KV cache directly to decode memory over RDMA.

- Replaces sequential pull-based NIXL READ operations with direct RDMA writes from prefill to decode instances, removing router relay overhead from the critical path.
- Decouples KV transfer setup by having the decode instance register target blocks upfront while the prefill instance matches and executes transfers.
- Demonstrates up to 3x TTFT improvement and up to 30% lower TPOT over pull mode in a 1P1D benchmark using Qwen3-32B on AWS EC2 P5en instances over EFA.
- Utilizes GPUDirect RDMA and Neuron Direct RDMA to bypass host memory staging across supported GPU and AWS Trainium instance types.

**Why it matters:** Push-based KV transfer reduces time-to-first-token and improves output token throughput for disaggregated LLM serving at high request rates.

### [Finish RL Training Faster: Bitwise-Consistent, High-Performance, Agent-Driven](https://vllm.ai/blog/2026-10-14-train-inference-consistency)

**vLLM Blog** · 2026-10-14

A new method achieves bitwise-identical training and inference logprobs (0 diff) by having training forwards directly call modified vLLM kernels, maintaining 91.3% rollout throughput while preventing RL instability.

- Eliminates train-inference numerical divergence by having the training forward call vLLM inference kernels modified to resist changes from batch composition, prefill/decode phases, or parallel layouts.
- Prevents training degradation observed in baselines where train-inference KL rose from 2e-3 to 29.9 and Nemotron-3.5 SWE-bench Pro scores fell to 0.23 (versus staying ~0.6 with consistent logprobs).
- Applies modifications to operators including dense GEMM (FP8), FP8 KV cache, sparse attention Top-K tie-breaking, expert GEMM layouts, and CUDA Graphs across DeepSeek-V4-Flash and Nemotron-3.5-Lightning-30B-A3B (NVFP4).
- Encapsulated the debug and numerical alignment procedure into an automated agent skill to streamline operator reduction, minimal repro generation, and regression testing on new architectures.

**Why it matters:** Ensuring true on-policy RL training via bitwise-consistent logprobs eliminates policy drift, reducing crashes and rollbacks without sacrificing high-performance low-precision optimizations.
