### [Efficient Decode Context Parallelism with vLLM for Long Context Workloads](https://vllm.ai/blog/2026-08-07-decode-context-parallelism)

**vLLM Blog** · 2026-08-07

vLLM provides enhanced Decode Context Parallelism (DCP) to shard KV caches across GPUs along the sequence dimension, addressing memory bottlenecks caused by small KV head counts in long-context, agentic AI workloads.

- Traditional Tensor Parallelism (TP) duplicates KV caches across GPUs once TP exceeds the KV head count in Grouped-Query Attention (GQA) or Multi-head Latent Attention (MLA) models, limiting memory and batch sizes.
- Decode Context Parallelism partitions the KV cache by sequence length rather than attention head, enabling GPUs to store only a fraction of the cache and freeing memory for larger concurrency.
- Benchmark testing uses a Mooncake trace format dataset reflecting realistic long-horizon agent behavior with a median input length of ~67k tokens (up to ~1M tokens) and short ~400-token outputs.

**Why it matters:** DCP eliminates redundant KV cache replication during long-context decoding, allowing higher batch sizes, better concurrency, and increased throughput for agentic LLM deployments.

### [vLLM Reaches 25K Total TPS/GPU on Qwen3.5](https://vllm.ai/blog/2026-08-06-qwen35-25k-tps)

**vLLM Blog** · 2026-08-06

vLLM achieved over 25K total tokens per second per GPU on Qwen3.5-397B-A17B-NVFP4 using NVIDIA GB200 NVL72 disaggregated serving, Blackwell GDN kernels, HMA cache transfers, and async scheduling.

- FlashInfer's Blackwell GDN prefill kernel improved performance by 1.02x to 5.78x across Qwen3.5 sizes compared to prior FLA/Triton implementations.
- HMA and NIXL connectors support hybrid SSM-FA disaggregation with dual descriptor views, mapping logical blocks to physical memory and reducing transferred descriptors from 4,284 to 1,650.
- Disaggregated serving transfers both full-attention KV cache and Mamba-style GDN/SSM state between prefill and decode workers over NIXL.

**Why it matters:** Optimized disaggregated serving and custom Blackwell kernels allow ultra-large hybrid SSM-attention models like Qwen3.5 to achieve significantly higher throughput on GB200 hardware.

### [How we built an MCP bridge to give our AgentCore-hosted AI agent access to local MCP tools](https://aws.amazon.com/blogs/machine-learning/how-we-built-an-mcp-bridge-to-give-our-agentcore-hosted-ai-agent-access-to-local-mcp-tools/)

**AWS Machine Learning Blog** · 2026-08-05

AWS introduced a mechanism to connect cloud-hosted AI agents on Amazon Bedrock AgentCore to local, client-side MCP servers via WebSockets and native messaging.

- Connects cloud-based Strands agents acting as MCP clients to local MCP servers running over stdio.
- Uses a browser extension as a bidirectional relay between the AgentCore runtime over presigned WebSockets and a local proxy over native messaging.
- Employs a local FastMCP proxy (MCP Bridge) to unwrap JSON-RPC requests from the native messaging envelope and send them to local tool servers.
- Enables centrally deployed cloud models to access local files like Excel workbooks without transferring data through remote server endpoints.

**Why it matters:** It allows enterprise cloud AI agents to securely execute tools and access sensitive files on a user's local machine without exposing local MCP servers to the public internet.
