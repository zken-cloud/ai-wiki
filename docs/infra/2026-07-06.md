### [Bringing PyTorch Monarch to AMD GPUs: Single-Controller Distributed Training on ROCm](https://pytorch.org/blog/bringing-pytorch-monarch-to-amd-gpus-single-controller-distributed-training-on-rocm/)

**PyTorch Blog** · 2026-07-06

PyTorch Monarch, a single-controller distributed training framework, has been ported to AMD Instinct GPUs with ROCm, enabling elastic, fault-tolerant large language model training beyond CUDA environments.

- Monarch's architecture decouples the Python API from a Rust runtime (Tokio) and infrastructure, managing actors, meshes, supervision trees, and tensor sharding.
- The system dynamically recovers from node failures, allowing healthy nodes to continue training while failed nodes recover, minimizing wasted computation.
- Traditional checkpointing, which causes wasted computation and cluster idle time, is replaced by Monarch's dynamic fault-tolerance model.
- Porting Monarch to ROCm required significant engineering effort to adapt its GPU runtime and distributed communication stack.

**Why it matters:** This enables more reliable and efficient large-scale AI infrastructure by addressing hardware failures in distributed training environments.
