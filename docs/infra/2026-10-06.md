### [Evolution of the PyTorch Media Processing Landscape](https://pytorch.org/blog/evolution-of-the-pytorch-media-processing-landscape/)

**PyTorch Blog** · 2026-10-05

PyTorch has consolidated media processing by moving all image, video, and audio encoding/decoding into TorchCodec while refocusing TorchVision and TorchAudio strictly on media transforms.

- TorchCodec is now the single library for CPU and CUDA media decoding and encoding, replacing scattered APIs in TorchVision (io.read_video, io.VideoReader) and TorchAudio (StreamReader, StreamWriter).
- TorchCodec centralizes C/C++ backend dependencies, including FFmpeg versions 4 through 9, NVIDIA's codec SDK, and image libraries like libjpeg and libpng.
- TorchVision and TorchAudio have deprecated or removed their I/O utilities, models, datasets, and pipelines to focus exclusively on image, video, and audio transforms.
- Centralizing media I/O in TorchCodec improves performance, specifically for CUDA video decoding, and reduces build and maintenance complexity across the PyTorch ecosystem.

**Why it matters:** Developers can streamline their data pipelines by using TorchCodec for high-performance media I/O and relying on TorchVision or TorchAudio solely for tensor transformations.

**AWS Machine Learning Blog** · 2026-10-05

Z.ai's GLM 5.3, a 753B-parameter open-weight mixture-of-experts model optimized for coding and agentic tasks, is now available as a fully managed API on Amazon Bedrock.

- Includes cost and latency optimizations such as implicit and explicit prompt caching alongside Flex, Standard, and Priority service tiers.
