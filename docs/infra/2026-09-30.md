### [Taking vLLM Apart: A Practical Guide to Disaggregated Serving](https://vllm.ai/blog/2026-09-29-disaggregated-serving-guide)

**vLLM Blog** · 2026-09-29

vLLM v0.30.0+ supports disaggregated serving by splitting compute-bound prefill from memory-bound decode via KV cache transfers, and offloading tokenization and parsing to CPU-only render frontends.

- Prefill (compute-bound, TTFT) and decode (memory-bound, ITL) are split into separate instances using KV cache connectors like NIXL, LMCache, Mooncake, FlexKV, and MoRI-IO over RDMA.
- KV cache transfers require high bandwidth; a 10k-token prompt for Llama-3.1-70B in BF16 generates ~3 GB of KV data (~320 KiB/token), taking ~65 ms over a 400 Gb/s link.
- A GPU-less frontend decouples CPU-heavy operations from accelerator nodes using /render to map OpenAI requests into token IDs and /derender to parse outputs into content, reasoning, and tool calls.
- Disaggregation extends beyond P/D to include Mamba state transfers for hybrid SSMs, encoder disaggregation for multimodal models, and the AFD plugin for splitting attention from FFN in MoE architectures.

**Why it matters:** Disaggregating vLLM workloads prevents long prompt prefills and CPU preprocessing tasks from causing latency spikes and stalling inter-token generation across concurrent decode streams.

### [Amazon Bedrock expands Claude model availability to in-country inferencing in India](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-expands-claude-model-availability-to-india-cross-region-inference/)

**AWS Machine Learning Blog** · 2026-09-30

Amazon Bedrock now provides in-country geographic cross-Region inference in India for Anthropic's Claude Opus 5, Claude Sonnet 5, and Claude Haiku 4.5 models.

- Geographic cross-Region inference routes requests exclusively between the ap-south-1 (Mumbai) and ap-south-2 (Hyderabad) AWS Regions.
- Customer data is not stored in destination Regions, while Amazon CloudWatch logging, AWS CloudTrail logging, quota consumption, and billing remain tracked strictly within the source Region.
- The bedrock-runtime endpoint supports the India geographic inference profile via the Anthropic Messages API, Amazon Bedrock InvokeModel API, and Converse API.
- The architecture operates under a zero data retention (ZDR) model by default with end-to-end encryption for data in transit across the secure AWS network.

**Why it matters:** Organizations operating in India can run high-throughput Claude workloads with cross-region capacity routing while complying with local in-country data processing requirements.

### [Introducing Anthropic models on Amazon Bedrock for in-region inference in Seoul and Singapore](https://aws.amazon.com/blogs/machine-learning/introducing-anthropic-models-on-amazon-bedrock-for-in-region-inference-in-seoul-and-singapore/)

**AWS Machine Learning Blog** · 2026-09-30

Amazon Bedrock now supports in-region inference for Anthropic Claude Opus 5 and Claude Sonnet 5 in Seoul, and Claude Sonnet 5 in Singapore.

- In-region inference processes prompts and outputs entirely within ap-northeast-2 (Seoul) or ap-southeast-1 (Singapore) without a cross-region routing layer.
- Supported APIs on the bedrock-runtime endpoint include the Anthropic Messages API, Amazon Bedrock InvokeModel API, and Converse API.
- Throughput, service quotas, CloudWatch metrics, and CloudTrail logs are strictly scoped to the single called AWS Region.
- Models are invoked using direct model IDs such as anthropic.claude-opus-5 and anthropic.claude-sonnet-5.

**Why it matters:** This allows organizations in regulated industries like healthcare and finance to scale Claude models while strictly adhering to local data residency requirements.
