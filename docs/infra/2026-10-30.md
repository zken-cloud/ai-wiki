### [Lend and borrow resources across teams with AWS Batch’s quota management for SageMaker Training jobs](https://aws.amazon.com/blogs/machine-learning/lend-and-borrow-resources-across-teams-with-aws-batchs-quota-management-for-sagemaker-training-jobs/)

**AWS Machine Learning Blog** · 2026-10-29

AWS Batch introduces quota management for Amazon SageMaker Training jobs, enabling multi-team resource allocation, automated lending and borrowing of idle GPU capacity, and job preemption.

- Quota shares act as virtual queues nested within job queues, allowing administrators to set compute limits and define sharing strategies: RESERVE, LEND, or LEND_AND_BORROW.
- Cross-share preemption automatically reclaims lent capacity when new workloads arrive in the original lending quota share.
- Priority-based in-share preemption preempts lower-priority jobs in SCHEDULED, STARTING, or RUNNING states to allow higher-priority jobs to execute immediately.
- Configuration requires a Scheduling Policy containing a quotaSharePolicy and a Service Environment, supported via the SageMaker Python SDK v3.

**Why it matters:** It eliminates manual coordination and custom queuing overhead by automatically maximizing shared GPU cluster utilization while guaranteeing capacity for prioritized workloads across teams.

### [Accelerate agentic AI with NVIDIA Nemotron models on Amazon EKS and SageMaker HyperPod EKS](https://aws.amazon.com/blogs/machine-learning/accelerate-agentic-ai-with-nvidia-nemotron-models-on-amazon-eks-and-sagemaker-hyperpod-eks/)

**AWS Machine Learning Blog** · 2026-10-29

AWS announced deployment patterns for NVIDIA Nemotron 3.5 Super VL, a 120B-parameter hybrid Mamba-Transformer MoE multimodal model, on Amazon EKS, EKS Auto Mode, and SageMaker HyperPod EKS.

- Nemotron 3.5 Super VL uses a hybrid Mamba-2, MoE, and attention architecture with a RADIO vision encoder, activating 12B of its 120B total parameters per token up to a 1M token context.
- The model includes a recursively shared Multi-Token Prediction (MTP) head to support native speculative decoding.
- Minimum vLLM hardware requirements range from 1 NVIDIA B300/GB300 GPU (for NVFP4) up to 16 H100 GPUs (for BF16).
- Reference deployment infrastructure uses Amazon ECR for container images, Amazon FSx for Lustre for shared model weights, and EFA networking across GPU nodes.

**Why it matters:** It enables developers to deploy a high-context, open-weights multimodal model optimized for low-memory long-sequence inference on AWS-managed Kubernetes infrastructure.

### [Day 0 support for Mistral Large 4 on vLLM](https://vllm.ai/blog/2026-10-29-mistral-large-4)

**vLLM Blog** · 2026-10-29

vLLM announced day-0 support for Mistral Large 4, introducing optimizations for its native MoE multimodal architecture across NVIDIA Blackwell, AMD ROCm, and TPU hardware using Model Runner V2.

- Mistral Large 4 integrates sparse MLA, a DSA top-k indexer, cross-layer KV sharing (nine NoPE layers reuse layer 35's KV cache), and a built-in DSpark speculative decoding drafter.
- Per token KV cache footprint is 47,136 bytes (41,328 for MLA latent and 5,808 for the indexer), requiring 8 ranks via Decode Context Parallelism (DCP) for long contexts.
- The model is deployed via Model Runner V2 (MRV2) with breakable CUDA graphs, supporting NVFP4 and FP8 quantizations.
- NVFP4 decoding on Blackwell provides 1.08–1.19x faster decoding per token compared to FP8 without speculative decoding (1.18–1.22x with DSpark) while retaining performance within a -0.3 mean point margin.

**Why it matters:** It enables immediate, highly optimized production serving and speculative decoding for Mistral's latest 1T-class native multimodal model with minimal quality degradation and lower memory usage.
