### [ZGateway: Learnings from Putting a Proxy in Front of ZippyDB](https://engineering.fb.com/2026/09/03/core-infra/zgateway-proxy-zippydb-meta/)

**Meta Engineering** · 2026-09-03

Meta introduced ZGateway, a proxy layer that unifies client traffic to ZippyDB to resolve many-to-many connection explosion, enable admission control, and improve fleet resilience.

- Direct client access created an unbounded many-to-many TLS mesh where single clients held tens of thousands of outbound connections and database hosts accepted tens of thousands of inbound connections.
- ZGateway decouples clients from the database hosts by collapsing the connection mesh into two bounded hops, preventing file-descriptor exhaustion and OOM crashes from connection storms.
- The proxy tier acts as a centralized control point for shared operational logic including connection pooling, request batching, load balancing, cross-region routing, and admission control.
- Centralizing control allows Meta infrastructure engineers to deploy fleet-wide operational changes in minutes rather than waiting for client binary rollouts across over a million host machines.

**Why it matters:** Interposing a managed proxy tier between massive client fleets and backend key-value stores prevents cascading infrastructure outages caused by connection fan-out and reconnection storms.
