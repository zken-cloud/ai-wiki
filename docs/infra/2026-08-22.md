### [IsoExec: Unified Execution to Eliminate Trainer-Inference Mismatch in SkyRL](https://vllm.ai/blog/2026-08-21-isoexec)

**vLLM Blog** · 2026-08-21

SkyRL introduced IsoExec, a unified execution abstraction combining an execution contract and unified model with batch-invariant kernels to eliminate floating-point rollout-versus-training mismatch across vLLM and Megatron engines.

- IsoExec addresses numerical train-inference mismatch caused by floating-point non-associativity across different kernels, batch shapes, and distributed layouts in vLLM and Megatron.
- The abstraction uses an execution contract to enforce execution details affecting rounding, alongside a unified model with batch-invariant kernels that maintain bitwise consistency across engines.
- In a single-node 8xH100 test with synchronous Qwen3.5-35B-A3B DAPO training over 50 steps, IsoExec reduced the average rollout-versus-training logprob difference below 1e-6 with a 25% overhead compared to the SkyRL baseline.
- Eliminating execution mismatch prevents policy instability, distorted advantage-weighted loss contributions, and high token-clipping rates seen in systems with train-inference divergence.

**Why it matters:** Eliminating train-inference numerical mismatch ensures true on-policy execution in RL training systems, preventing reward collapse and training instability caused by floating-point rounding discrepancies.

**AWS Machine Learning Blog** · 2026-08-21

A custom post-retrieval pattern on Amazon Bedrock uses a small model like Claude Haiku to extract relevant context before passing it to a primary model like Claude Sonnet.

- Uses a two-model cascade inside an AWS Lambda function: a low-cost compression model (e.g., Anthropic Claude Haiku) filters retrieved chunks, and a primary model (e.g., Anthropic Claude Sonnet) generates the answer.
- The compression step runs after initial chunk retrieval (such as from Amazon Bedrock Knowledge Bases or OpenSearch Serverless) but before the final generation call.
- The smaller model reads the top-k retrieved chunks alongside the user query and outputs only the verbatim relevant spans.
- Can be layered on top of Amazon Bedrock features like prompt caching, Intelligent Prompt Routing, and the Rerank API.

**Why it matters:** Filtering out irrelevant context before invoking the primary LLM reduces per-query input token counts, lowering overall operational costs for high-volume RAG workloads and reducing model hallucination risk.
