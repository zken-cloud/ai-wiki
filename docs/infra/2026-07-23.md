### [Helion on TPU: Towards Hardware Heterogeneous Kernel Authoring](https://pytorch.org/blog/helion-on-tpu-towards-hardware-heterogeneous-kernel-authoring/)

**PyTorch Blog** · 2026-07-23

Helion, PyTorch's high-level DSL, now supports a TPU backend that compiles kernels to Pallas, enabling PyTorch-friendly authoring of performant TPU kernels.

- Helion-generated kernels achieved 838 TFLOPs (~79% MFU of one tensor core) on a flash attention workload on TPU v7.
- Helion autotunes code-generation strategies for different input shapes to optimize pipelining and VMEM/compute utilization.
- Helion targets performance-critical use cases requiring autotuning, non-Pallas experts, and cross-hardware users maintaining kernels across TPU and GPU.
- Helion's Pallas codegen maximizes software pipelining by overlapping memory transfers and computation, using pallas_call/emit_pipeline for outer loops and autotuning inner loops between emit_pipeline and pre-fetching (unroll).

**Why it matters:** Helion simplifies authoring high-performance ML kernels for TPUs, making the platform more accessible to a wider range of developers without requiring deep Pallas expertise.

### [From Day 0 to Production SLAs: Serving GLM-5.2 on 24 NVIDIA B300 GPUs with vLLM](https://vllm.ai/blog/2026-07-23-glm-5.2-nvfp4-b300-pd)

**vLLM Blog** · 2026-07-23

vLLM optimized GLM-5.2-NVFP4 serving on 24 NVIDIA B300 GPUs, reducing mean TPOT from 40 ms to 17 ms by implementing P/D disaggregation, MTP speculative decoding, and Model Runner V2.

- Achieved a mean TPOT of 17 ms and mean TTFT of ≤ 2.5 s for GLM-5.2-NVFP4 on 24 B300 GPUs, down from an initial 40 ms mean TPOT.
- Utilized a disaggregated 4-Prefill + 1-Decode topology across three 8-GPU B300 servers to isolate prefill work from the decode critical path.
- Implemented Model Runner V2, All-to-All Backend, CUDA Graph Mode, and MTP speculative decoding, with Model Runner V2 contributing an 11% TPOT reduction.
- Optimized for SLA compliance (mean TTFT ≤ 2.5 s, mean TPOT ≤ 20 ms) rather than peak throughput, allowing dynamic concurrency based on input length (e.g., 700 concurrent requests at 8K tokens).
- Integrated IndexerCache with MTP speculative decoding and DSA sparse attention to improve acceptance rates and cost-effectiveness for the 744B-parameter MoE model.

**Why it matters:** This optimization demonstrates how to achieve strict production latency SLAs for large language models on substantial GPU clusters by focusing on disaggregation and specific decode-side improvements.

### [Announcing vLLM AFD Plugin: Disaggregating Attention and FFN for Flexible MoE Serving](https://vllm.ai/blog/2026-07-23-vllm-afd-plugin)

**vLLM Blog** · 2026-07-23

The vLLM AFD Plugin introduces Attention-FFN Disaggregation (AFD) for Mixture-of-Experts (MoE) models, allowing independent scaling of Attention and FFN services on NVIDIA GPUs and Ascend NPUs.

- vLLM AFD Plugin disaggregates Attention and FFN into independently deployed services for MoE models, preserving vLLM's request lifecycle and OpenAI-compatible serving interface.
- The plugin supports NVIDIA GPUs and Ascend NPUs, offering synchronous and asynchronous connectors, DeepSeek V2/V3-family model wrappers, and eager, graph, and dual-batch execution paths.
- Integration occurs via vLLM's vllm.general_plugins entry point and --additional-config channel, without requiring vLLM source tree modifications.
- The runtime comprises AFD workers, model runners, connectors, metadata, model split points, and version-scoped compatibility patches, with backend packages remaining separate to avoid leakage of hardware-specific behaviors.

**Why it matters:** This disaggregation enables independent scaling and optimization of Attention and FFN paths, addressing the distinct computational requirements of each for more efficient MoE model serving.
