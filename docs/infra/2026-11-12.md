**PyTorch Blog** · 2026-11-12

### [Training a 1T-Parameter MoE on EU public infrastructure with PyTorch and TorchTitan](https://pytorch.org/blog/training-a-1t-parameter-moe-on-eu-public-infrastructure-with-pytorch-and-torchtitan/)

**PyTorch Blog** · 2026-11-12

The EUROPA consortium successfully scaled pretraining of a 951.9B parameter MoE model on public JUPITER supercomputer infrastructure using PyTorch and TorchTitan, boosting throughput from 90 to ~1,300 tokens/sec per GPU.

- Trained a 951.9B total / 32.8B active parameter MoE model with 74 layers, 384 routed experts (top-8), and a 65,536 sequence length using Muon and AdamW optimizers.
- Achieved scaling across 384 NVIDIA GH200 GPUs (96 nodes) despite JUPITER's node limits of 96 GB HBM3 per GPU, 120 GB host CPU memory, and low inter-node InfiniBand bandwidth.
- Applied FlexShard placement for the Muon optimizer to reduce communication, offloaded activation checkpoints to the Grace CPU over NVLink-C2C, and ran FSDP all-gather setup on the compute stream to free ~14 GiB HBM per GPU.

**Why it matters:** It demonstrates that trillion-parameter MoE models can be efficiently trained on shared public exascale infrastructure using open-source PyTorch tools rather than requiring dedicated private clusters.

### [Detecting and recovering from silent data corruption on Amazon SageMaker HyperPod](https://aws.amazon.com/blogs/machine-learning/detecting-and-recovering-from-silent-data-corruption-on-amazon-sagemaker-hyperpod/)

**AWS Machine Learning Blog** · 2026-11-11

SageMaker HyperPod users can detect and isolate Silent Data Corruption by adding non-finite gradient checks, ring replay audits, and weight fingerprint comparisons directly into their PyTorch DistributedDataParallel training loops.

- Silent Data Corruption (SDC) bypasses standard ECC, Xid, DCGM, and network checksums because arithmetic logic paths in tensor cores lack ECC and do not report hardware faults.
- Non-finite gradient checks detect NaN, Inf, and overflow during forward/backward passes and all-reduce operations on the exact step they occur.
- Ring replay audits detect finite wrong values by having GPUs recompute another node's micro-batch to compare losses bit-for-bit and gradients via fingerprints.
- Weight fingerprint comparisons evaluate every replica's weights after the optimizer step to catch corruptions in weight updates and stored state.
- The three-check detection mechanism was validated using software-injected faults on a SageMaker HyperPod cluster with 32 NVIDIA H100 GPUs across four ml.p5.48xlarge instances.

**Why it matters:** Detecting SDC directly within training loops prevents corrupted gradients and weights from silently propagating across distributed nodes, saving significant compute costs and training time.

### [Introducing usage-based pricing for Amazon SageMaker AI bidirectional streaming](https://aws.amazon.com/blogs/machine-learning/introducing-usage-based-pricing-for-amazon-sagemaker-ai-bidirectional-streaming/)

**AWS Machine Learning Blog** · 2026-11-11

AWS has introduced usage-based software metering for Amazon SageMaker AI bidirectional streaming inference, allowing model providers to charge based on actual consumption during live sessions via AWS Marketplace.

- Introduces a companion WebSocket connection (/invocations-bidirectional-stream-metadata) dedicated to streaming metering data alongside the primary inference connection.
- Model servers opt in by returning the 'X-Amzn-SageMaker-Metadata-Stream-Supported: true' header during the WebSocket upgrade response.
- Correlates metering records with active inference sessions using matching 'X-Amzn-SageMaker-Request-Id' headers across both connections.
- Enforces a metadata stream rate quota of one message per second per connection, with a maximum message size limit of 512 bytes.
- Deepgram is the launch partner, utilizing the feature for Speech-to-Text and Text-to-Speech usage-based software billing.

**Why it matters:** It enables software providers to charge based on actual streaming consumption rather than fixed hourly rates, without altering existing SageMaker endpoint infrastructure costs.
