### [Low Precision Flash Attention 4: End-to-End Block-Scaled Attention for Blackwell](https://pytorch.org/blog/low-precision-flash-attention-4-end-to-end-block-scaled-attention-for-blackwell/)

**PyTorch Blog** · 2026-09-16

Meta has open-sourced Low Precision FlashAttention-4, adding MXFP8 forward and backward support on Nvidia Blackwell architecture to achieve up to 2.85 PF/s forward and 2 PF/s backward performance.

- Utilizes Blackwell block-scaled MMA instructions (tcgen05.mma.block_scale) with TMEM allocation strategies designed to fit scale factors within a fully-utilized 512-column TMEM.
- Implements online transpose-invariant square block scale quantization of dS using the warp-wide reduction PTX instruction redux.sync.max.abs.f32.
- Features fused RMSNorm+Quantize and GEMM+Quantize kernels that directly generate FP8 outputs alongside dual scale factor layouts in a single pass.
- Introduces a zero-gather jagged module that maintains unpadded FP8 data and scatters only smaller scale factors to 128-aligned addresses for TMA.
- Delivers speedups up to 1.6x in forward and 1.52x in backward passes over BF16 on internal shapes, enabling state-of-the-art MXFP8 training.

**Why it matters:** It demonstrates a practical, end-to-end MXFP8 training implementation that unlocks Blackwell's native block-scaled hardware acceleration, dramatically reducing precision conversion overhead and memory bandwidth constraints in production LLM workloads.

### [Fault tolerant distributed training on Amazon EKS using NVRx](https://aws.amazon.com/blogs/machine-learning/fault-tolerant-distributed-training-on-amazon-eks-using-nvrx/)

**AWS Machine Learning Blog** · 2026-09-16

Integration of the NVIDIA Resiliency Extension (NVRx) with PyTorch FSDP on Amazon EKS enables fault-tolerant distributed training through async checkpointing, in-process restart, and in-job restart.

- Async checkpointing via TorchAsyncCheckpoint hands off FSDP LOCAL_STATE_DICT writes to a background process, avoiding rank-0 bottlenecks and reducing I/O idle time.
- In-process restart wraps training loops to recover soft faults and NCCL hangs in seconds by re-rendezvousing surviving ranks without restarting the Python interpreter or container.
- The ft_launcher binary manages hard failures (SIGKILL, OOM, OS hangs) by monitoring rank heartbeats, terminating survivors, clearing GPU memory, and respawning workers in the same job.
- Target environment uses Amazon EKS self-managed p5.48xlarge node groups, featuring 8 NVIDIA H100 80 GB GPUs and 32 EFA network interfaces per instance.

**Why it matters:** It eliminates single-point-of-failure cascades and reduces GPU idle time on large-scale distributed training clusters without requiring custom kernels or PyTorch forks.
