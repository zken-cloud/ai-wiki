### [Stop guessing auto scaling targets for TTS on Amazon SageMaker AI](https://aws.amazon.com/blogs/machine-learning/stop-guessing-auto-scaling-targets-for-tts-on-amazon-sagemaker-ai/)

**AWS Machine Learning Blog** · 2026-10-22

A systematic method for Amazon SageMaker AI replaces auto scaling guesswork for text-to-speech models by deriving exact scaling thresholds from two measured endpoint metrics: concurrency ceiling (Q_max) and scale-out duration (T_total).

- Uses Kokoro-82M (an 82-million-parameter non-autoregressive StyleTTS2 derivative with an ISTFTNet decoder) deployed on a custom container via AWS CDK.
- Scales on the native CloudWatch metric ConcurrentRequestsPerModel (Maximum over a 10-second window) instead of custom container metrics or token-generation metrics.
- Derives scale-out thresholds, scale-in thresholds, and cooldown durations via arithmetic from the maximum SLO-compliant concurrency per instance (Q_max) and end-to-end scale-out time (T_total).
- Accounts for client-side versus CloudWatch metric differences by measuring the ratio between client-side in-flight counts and CloudWatch Maximum values across concurrency load rungs.

**Why it matters:** It eliminates SLO latency breaches and idle GPU over-provisioning caused by misconfigured auto scaling targets on non-autoregressive real-time TTS endpoints.
