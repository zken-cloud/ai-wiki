### [Adaptive Verification in vLLM: DSpark confidence-scheduled verification](https://vllm.ai/blog/2026-08-14-dspark-adaptive-verification)

**vLLM Blog** · 2026-08-14

vLLM introduced DSpark adaptive verification, which dynamically allocates draft token verification budgets per step using per-request confidence scores to maintain speculative decoding throughput gains up to batch size 256.

- Uses a learned DSpark confidence head to estimate position-wise survival probabilities across drafted tokens, selecting a global top-B contiguous prefix across requests.
- Calculates the optimal draft token budget (B) by maximizing expected tokens per unit step time using profiled cost tables evaluated via an np.argmax operation on the CPU.
- Addresses severe acceptance decay (e.g., DeepSeek-V4-Pro-0813 acceptance dropping from >70% for token 1 to <10% for token 7) to prevent rejected draft tokens from consuming compute at high concurrencies.
- Implemented in vLLM PR #47808 under the parameter enable_adaptive_verification.

**Why it matters:** It eliminates the need to manually tune num_speculative_tokens per workload while preventing speculative decoding throughput degradation at high batch sizes.

### [Custom reward functions for multi-turn reinforcement learning with Amazon Nova Forge](https://aws.amazon.com/blogs/machine-learning/custom-reward-functions-for-multi-turn-reinforcement-learning-with-amazon-nova-forge/)

**AWS Machine Learning Blog** · 2026-08-14

Amazon Nova Forge provides a Bring Your Own Orchestration (BYOO) environment using Group Relative Policy Optimization (GRPO) to train LLM agents via composite, multi-turn custom reward functions.

- Nova Forge supports multi-turn Reinforcement Fine-Tuning (RFT) using GRPO with either rule-based verifiable rewards or LLM-as-a-Judge grading.
- BYOO allows custom reward logic to run in user-managed environments on Amazon ECS alongside serverless multi-turn RL options.
- Custom reward functions optimize cumulative reward trajectories over multiple agent steps, including tool calling, code execution, and error recovery.
- The customer-managed environment requires setting specific CDK configuration options (`use_custom_env` and `custom_env_id`) on SageMaker HyperPod and Amazon ECS.

**Why it matters:** It enables developers to optimize complex multi-turn agent behaviors and out-of-distribution generalization without relying solely on supervised fine-tuning data.

### [Part 2: Amazon Bedrock cost attribution with Amazon Athena and CUDOS](https://aws.amazon.com/blogs/machine-learning/part-2-amazon-bedrock-cost-attribution-with-amazon-athena-and-cudos/)

**AWS Machine Learning Blog** · 2026-08-12

AWS details how to analyze Amazon Bedrock granular cost attribution by connecting CUR 2.0 IAM principal data to Amazon Athena and CUDOS dashboards.

- Requires enabling 'caller identity (IAM principal) allocation data' in CUR 2.0 to populate the line_item_iam_principal column and iamPrincipal/ tags.
- Enabling IAM principal data expands single CUR rows into multiple rows per principal, increasing S3 storage requirements for high-volume workloads.
- CUR 2.0 exports should be configured with hourly time granularity and overwrite delivery options to maintain maximum detail without duplicating files.
- An open-source repo (sample-cur-iam-principal-bedrock-tracking) provides an agent.md workflow to automate Athena setup using tools like Claude Code or Kiro-CLI.

**Why it matters:** Organizations can now perform SQL queries and view pre-built dashboards to attribute Amazon Bedrock usage and costs directly to specific IAM principals, applications, or teams.
