### [Optimizing Jagged Flash Attention with TLX: The Road Toward SOTA FA4 on Blackwell](https://pytorch.org/blog/optimizing-jagged-flash-attention-with-tlx-the-road-toward-sota-fa4-on-blackwell/)

**PyTorch Blog** · 2026-10-01

Meta implemented Jagged Flash Attention using Triton Low-level Extensions (TLX) on NVIDIA Blackwell B200 GPUs, achieving higher performance than FlashAttention-4 while using approximately 3x fewer lines of code.

- TLX provides explicit hardware control over Blackwell capabilities, including SMEM/TMEM allocation, async_task warp specialization, TMA, MMA, and barriers within Triton.
- The TLX kernel requires ~3.2K lines of code compared to ~10K lines in CuteDSL-based FlashAttention-4 (FA4).
- In bfloat16 benchmarks on B200, the TLX implementation outperforms FA4 on jagged shapes by ~13% on the forward pass and ~50% on the backward pass.
- Jagged Flash Attention processes packed, variable-length Q/K/V tensors via offset tensors, eliminating up to 50% compute waste caused by padding.

**Why it matters:** It demonstrates that low-level hardware optimizations on NVIDIA Blackwell GPUs can be achieved with higher performance and significantly lower code complexity using TLX instead of hand-written CUDA or CuteDSL.

### [Build agent memory with NVIDIA NeMo Agent Toolkit and Amazon S3 Vectors](https://aws.amazon.com/blogs/machine-learning/build-agent-memory-with-nvidia-nemo-agent-toolkit-and-amazon-s3-vectors/)

**AWS Machine Learning Blog** · 2026-10-01

AWS and NVIDIA detailed an implementation using Amazon S3 Vectors as a custom, scalable persistent memory provider for the NVIDIA NeMo Agent Toolkit deployed on Amazon EKS.

- NVIDIA NeMo Agent Toolkit (NAT) memory module uses the MemoryEditor abstract interface requiring three core methods: add_items(), search(), and remove_items().
- NAT uses the auto_memory_agent workflow to automatically capture and retrieve memory items (containing conversation history, tags, and metadata) without explicit LLM tool calls.
- Amazon S3 Vectors provides a cost-efficient backend supporting up to 2 billion vectors per index, cosine and euclidean distance metrics, metadata filtering, and immediate strong write consistency.
- Custom NAT memory providers extend the MemoryBaseConfig Pydantic class and are discovered dynamically via the _type field in YAML configurations.

**Why it matters:** Integrating Amazon S3 Vectors into NAT enables multi-agent systems to maintain strongly consistent, serverless persistent memory at a scale of billions of vectors without managing idle cluster infrastructure.

### [Implementing Multi-Environment Access for Claude Platform on AWS](https://aws.amazon.com/blogs/machine-learning/implementing-multi-environment-access-for-claude-platform-on-aws/)

**AWS Machine Learning Blog** · 2026-10-01

AWS published an implementation guide for securing multi-environment Claude Platform on AWS access across internal accounts, developer laptops, and external workloads using a dedicated AI Services account topology.

- Uses a three-account architecture: a management account, a dedicated AI Services account hosting the subscription/workspaces, and consuming workload accounts.
- AWS workloads access inference via cross-account IAM roles and SigV4 signing without storing API keys.
- External environments and CI/CD pipelines authenticate using OIDC federation to obtain short-term credentials and tokens without persistent secrets.
- Developer iteration is facilitated through long-lived API keys locked strictly to specific development workspaces.

**Why it matters:** It provides a blueprint to centralize enterprise LLM subscription billing and governance while isolating production, development, and external traffic across diverse infrastructure.
