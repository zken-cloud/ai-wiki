### [Reduce inference cold starts on Amazon SageMaker HyperPod with model caching](https://aws.amazon.com/blogs/machine-learning/reduce-inference-cold-starts-on-amazon-sagemaker-hyperpod-with-model-caching/)

**AWS Machine Learning Blog** · 2026-09-10

AWS has launched model caching for Amazon SageMaker Inference on HyperPod to pre-load container images and model weights onto local NVMe storage before pods are scheduled.

- Uncached cold starts take 25 to 30+ minutes due to downloading multi-gigabyte container images (5–7 minutes) and heavy model weights like the 600+ GB DeepSeek-R1 (30+ minutes) over the network.
- Model caching uses local NVMe storage to read model data at approximately 7 GB/s, allowing pods to start serving traffic in seconds.
- The weights cache capability introduces a modelCacheConfig setting that triggers the HyperPod Inference Operator to download weights to local NVMe and label target nodes as cache-ready before creating deployments.
- The feature includes two independent, mixable capabilities: a weights cache (supporting Amazon S3, Amazon FSx for Lustre, HuggingFace Hub, and JumpStart) and an image cache for pre-pulling container images.

**Why it matters:** It dramatically reduces autoscaling response times from tens of minutes to seconds by replacing slow network downloads with fast local NVMe reads during scale-out events.

### [Tiered KV Cache Offloading in vLLM](https://vllm.ai/blog/2026-09-10-tiered-kv-offloading)

**vLLM Blog** · 2026-09-10

vLLM introduced a host-centric tiered KV cache offloading framework that routes accelerator KV data through host memory to secondary tiers like filesystems, object storage, and peers.

- Uses a host-centric design where KV data moves between accelerator HBM and host CPU DRAM via local PCIe before propagating to secondary tiers.
- Consolidates multi-accelerator shards (e.g., tensor parallelism) into a canonical host memory layout where each page holds one block of one layer with gathered KV heads.
- Decouples KV layouts from node configurations, allowing instances with different accelerator types, attention backends, or TP ranks to share cached data without format conversions.
- Enables just-in-time accelerator memory allocation by only reserving GPU memory once reloaded KV data is ready in host DRAM.

**Why it matters:** It prevents expensive KV cache recomputation for long contexts, reduces latency, and enables horizontal cache sharing across heterogeneous nodes.
