AWS details a solution using NVIDIA NeMo Switchyard integrated with LiteLLM on Amazon ECS to route coding agent requests across Amazon Bedrock models based on recent tool activity history or random weights.

- Evaluates model routing efficiency using cost per solved task (total run cost divided by test-passing runs) rather than price per token.

- LiteLLM invokes selected models via the Amazon Bedrock Converse or ConverseStream APIs over OpenAI-compatible endpoints.

**Why it matters:** It enables developers to optimize LLM API costs for multi-turn coding agent tasks by dynamically routing easier or later-stage execution steps to cheaper models.

**AWS Machine Learning Blog** · 2026-11-13

AssemblyAI optimized its speech-to-text inference platform costs on AWS using Amazon ECS capacity providers, multi-family NVIDIA GPU Spot Instances, and an Amazon SQS-based job retry mechanism.

- Uses Amazon ECS capacity providers to mix On-Demand and Spot Instances across GPU families including g4dn.xlarge, g4dn.2xlarge, g5.xlarge, g5.4xlarge, and g6.2xlarge.
- Employs an AWS Lambda Spot Interruption Handler triggered by Amazon EventBridge to return in-flight inference jobs back to a main Amazon SQS queue upon receiving a two-minute interruption notice.

- Deploys regionally across us-west-2 (Oregon) and eu-west-2 (London) to comply with European data residency requirements for regulated industries.

**Why it matters:** This architecture demonstrates how high-volume, latency-sensitive GPU inference workloads can achieve significant cost reductions using Spot Instances without sacrificing service availability or data compliance.

### [Architecture patterns for fast session startup on Amazon Bedrock AgentCore runtime](https://aws.amazon.com/blogs/machine-learning/architecture-patterns-for-fast-session-startup-on-amazon-bedrock-agentcore-runtime/)

**AWS Machine Learning Blog** · 2026-11-13

Amazon Bedrock AgentCore runtime V2 replaces per-session container initialization with microVM snapshotting and restore, significantly reducing cold start latency.

- AgentCore V2 initializes the container once during creation or update, freezes the microVM upon a successful GET /ping, and stores a memory and disk snapshot.
- New sessions resume directly from the restored snapshot, keeping all pre-initialized process memory, imports, and objects instantly accessible.
- File system caches are cleared before snapshotting, meaning image files are fetched lazily from snapshot storage upon their first read during a session.
- Developers can use build hooks before calling app.run() to prime large dependencies and assets into memory prior to snapshot creation.
- Architectural patterns for sub-second responses include background session pre-warming when a user opens an app or chat interface.

**Why it matters:** Understanding V2 snapshot lifecycle dynamics allows developers to structure initialization code to eliminate image pull overhead and achieve consistent, fast session start times.
