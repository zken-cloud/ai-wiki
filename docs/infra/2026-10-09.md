### [Session-Aware Agentic Inference with NVIDIA Dynamo](https://pytorch.org/blog/session-aware-agentic-inference-with-nvidia-dynamo/)

**PyTorch Blog** · 2026-10-08

NVIDIA Dynamo introduces a unified session-level identifier to transform request-level serving infrastructure into a program-aware system for agentic LLM workloads.

- Utilizes stable session_id and parent_session_id tags to link multi-turn tool calls, subagents, and parent-child trajectories across inference requests.
- Implements session-aware scheduling and admission control that accounts for session working sets and applies backpressure at tool boundaries to prevent KV cache thrashing.
- Provides programmatic KV cache management via an experimental shared-pool indexer, Session-Prefix Indexer, and proposed KvHint interface across vLLM and SGLang.
- Enables tracing and replay functionality to connect agent harness activity directly to inference performance for live benchmarking and offline simulation.

**Why it matters:** It enables inference servers to optimize KV cache residency and routing for multi-turn agentic workflows, drastically reducing redundant prefill latency and context re-computation.

### [Share GPU clusters across teams with isolation and fairness using Amazon SageMaker HyperPod](https://aws.amazon.com/blogs/machine-learning/share-gpu-clusters-across-teams-with-isolation-and-fairness-using-amazon-sagemaker-hyperpod/)

**AWS Machine Learning Blog** · 2026-10-08

AWS details a reference architecture for multi-tenant Amazon SageMaker HyperPod EKS clusters to share GPUs across teams with isolation and fair resource allocation.

- Authentication uses AWS IAM Identity Center federated with external identity providers (e.g., Microsoft Entra ID) to grant users temporary credentials via team permission sets.
- Teams access workloads via CLI using `aws sso login` and `kubectl` or via team-specific SageMaker AI domains and SageMaker Studio applications.
- Isolation and governance are achieved using dedicated Kubernetes namespaces per team, HyperPod Task Governance for resource allocation, and team-specific IAM execution roles.

**Why it matters:** It enables organizations to consolidate GPU infrastructure into a single cluster while maintaining secure team isolation, equitable resource sharing, and accurate cost chargebacks.
