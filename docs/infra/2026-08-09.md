### [Build visibility for Codex on Amazon Bedrock with OpenTelemetry and Amazon CloudWatch](https://aws.amazon.com/blogs/machine-learning/build-visibility-for-codex-on-amazon-bedrock-with-opentelemetry-and-amazon-cloudwatch/)

**AWS Machine Learning Blog** · 2026-08-06

AWS has published reference guidance to route OpenAI Codex OpenTelemetry metrics from local developer workstations directly to Amazon CloudWatch using a local collector and AWS SigV4 authentication.

- Uses a local OpenTelemetry collector bound to 127.0.0.1 on the developer workstation, avoiding a centralized proxy, load balancer, or public ingestion endpoint in the request path.
- Enriches local metrics with IAM Identity Center attributes including user, team, department, cost center, and organization context.
- Sends enriched metrics to regional CloudWatch OTLP endpoints using temporary credentials signed with AWS SigV4.
- Provides a pre-built CodexOnBedrock dashboard tracking rolling 24-hour active users, conversation turns, token usage, tool-call volumes, and API duration.
- Separates operational metric tracking from financial reporting, recommending AWS Cost and Usage Reports (CUR) 2.0 with IAM principal data for precise billing allocation.

**Why it matters:** Engineering leaders can monitor and govern developer AI agent usage, reliability, and token consumption across organizational units without altering local developer client workflows or deploying network proxies.
