### [Distributed Layerwise Offload: Scaling Toward 200B+ DiT Models Efficiently in vLLM-Omni](https://vllm.ai/blog/2026-08-17-distributed-layerwise-offload)

**vLLM Blog** · 2026-08-17

vLLM-Omni introduced Distributed Layerwise Offload (DLO), a technique that shards and streams Diffusion Transformer (DiT) weights across devices to run large models like 124 GB Cosmos3-Super on 64 GB HBM devices.

- Uses double-buffered prefetching to overlap Host-to-Device (H2D) transfers with AllGather weight reconstruction across devices.
- Shards host memory usage so cgroup-visible host memory scales as O(model_size + dp_size × constant) instead of duplicating the full model per DP rank.
- Supports a --dlo-no-use-allgather flag to disable weight sharding when AllGather synchronization overhead outweighs host memory savings.
- Requires vLLM 0.27.0 with vLLM-Omni v0.27.0rc1, incorporating PR #5864 to enable independent request dispatch per DP rank.

**Why it matters:** DLO enables serving massive video and image diffusion models exceeding single-device HBM capacity without requiring prohibitive multi-copy host RAM allocation.

### [NVIDIA Nemotron 3.5 Lightning now available in Amazon SageMaker JumpStart](https://aws.amazon.com/blogs/machine-learning/nvidia-nemotron-3-5-lightning-now-available-in-amazon-sagemaker-jumpstart/)

**AWS Machine Learning Blog** · 2026-08-17

NVIDIA Nemotron 3.5 Lightning is now available on Amazon SageMaker JumpStart, enabling simplified deployment of an open, high-throughput model built for agentic workloads.

- Features a hybrid Mixture-of-Experts (MoE) architecture with 30B total parameters and 3B active parameters, supporting up to a 1M-token context window.
- Utilizes DFlash speculative decoding to deliver up to 4x higher throughput and 30% faster task completion for agentic tool use.
- Distilled from NVIDIA Nemotron 3 Ultra and runnable on a single GPU in both BF16 and quantized NVFP4 formats.
- Achieves benchmark scores such as 81.94 (BF16) / 81.62 (NVFP4) on MMLU Pro and 51.56 (BF16) / 52.80 (NVFP4) on SWE-bench Verified.

**Why it matters:** Developers can route high-volume, specialized agent steps to a smaller, single-GPU model, reducing cost and latency compared to using frontier-scale infrastructure for every task.
