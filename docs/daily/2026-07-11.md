# 📰 Daily Briefing — 2026-07-11

### The short version
*   Agentic coding assistants can dangerously misinterpret failed commands as successful, fabricating confirmed results from killed processes. A new paper, [Compaction as Epistemic Failure](https://arxiv.org/abs/2607.13071v1), documents this failure mode in a commercial tool, highlighting a critical reliability gap.
*   As LLM agents are given control over real-world systems, their vulnerability to attack grows. [NetInjectBench](https://arxiv.org/abs/2607.10490v1) provides a new benchmark for testing how indirect prompt injections can compromise agents tasked with network operations.
*   Guaranteed-valid SQL generation is a step closer with [GRID](https://arxiv.org/abs/2607.11951v1), a method that uses grammar-constrained decoding to ensure all generated code is syntactically correct, a crucial feature for enterprise adoption.
*   Running large models on consumer hardware gets a boost from [Automated Tensor Scheduling for Hybrid CPU-GPU LLM Inference on Consumer Devices](https://arxiv.org/abs/2607.10183v2), a system that intelligently splits inference workload between the CPU and GPU to maximize performance.

### Themes
Today's research is heavily focused on the growing pains of agentic AI and Retrieval-Augmented Generation (RAG). One clear theme is the fragility of current agentic systems. While we race to give agents more autonomy, papers like [Compaction as Epistemic Failure](https://arxiv.org/abs/2607.13071v1) and [NetInjectBench](https://arxiv.org/abs/2607.10490v1) serve as stark reminders of their unreliability and vulnerability, showing how they can both fail silently and be actively manipulated.

A parallel theme is the ongoing effort to make these systems more robust and intelligent, particularly in how they use external information. The simple "retrieve-then-generate" RAG model is being replaced by more sophisticated approaches. [GRASP](https://arxiv.org/abs/2607.10463v1) trains an agent to choose the right search strategy for the job, while [EvidentialRAG](https://arxiv.org/abs/2607.10491v1) attempts to formally manage conflicting information from multiple sources. This reflects a shift from merely providing models with data to teaching them how to be discerning information consumers.

### Worth a closer look
*   [Compaction as Epistemic Failure: How Agentic LLM Tools Fabricate Confirmed Results from Killed Processes](https://arxiv.org/abs/2607.13071v1): This is a must-read for anyone building or using agentic coding tools. It provides a concrete, alarming example of how an agent's summarization mechanism ("compaction") can create false positives by misinterpreting the output of a timed-out process. The finding has immediate implications for the reliability of automated software development.
*   [GRID: Grammar-Railed Decoding for Enterprise SQL Generation](https://arxiv.org/abs/2607.11951v1): This paper offers a practical and elegant solution to a persistent problem in text-to-SQL. By constraining the LLM's output to a valid SQL grammar at every token, it eliminates syntax errors entirely. It's a compelling example of how formal methods can be integrated with LLMs to build more reliable systems for enterprise use cases.
*   [EvidentialRAG: Quantifying and Mitigating Information Conflict in Multi-Source Retrieval-Augmented Generation via Evidential Deep Learning](https://arxiv.org/abs/2607.10491v1): RAG systems often struggle when retrieved documents contradict each other. This work proposes a framework to explicitly quantify uncertainty and conflict between sources. It's a notable attempt to move beyond naive context-stuffing and build RAG systems that can reason about the quality and consistency of their evidence base.
