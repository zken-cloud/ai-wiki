### The short version
*   A new report details [TuxBot v3](https://unit42.paloaltonetworks.com/tuxbot-v3-evolution-iot-botnet/), an IoT botnet whose developers are reportedly using LLMs, providing a concrete example of AI-assisted malware creation.
*   Researchers propose using off-the-shelf multimodal models as zero-shot reward models for text-to-image generation, potentially sidestepping the need for expensive human preference data collection in the [Read It Back](https://arxiv.org/abs/2607.11886) paper.
*   Probing the internal states of LLMs provides a more reliable measure of their confidence in a forecast than their chain-of-thought reasoning, suggesting that what models "think" and what they "say" can diverge ([What LLM Forecasters Know but Don't Say](https://arxiv.org/abs/2607.08046)).
*   PyTorch now supports [Triton Plugin Extensions](https://pytorch.org/blog/triton-plugin-extensions-enabling-tlx-and-custom-compiler-passes-out-of-the-box/), allowing developers to add custom compiler passes without recompiling Triton, a key update for performance engineering and hardware-specific optimizations.

### Themes
Today's papers show a field grappling with the unreliability of its own creations. A significant cluster of research is dedicated to building better diagnostics. We see new benchmarks designed to systematically find failure modes in long documents ([SynthDocBench](https://arxiv.org/abs/2607.10400)), expose persistent [blind spots](https://arxiv.org/abs/2607.08317) in multimodal models, and test for knowledge of the world that can't be found in training data ([Search Beyond What Can Be Taught](https://arxiv.org/abs/2607.05382)). This focus on rigorous testing is a necessary, if unglamorous, step towards maturity.

In parallel, another set of papers attempts to engineer reliability from the ground up using agentic frameworks. Rather than relying on a single monolithic model, these approaches break problems down into discrete steps. One framework explicitly acquires knowledge about a code repository *before* attempting a fix ([Know Before Fix](https://arxiv.org/abs/2607.11111)), while another uses a "cynical" verification path to check for misleading data in charts ([Navigating the Mirage](https://arxiv.org/abs/2603.28583)). This suggests a move away from pure scaling and towards more structured, auditable reasoning processes.

### Worth a closer look
*   [What LLM Forecasters Know but Don't Say](https://arxiv.org/abs/2607.08046): This paper's finding that a model's internal representations are a better guide to its actual "beliefs" than its textual output is critical for anyone working on AI safety and auditing. It implies that simply reading a model's chain-of-thought is insufficient for genuine oversight.
*   [Read It Back: Pretrained MLLMs Are Zero-Shot Reward Models for Text-to-Image Generation](https://arxiv.org/abs/2607.11886): This is an elegant and resourceful approach. Using an existing MLLM to "read back" a generated image and check if it matches the prompt is a clever way to create a reward signal without any fine-tuning or preference labeling. It's a prime example of building new capabilities by creatively combining existing ones.
*   [TuxBot v3: Inside an IoT Botnet Framework With LLM-Assisted Development](https://unit42.paloaltonetworks.com/tuxbot-v3-evolution-iot-botnet/): While not a research paper, this security report provides a sobering, real-world look at how AI is already being used to accelerate malware development. It moves the discussion of AI misuse from the theoretical to the tangible.
*   [Let RGB Be the Language of Vision](https://arxiv.org/abs/2607.12450): This paper makes a bold claim: that diverse computer vision tasks like segmentation and depth estimation can be unified into a single RGB-to-RGB image editing problem. If the "RINO" model holds up, it could represent a significant step toward generalization in vision, though such unification claims often prove brittle.
