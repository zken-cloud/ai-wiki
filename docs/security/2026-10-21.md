### [After the Attacker Leaves: Benchmarking Carryover Attacks on LLM Agents](https://arxiv.org/abs/2610.28425v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28425v1`

CarryoverBench evaluates long-term LLM agent prompt injections, revealing that planted payloads re-fire without measurable decay over multiple sessions across five frontier models.

- Identifies two state persistence channels for carryover attacks: long-lived memory files prepended to system prompts and autonomous heartbeat-scheduled tasks.
- Introduces CarryoverBench, featuring 12 personal-assistant scenarios and 101 attack tasks across Instant (same-turn), Autonomous (heartbeat-scheduled), and Latent (memory-resurfaced) trigger channels.
- Employs a rule-based verifier to independently score the initial payload planting stage and the subsequent triggering stage.
- Demonstrates that conditional on successful payload planting, planted attacks re-fire without decay over five rounds, while porting to the Hermes runtime attenuates but fails to eliminate latent attacks.

**Why it matters:** The findings demonstrate that prompt-level defenses are insufficient to stop persistent indirect prompt injections, necessitating dedicated runtime-layer controls for long-term agent security.

<small>Zhiyue Xu, Xukai Wang, Zhiyuan Huang, Mingjie Zhan, Jian Zhao, Xu-Yao Zhang</small>

### [MAS-Guard: Unified Guardrails from Individual Agents to Multi-Agent LLM Systems](https://arxiv.org/abs/2610.28397v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28397v1`

MAS-Guard is a unified guardrail framework for single- and multi-agent LLM systems featuring local event assessment and system-level deterministic and semantic controls.

- A-Guard provides local-level guardrails within instrumentable agents using task-specific experts to evaluate agentic events.
- System-level security uses Agent Charters and a Control Plane combining deterministic checks (routes, capabilities, message formats) with semantic evaluations (roles, content).
- Interventions are standardized into four specific actions: allow, reflection, confirmation, and block.
- Empirical evaluation across six benchmarks and three LLM providers showed a 71.5-86.3% reduction in attack success rate while maintaining baseline utility on benign tasks.
- Supports heterogeneous environments containing both instrumentable and opaque (non-instrumentable) agents.

**Why it matters:** It offers a comprehensive defense architecture that mitigates security risks like information leakage and adversarial manipulation in complex multi-agent workflows without sacrificing task performance.

### [Context-Aware Prompt Injection Detection via Small Language Models in RAG Pipelines: nokast-secureRAG](https://arxiv.org/abs/2610.28364v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28364v1`

nokast-secureRAG is an open-source 0.5B small language model that acts as a context-aware semantic firewall, jointly evaluating user queries and retrieved context to detect indirect prompt injections with high accuracy.

- Trained via a teacher-judge-student pipeline using a 35B teacher for data generation and a 120B judge for labeling, reaching 95.0% teacher-judge agreement across 5,233 examples.
- Achieves 0.994 detection recall at a 0.026 false-positive rate on an in-distribution test set, outperforming Prompt-Guard-86M (0.900 recall, 0.690 false-positive rate) and Llama Guard 3 1B.

- Delivers 37 ms amortized throughput latency under batching (293-404 ms single-request latency).
- Exhibits near-zero recall on the external PoisonedRAG benchmark, highlighting a limitation against fluent fact-poisoning attacks that fall outside its instruction-consistency threat model.

**Why it matters:** It provides a lightweight, open-source defense mechanism that evaluates context-aware security in RAG pipelines without the high false-positive rates of non-contextual classifiers.

### [Disclosure Begets Disclosure: A Self-Reinforcing Privacy Loop in LLM Agents with Persistent Memory](https://arxiv.org/abs/2610.28315v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28315v1`

Persistent memory in LLM support agents triggers a self-reinforcing privacy loop where memory-conditioned responses lead users to affirm past disclosures, raising cumulative attribute leakage over time.

- Multi-session simulations tracking 24 personal attributes across four LLM support models showed memory usage improves response quality but widens empirical leakage over sessions.
- The privacy loop occurs in non-adversarial usage as agents repeat or presuppose earlier values, turning user affirmations, uncorrected guesses, and cues into persistent recorded data.
- User attempts to disrupt the loop fail: correcting errors still discloses attributes, opting out shifts model predictions toward sensitive values, and uncorrected errors entrench false data.
- Instructing the agent not to state or presuppose attributes reduces leakage to near no-memory levels while preserving quality gains, outperforming input filtering or memory anonymization.

**Why it matters:** Attempting to fix memory privacy at the input or storage level degrades agent performance, whereas restricting agents from repeating or presupposing user attributes prevents compounding privacy leaks.

<small>Masahiro Kaneko, Hiromi Arai, Timothy Baldwin</small>

### [ClawMMU: Protection-Coherent Virtual Memory for Stateful LLM Agents](https://arxiv.org/abs/2610.28093v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28093v1`

ClawMMU is a protection layer for stateful LLM agents that attaches origin and authority labels to memory to prevent context injection attacks.

- Labels every memory unit with owner, scope, origins, and authority attributes.
- Enforces authority checks when memory enters context, writes to storage, returns from storage, or triggers tool calls.
- Applies the core rule that information may rise in authority, but authority cannot elevate itself.
- Decouples security enforcement from content interpretation, converting memory attacks into deterministic protection faults at the harness level.

**Why it matters:** It prevents malicious web content and tool outputs from hijacking agent execution, protecting the system even when the underlying LLM is deceived.

### [Make the Adversary Spend More Energy: Generative Deception against Language-Model Attackers in Critical Infrastructure](https://arxiv.org/abs/2610.27739v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.27739v1`

A 330-session study shows generative language-model decoys force attackers to consume more GPU energy than defenders, though enabling runtime thinking can reverse this asymmetry.

- Across 330 sessions, 8 model pairs, and 2 attacker profiles, the attacker-to-defender GPU energy ratio (above idle) favored defenders in 41 of 48 non-diagnostic configurations and all 48 total configurations with thinking disabled.
- Token counts obscure true energy costs; token ratios stayed within a factor of two without generation-cap truncation, while energy costs differed significantly.
- Counter-injection responses increased attacker token output by approximately 9% per level, though without a statistically detectable pooled change in attacker energy consumption.
- Enabling runtime thinking on both sides increased defender energy use by 8 to 17 times, flipping the energy advantage back to the attacker for one model pair.
- Findings were applied to design a proposed SCADA deception architecture using private physical states per adversary alongside deterministic process and protocol emulation.

**Why it matters:** Generative deception can economically asymmetricize cyber defense by forcing automated LLM attackers to expend disproportionate computational energy during reconnaissance.

### [Local Allow, Global Deny: Why Per-Action Authorization Does Not Compose in LLM Agents](https://arxiv.org/abs/2610.27620v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.27620v1`

Researchers demonstrate that local per-action tool authorization in LLM agents fails to enforce global security policies, proving that relational purpose violations cannot be detected by single-trace per-action monitors without raising false alarms.

- Compositional authorization failures (CAFs) occur when locally authorized tool calls violate global policies covering intent, purpose, provenance, consent, and delegation.
- Relational purpose violations are classified as a 2-safety hyperproperty that lacks a per-trace locus of blame, making them impossible for precise per-action monitors to detect without cross-execution state.
- The authors developed AL-SYNTH, a SAT/SMT synthesizer that generates minimal CAF witness pairs without using language models.
- Across nine LLM judges, per-action monitors approved synthesized CAF witnesses at rates similar to benign controls, but flagged them when evaluating cross-execution pairs together.
- None of the six surveyed guardrail frameworks implement the cross-execution monitoring required to prevent 2-safety hyperproperty violations.

**Why it matters:** Current per-action guardrails are structurally incapable of preventing multi-trace authorization policy violations in autonomous LLM agents.

<small>Anmol Pandey, Aditya Jain, Liang Chen, Carsten Maple</small>

The Cloud Security Alliance proposes treating Model Context Protocol tool exposure as a privilege grant, advocating for a two-gate authorization model to secure AI agent tool catalogs.

- Model Context Protocol (MCP) enables AI agents to query databases, send messages, invoke APIs, and trigger workflows via standardized tool catalogs.
