### [Finding Vulnerabilities via LLM-Augmented Semantics-Aware Type-Checking](https://arxiv.org/abs/2608.14533v1)

**arXiv cs.CR** · 2026-08-14 · `arXiv:2608.14533v1`

SETYPE uses Large Language Models to derive type systems from code variable/function semantics, converting vulnerability detection into a semantics-aware type-checking process.

- SETYPE derives a semantics-aware type system directly from source code based on the natural language meanings of symbols and expressions.
- Type inference and type checking are offloaded entirely to LLMs, where a failed type check signals a potential security vulnerability.
- PYSETYPE, a Python web application prototype, achieved 87% detection precision and 88% detection accuracy in real-world evaluations.
- The tool identified 15 potential zero-day vulnerabilities, with nine officially confirmed by developers.

**Why it matters:** It replaces manual syntactic rule-writing in static analysis by leveraging LLM semantic understanding to automate complex zero-day vulnerability discovery.

**arXiv cs.CR** · 2026-08-14 · `arXiv:2608.14089v1`

Regime-Conditional Verification (RCV) is a lightweight wrapper that uses a classifier's internal representations to estimate policy disagreement, correct false predictions, and detect distribution shift without retraining the underlying model.

- RCV estimates the probability of prediction disagreement with a deployer's target policy using internal representations from off-the-shelf safety classifiers.
- It selectively corrects predictions likely to be wrong, catching up to 0.81 of previously missed unsafe content across tested datasets without modifying the classifier.
- Label-free correctness estimates enable shift detection, triggering a maintenance loop that updates the RCV layer and reserves full classifier fine-tuning for unresolved drift episodes.
- In a deployment study with ten held-out attack campaigns, RCV detected every campaign in a dedicated injection panel and repaired most drift episodes without classifier fine-tuning.

**Why it matters:** RCV enables dynamic adaptation and real-time drift monitoring for safety classifiers without the high computational cost of frequent model fine-tuning.

### [Does Fixing Break Security? An Empirical Study of Security Degradation in Iterative LLM-Driven Infrastructure-as-Code Repair](https://arxiv.org/abs/2608.13404v2)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.13404v2`

A study of LLM-driven Infrastructure-as-Code repair reveals that iterative fixes cause true security regressions in 3.3% of scenarios, primarily driven by resource restructuring and high code churn.

- Analysis of 5,968 IaC-Eval scenario timelines across 15 configurations identified true security regressions (strict detection) in 3.3% of scenarios and 5.2% of iteration transitions.
- Resource restructuring accounted for 79.0% of root causes, with regression transitions exhibiting 2.6x more code churn (Cohen's d=0.90) and 4.9x higher check volatility (d=1.49).
- Standard detection metrics inflated apparent regressions to 13.8% of scenarios due to multi-resource measurement artifacts.
- 36.6% of standard-mode regressions self-correct in an average of 1.2 iterations, establishing iteration 3 as the optimal stopping point for repair loops.

**Why it matters:** Iterative LLM repair loops require security-aware feedback mechanisms and capped iteration budgets to prevent automated code fixes from introducing silent security vulnerabilities.

<small>Benjamin Agyekum, Fabio Santos</small>
