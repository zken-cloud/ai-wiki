### [PatchBench: Measuring Collateral Damage in Activation Patching](https://arxiv.org/abs/2610.10276v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.10276v1`

PatchBench and PatchBench-Local evaluate jailbreak safety patches by measuring local collateral damage, distinguishing selective model repairs from over-refusal and ungeneralizable suppression through paired local prompt neighbors.

- PatchBench curates a bank of 400 high-confidence jailbreak failures derived from 15,314 English prompts across 8 open-source instruction-tuned models using WildGuard filtering, pairwise Elo ranking, and human verification.
- PatchBench-Local tests behavioural precision around harmful source prompts using three local neighbor types: intent-preserving harmful variants, structure-matched benign prompts, and key-term-reusing benign prompts.
- Experiments evaluating four activation steering methods on MMLU and PatchBench-Local demonstrate that global capability metrics mask severe local benign performance regressions.

**Why it matters:** Aggregate capability and safety metrics fail to detect local over-refusal and narrow over-fitting, necessitating neighbor-based precision testing to evaluate actual jailbreak repairs.

<small>Alexi Canesse, Mathis Le Bail, Maël Jenny, Clément Elliker, Mahammed El Sharkawy, Sonia Vanier</small>

### [On the Reliability of LLM-Based Vulnerability Patching Benchmarks](https://arxiv.org/abs/2610.10150v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.10150v1`

A study reveals that LLM vulnerability patching benchmarks suffer from severe evaluation distortions, with high proof-of-concept pass rates masking low alignment with original developer-written tests.

- Evaluated LLM patching across 112 historical bugs from 84 open-source C/C++, Go, and Rust projects using proof-of-concept (PoC), regression, and developer tests.
- Identified agent-level pitfalls where specific prompting, tool access, and detailed instructions boost benchmark success rates without improving real patch quality.
- Discovered framework-level flaws, including timeout handling, infrastructure bugs, and permission errors, that silently distort model performance metrics.
- Found that while LLMs achieve high PoC test pass rates, developer-test pass rates remain low and show minimal improvement in newer models, indicating models often mask symptoms rather than fixing root causes.

**Why it matters:** Current benchmark metrics overestimate the practical utility of LLM patch generation by rewarding symptom suppression rather than upstream-quality, root-cause fixes.

<small>Dang K Le, Wenxuan Shi, Xinyu Xing</small>

### [Sensitive-Topic Leakage Through LLM Routing Metadata: Measurement and Mitigation](https://arxiv.org/abs/2610.09981v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.09981v1`

LLM routing decisions reveal user sensitive topics even with content logging disabled, but accurate per-category length-matched parity mitigates this side-channel leakage with minimal accuracy loss.

- Evaluated 1.7 million requests from WildChat-1M and LMSYS-Chat-1M across cost/quality and domain routers, demonstrating that metadata logs reveal sensitive topics like harassment, self-harm, medical, and sexual queries.
- RouteLLM metadata allows tracking frequent medical askers across 20 requests with an AUC of 0.71, while a domain router achieves an AUC of 0.92.
- Sensitive topic routing gaps on RouterBench (13-42 points) significantly exceed an oracle router's baseline gaps of 1-11 points.
- Per-category length-matched parity using accurate labels eliminates the privacy gap on real traffic while costing at most 0.2 accuracy points on RouterBench.
- Defenses like per-conversation stickiness, per-user budget bands, pooled parity, and exact per-user rate limiting fail to fully prevent side-channel leaks (e.g., log attacks still reach 0.73 AUC after 20 requests).

**Why it matters:** LLM gateways logging basic model routing metadata expose sensitive user prompt topics even when full payload logging is turned off.

<small>Teng-Ruei Chen</small>

### [Formal Runtime Verification for Tool-Using LLM Agents: An Offline Same-Benchmark Study on AgentDojo and STAC](https://arxiv.org/abs/2610.09793v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.09793v1`

Researchers evaluated metric first-order temporal logic (MFOTL) runtime verification on tool-using LLM agent benchmarks using the MonPoly monitor, demonstrating effective attack detection alongside vulnerabilities to trace manipulation.

- Evaluated five generic MFOTL obligations offline on AgentDojo, STAC, and R-Judge corpora using the unmodified MonPoly monitor.

### [Understanding and Mitigating Token-Pruning-Induced Vulnerabilities in VLMs](https://arxiv.org/abs/2610.09703v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.09703v1`

Researchers identify how token pruning causes safety degradation in VLMs and introduce Safety-Aware Pruning (SAP) to reduce Attack Success Rates by up to 62% without losing efficiency.

- Pruning strategies generally degrade safety at higher pruning ratios, whereas Query-based Compression improves safety under extreme pruning up to 99.8%.
- Pruning-Induced Malicious Amplification occurs when removing background tokens forces model attention to collapse onto retained malicious foreground anchors, amplifying toxic semantics under jailbreak attacks.
- Safety-Aware Pruning (SAP) is an inference-time, plug-and-play mechanism that identifies malicious anchors, restores pruned benign tokens, and reallocates attention away from malicious anchors.
- Experiments across three safety and four utility benchmarks show SAP reduces Attack Success Rate (ASR) by up to 62% while maintaining model utility and acceleration.

**Why it matters:** Understanding and counteracting pruning-induced vulnerabilities allows developers to deploy accelerated Vision-Language Models without exposing them to heightened jailbreak risks.

<small>Shuailong Wang, Xinyu Lyu, Shengming Yuan, Jingkuan Song, Heng Tao Shen, Lianli Gao</small>

### [Correct Answers, Unsupported Findings: Evidence Binding in Forensic Reconstruction of LLM Agent Logs](https://arxiv.org/abs/2610.09581v1)

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.09581v1`

A forensic evaluation of LLM agent log reconstruction reveals that models often output correct source locations without preserved evidence bindings, making factual accuracy insufficient to prove forensic grounding.

- Audited LLM readers using 64 mechanically checkable cases from saved AgentDojo Banking execution logs under varying visible evidence and identifier-to-record bindings.
- Without a binding table, Claude Sonnet identified literal source locations but made unsupported citation-source assertions in 26 out of 28 cases needing the missing relation, despite matching the reference answer in 22 of those cases.
- Providing explicit record bindings improved grounded reconstruction across tested LLM readers, whereas identifier renaming alone failed to provide a consistent fix.
- A deterministic same-packet comparator successfully resolved the bounded reconstruction task or abstained without generating unsupported assertions.

**Why it matters:** Forensic log analysis requires explicit, preserved record bindings rather than relying on LLM correctness alone to ensure findings are genuinely supported by evidence rather than guessed.

**arXiv cs.CR** · 2026-10-07 · `arXiv:2610.09469v1`

Secure-CUA protects computer-use agents from untrusted content attacks by executing actions via pre-committed action transactions that use an isolated query model and masked interface targets.

- Formalizes security requirements for agent decisions and GUI command executions to protect execution traces.
- Introduces action transactions that commit to explicit per-action programs, fixing queries to untrusted content and restricting permitted response uses prior to accessing untrusted content.
- Employs an isolated query model for untrusted queries and masks untrusted interface regions to locate target elements securely.
- Evaluated on 400 WebArena tasks across 6,000 execution traces using three frontier models, Secure-CUA achieved a 53.55% success rate under benign conditions, compared to 55.12% for Vanilla-CUA and 13.17% for CaMeL-CUA.

**Why it matters:** It demonstrates a secure-by-design architecture for computer-use agents that defends against indirect instruction injection and visual manipulation while maintaining competitive task utility.

### [Visual Memory Attacks Can Persist Through The KV Cache](https://arxiv.org/abs/2610.09027v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.09027v1`

Persistent Visual Memory Injection (P-VMI) demonstrates that adversarial image attacks can steer vision-language models via the KV cache even after the trigger image is masked from attention or contextually summarized.

- Persistent Visual Memory Injection (P-VMI) optimizes images to plant hidden backdoors that persist after the input image is masked from attention.
- On Qwen3-VL-8B-Instruct, P-VMI achieves up to approximately 90% target attack success in its strongest configuration, remaining effective even when the image is exposed only on the first turn.
- A cache-swap ablation directly localizes the persistent adversarial influence to the model's KV cache.
- Attacks survive context compaction where only the KV cache of a model-generated summary is retained, proving adversarial behavior persists without direct access to the source image.

**Why it matters:** Autonomous language model systems using persistent KV caches or long-context summaries remain vulnerable to adversarial control even after malicious visual inputs are pruned from context.

<small>David Dobre, Leo Schwinn, Gauthier Gidel, Spandana Gella, Perouz Taslakian, Pierre-André Noël</small>
