### [The Implications of Linguistic Illegibility for LLM Security](https://arxiv.org/abs/2609.02852v1)

**arXiv cs.CR** · 2026-09-02 · `arXiv:2609.02852v1`

This paper introduces linguistic illegibility, arguing that language-based LLM security methods are fundamentally unsound because internal continuous activation computations do not reliably map to externalized or probed natural language.

- Defines linguistic illegibility as scenarios where an LLM's externalized outputs or mechanistically-probed language features fail to represent internal model computation.
- Demonstrates that security controls relying on linguistic self-reporting—including chain-of-thought monitoring, constitutional self-critique, and feature vector activation probing—are inherently unsound.
- Proposes taint tracking as an alternative sandboxing approach to define a priori system state constraints independent of model-produced linguistic data.
- Advocates for non-linguistic isolation techniques, such as robust virtualization and third-party auditing of configurations, to prevent sandbox exploits.

**Why it matters:** AI safety architectures cannot rely solely on language monitoring or interpretability probes to prevent sandbox escapes, requiring deterministic system-level controls like taint tracking.

### [CodePoisonRAG: Knowledge Poisoning Attacks on Retrieval-Augmented Code Generation](https://arxiv.org/abs/2609.02774v1)

**arXiv cs.CR** · 2026-09-02 · `arXiv:2609.02774v1`

CodePoisonRAG is a targeted, black-box knowledge-poisoning framework that transforms benign code into task-aligned, mislabeled poisoned artifacts to reliably inject specific vulnerabilities via Retrieval-Augmented Code Generation (RACG).

- Combines CWE-specific Vulnerability Injection (embedding source-to-sink flows) with Semantic Mislabeling (adding false safety claims without fixing flaws).
- Operates under a strict black-box model without access to the victim's retriever, re-ranker, generator, prompt, or defenses, injecting at most one artifact per task.
- Tested with 85 poisoned artifacts across ten CWE classes in Java and C, comprising a 0.7% corpus-poisoning ratio.
- Achieved Top-3 retrieval placement for all 85 artifacts, yielding attack success rates of 0.80 to 0.93 across three generators.
- Maintained attack success rates between 0.40 and 0.71 against the CodeGuarder defense mechanism.

**Why it matters:** It demonstrates that RACG pipelines are vulnerable to targeted, low-volume poisoning attacks that bypass safety defenses to deliberately inject specific security flaws into generated code.

<small>Varun Gadey, Ziad Marey, Alexandra Dmitrienko</small>

### [ACLE-MCP: Attested Capability Leases for Execution-Time Trust in Remote LLM Tool Use](https://arxiv.org/abs/2609.02690v1)

**arXiv cs.CR** · 2026-09-02 · `arXiv:2609.02690v1`

ACLE-MCP closes the post-authorization execution trust gap in remote LLM tool use by issuing short-lived, sender-constrained capability leases validated by a provider-side Execution Gate at invocation time.

- Binds delegated authorization, workload appraisal, freshness requirements, operation/object bounds, downstream constraints, and receipt obligations into an invocation-scoped lease.
- Implements an Execution Gate that validates the capability lease immediately before protected tool logic executes on the provider side.
- Prototype uses a Keycloak/OIDC validation pipeline, an MCP Python SDK server, and an optional vTPM quote-verification backend.
- Blocks all evaluated post-authorization attack families (such as workload substitution and stale appraisal) while preserving benign tasks, at a cost of a 25.7% p95 latency increase over OAuth-only in local simulations.

**Why it matters:** It provides a practical security mechanism to ensure remote LLM tool calls execute strictly on verified, intended provider workloads beyond basic OAuth connection authorization.

<small>Zhiyang Ding, Yang Luo, Guangpu Chen, Qingni Shen, Zhonghai Wu</small>

Researchers identified endogenous authorization laundering in LLM agents, where persistent memory errors create false permissions that executors act on, and introduced the EAL-Bench benchmark to evaluate this vulnerability.

- Endogenous authorization laundering occurs without external attacks when persistent memory incorrectly records permission changes, stripping away authorization provenance.
- Evaluating five LLM writers and two executors across procurement, cybersecurity, and finance revealed writers create false authority in up to 50.2% of unauthorized requests under incremental updates.
- Once false authority exists in persistent memory, LLM executors carry out unauthorized actions in 98.6% of test trials.
