### [BARE-AI: Bit-Flip Attack Resilience in AI Hardware through Built-in Performance Monitors](https://arxiv.org/abs/2610.08739v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08739v1`

BARE-AI is a hardware-based runtime framework that uses AI Performance Counters and an ensemble-based neural engine to detect, localize, and mitigate bit-flip attacks during inference with constant overhead.

- Uses hardware AI Performance Counters (APCs) in the accelerator datapath to track layer activation metrics including sparsity, entropy, kurtosis, and spectral shift.
- Employs the Predictive Unit for Layer Security Evaluation (PULSE), an ensemble detector on a small neural engine, and an Activation Shift Index (ASI) for layer-level fault localization.
- Applies a z-score based repair to reset anomalous weights toward clean layer statistics without relying on error correcting codes (ECC) or model retraining.
- Achieves 98% detection accuracy on vision models (CNNs, ViTs) and 74-95% on LLMs under random, targeted, adaptive, and magnitude-based attacks.
- 28nm synthesis demonstrates under 3% energy, under 4% area, and 6% to 10% latency overheads that remain constant regardless of attack strength.

**Why it matters:** It provides a low-overhead, hardware-level defense against memory bit-flip attacks for safety-critical edge AI applications without requiring retraining or scaling overhead with fault counts.

<small>Habibur Rahaman, Swastik Bhattacharya, Sanjay Das, Kanad Basu, Swarup Bhunia</small>

### [Semantic Behavioral Watermarking: Paraphrase-Robust and Forgery-Resistant Provenance for LLM Agents](https://arxiv.org/abs/2610.08668v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08668v1`

Semantic Behavioral Watermarking (SBW) embeds provenance into LLM agent trajectories using semantic action clusters and keyed collision-resistant binning, providing high paraphrase robustness and resistance to adaptive forgery without modifying output tokens.

- SBW embeds watermarks over semantic action clusters rather than exact action symbols, preserving decoding accuracy under tool renaming and observation paraphrasing.
- Replaces public-cluster bins with keyed, collision-resistant binning that is provably unpredictable in the random-oracle model, dropping adaptive forgery from 100% to the false-positive floor.
- Achieves 0.49-0.66 detection under rewriting on ToolBench and 0.92-0.97 on ALFWorld across five 3B-14B models, outperforming exact-symbol baselines.
- Paraphrase robustness reduces per-step watermark capacity by roughly 50%.
- Neutralizes shuffled splicing attacks, though chained replay of victim steps remains an open challenge with 0.76-0.98 forgery rates.

**Why it matters:** It enables reliable, tamper-resistant attribution for LLM agent actions even when tool definitions, observations, or actions are rewritten or paraphrased by an adversary.

<small>Suxin Ji, Hungtao Wan, Shaoxuan Chen, An Zhang</small>

### [Newer and Bigger, but Safer? A Longitudinal Study of the Functionality-Security Gap in LLM-Generated Code](https://arxiv.org/abs/2610.08240v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08240v1`

A longitudinal evaluation of 32 LLMs across seven families reveals that newer open-weight models significantly narrow the functionality-security gap, contradicting prior findings that open models stagnate while proprietary models remain safer.

- Evaluated 32 LLMs across 7 model families (5 open-weight) using CWEval, covering 119 tasks across 5 programming languages and 31 Common Weakness Enumerations (CWEs).
- Openness does not dictate security performance; all open-weight families narrowed the gap significantly, whereas Gemini 3.1 Pro maintained a gap as wide as Llama's.
- Compact variants generally produce less secure code than flagships, though exceptions like Gemini 3.7 Flash exist.
- Persistent vulnerabilities remain high across generations, notably log injection (CWE-117) and HTTP response splitting (CWE-113), alongside regressions in newer proprietary models regarding memory and integer weaknesses.
- Vulnerability risks for the same CWE vary significantly depending on the target programming language.

**Why it matters:** Developers cannot assume model upgrades or proprietary status guarantee improved code security, making continuous automated security testing necessary after any LLM version change.

<small>Thiago Santos de Moura, Fynn Matuschek, Flavio Toffalini, Yannic Noller</small>

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08098v1`

CORSA optimizes skill injections for both retrieval and execution, overcoming an 87-97% attack success rate drop observed when realistic skill routers dynamically select third-party skills.

- Evaluations assuming pre-selected malicious skills overestimate efficacy, as realistic multi-skill router retrieval reduces existing injection attack success rates (ASR) by 87-97%.
- CORSA (Cluster Optimization for Router-Aware Skill Attacks) uses successive optimization stages to optimize injections for retrieval and execution across task clusters.
- The authors benchmarked skill injections by extending SkillRouter's dataset with eight malicious payload categories, evaluating user utility and naturalism separately.
- CORSA-generated attacks demonstrated transferable efficacy across different router architectures and underlying LLM backbones without sacrificing user utility.

**Why it matters:** It demonstrates that multi-skill security evaluations must account for the retrieval stage, while showing that dynamic routers can be bypassed by router-aware prompt optimization.

### [When Tools Lie: Reliability of Mathematical Agents Under Corrupted Tool Feedback](https://arxiv.org/abs/2610.08097v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08097v1`

A controlled study evaluates mathematical agent robustness under corrupted tool outputs, finding that mandatory reflection recovers 100% accuracy while optional verification success depends strictly on model invocation choices.

- Tool output corruption reduced baseline agent accuracy without verification from 100% down to 72.4% across 31 targeted problems.
- Mandatory same-context reflection fully restored agent accuracy back to 100%.
- Optional fresh-context and structural verifications improved accuracy only when models actively chose to invoke them.
- A supporting recovery experiment demonstrated that explicit detection followed by a full problem restart succeeded in 100% of cases.
- Results show that verifier availability and verification policies are distinct components, with checking frequency driving overall robustness.

**Why it matters:** Mathematical agents implicitly trusting silent tool failures suffer severe accuracy loss unless governed by mandatory verification policies or explicit restart mechanisms.

<small>Kavienan Jegatheesan, Gayathri Lihinikaduarachchi</small>

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.08061v1`

ASCENT is a downstream fine-tuning framework that alternates between first-order optimal task updates and periodic safety calibration to simultaneously enhance LLM utility and safety.

- Mathematically models LLM safety as a function $S(\theta)$ and uses its first-order gradient approximation to guide parameter updates.
- Proves that under a fixed rank and Frobenius-norm budget, an update constructed from the top-$r$ singular components of the safety-function gradient maximizes estimated safety gains.
- Derives a unique safety-preserving task update that minimizes deviation from original task updates while penalizing negative safety impacts.
- Demonstrates empirical improvements across multiple LLM families, increasing downstream utility by up to 20.3% and reducing attack success rates by up to 35.5%.

**Why it matters:** It provides a mathematically optimal method to fine-tune LLMs on downstream tasks without suffering from safety degradation or relying on static, outdated safety subspaces.

### [What Response Marginals Miss: Adaptive Query Complexity of Functional Backdoor Recovery](https://arxiv.org/abs/2610.07771v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.07771v1`

Researchers proved that response marginals and attack success rates are insufficient to determine functional backdoor recovery query complexity, demonstrating an adaptive query separation between Θ(log H) and Θ(H) under multi-class label feedback.

- Constructed two victim model families with identical attack success rates and query label distributions, yet possessing divergent adaptive query complexities of Θ(log H) and Θ(H) for H possible victims.
- Identified that the query complexity gap stems from non-target labels mapping to different victim subsets, altering the rate at which adaptive queries eliminate candidate models.
- Demonstrated that the complexity separation collapses under binary target-only feedback, but persists under multi-class label feedback for any fixed failure probability below one.
- Empirically validated the theoretical query bounds using trained CIFAR-10 ResNet-18 classifiers.

**Why it matters:** Evaluating backdoor recovery algorithms using only marginal label distributions or attack success rates can severely miscalculate the query budget required to identify functional triggers.

<small>Yunjae Hwang, Byoungjin Seok</small>

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.07723v1`

A novel answer-side backdoor attack for multi-turn LLMs induces the model to self-generate the trigger word in a benign turn, bypassing input-centric safety guardrails when a subsequent harmful query is submitted.

- The attack relies on a benign first-turn prompt that causes the LLM to output a specific word, which acts as the backdoor trigger once added to dialogue history.
- Subsequent harmful queries contain no input triggers, allowing the attack to bypass traditional input-sanitization guardrails while suppressing the model's refusal signal at the representation level.
- Evaluated across four LLMs, the attack achieved near-100% Attack Success Rates (ASR) at a 5% dataset poisoning rate without sacrificing general model utility or clean-input safety.

**Why it matters:** Current LLM defense mechanisms focus heavily on sanitizing user inputs, leaving systems vulnerable to stateful, multi-turn attacks triggered by the model's own context.

Adaptive model inversion attacks reveal that standard evaluations underestimate privacy leakage by 1.16x to 6.59x on FaceScrub, exposing a generalized tradeoff between privacy and adversarial robustness.

- Standard model inversion attack (MIA) evaluations mistake optimization and evaluation measurement failures for model privacy.
- Targeted training-data image leakage increases by 1.16 to 6.59 times on FaceScrub using adaptive attack modifications, with the highest increases occurring in defenses previously claiming the strongest privacy.
- Measured identity reconstruction rates depend heavily on the feature basis of the external evaluator, such as standard vs. adversarially trained Inception classifiers.

**Why it matters:** Current evaluation methodologies for privacy defenses overestimate model privacy, challenging the feasibility of building models that are simultaneously robust to adversarial attacks and resilient against training-data reconstruction.

Researchers introduced DEFER1, a defense framework for multi-agent systems that combines a cascade of 28 deterministic checks with a panel of four LLM judges to drop attack success rates from ~30.0% to ~3.0%.

- DEFER1 organizes defenses into five principles, utilizing 28 deterministic checks to filter explicit policy violations before escalating residual intent-misrepresentation attacks to a four-judge panel.
- Deterministic rules handled 78% of all blocked attacks, reducing the volume of proposals reaching the judge panel to only 25% in the security-operations domain.
- Across four test domains, the combined rule-and-judge architecture reduced overall attack success rates from approximately 30.0% to roughly 3.0%.
- Evaluations revealed specific failure modes in both layers, such as a risk-score approval gate that mistakenly approved a majority of attack proposals while rejecting legitimate ones.

**Why it matters:** The system demonstrates that pairing low-cost deterministic rule cascades with LLM judges efficiently secures multi-agent systems while pinpointing structural weaknesses like flawed risk-scoring gates.

### [SkillPoison: Progressive Skill Poisoning via Successful Experiences](https://arxiv.org/abs/2610.07645v1)

**arXiv cs.CR** · 2026-10-06 · `arXiv:2610.07645v1`

SkillPoison is a framework that causes LLM agent skill poisoning using only task-correct, verified successful experiences by removing context conditions to force over-generalized, misapplied behaviors.

- Constructs successful experiences that reinforce a target behavior, then strips out contextual conditions that limit when that behavior should apply.
- Manipulates the skill extractor's generalization process rather than injecting explicit malicious content, triggers, or false facts into individual trajectories.
- Achieves a 95.71% attack success rate across three benchmarks while remaining undetected by lexical inspection and task-correctness verification.

**Why it matters:** It demonstrates that persistent, malicious skills can be introduced into self-improving LLM agents without compromising the validity or safety of any individual training experience.
