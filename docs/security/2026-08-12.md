### [Once Poisoned, Arbitrarily Controlled: A Programmable Backdoor in VLMs](https://arxiv.org/abs/2608.10959v1)

**arXiv cs.CR** · 2026-08-11 · `arXiv:2608.10959v1`

A new poisoning method implants a programmable backdoor into Vision-Language Models, allowing attackers to dynamically specify unseen target captions and generate stealthy visual triggers at inference without retraining.

- Decouples target caption selection from the initial poisoning phase, introducing an any-to-any caption-control attack paradigm.
- Uses a heuristic poisoning strategy that trains the model on diverse trigger-caption pairs to establish a general trigger-as-instruction rule.
- Employs feature-space trigger steganography to map arbitrary target captions to stealthy visual triggers, such as norm-controlled perturbations or non-semantic patches.
- Maintains high attack success rates on previously unseen target captions while preserving clean model utility and bypassing several classical backdoor defenses.

**Why it matters:** It demonstrates that VLM backdoors can be dynamically controlled post-training, significantly underestimating the risk posed by traditional static, fixed-mapping backdoor attacks.

<small>Tao Lin, Gaojie Jin, Zongxin Liu, Peng Wu, Lijia Yu</small>

### [Trigger the Straggler: Load Hijack on Mixture-of-Experts LLMs](https://arxiv.org/abs/2608.10614v1)

**arXiv cs.CR** · 2026-08-11 · `arXiv:2608.10614v1`

Load Hijack is a supply-chain attack that modifies MoE router weights, allowing a private trigger to concentrate token assignments onto a single GPU, creating a straggler that degrades multi-GPU serving performance.

- The attack uses a three-stage optimization procedure on router weights to isolate trigger-dependent expert concentration without biasing ordinary routing behavior.
- Evaluated across three MoE model families and four corpora, the attack routes 92.3% to 95.6% of triggered token assignments to target experts co-located on one GPU.
- During live Expert Parallelism (EP) serving, triggered inputs increase time-to-first-token by 1.43x and reduce overall throughput to 0.86x compared to normal traffic.

**Why it matters:** This vulnerability demonstrates that malicious model checkpoints can act as trigger-controlled device schedulers, highlighting the need for routing audits and runtime load monitoring in MoE deployments.

<small>Rui Zhang, Wenbo Jiang, Hongwei Li, Zihan Wang, Rui Zhang, Chaoshun Zuo, Jianfei Sun, Guowen Xu</small>

### [On Understanding, Identifying, and Mitigating Vulnerabilities in Agentic Large Language Models](https://arxiv.org/abs/2608.10530v1)

**arXiv cs.CR** · 2026-08-11 · `arXiv:2608.10530v1`

A PRISMA 2020 systematic review of 85 agentic LLM security papers reveals a 3.9:1 attack-to-defense research imbalance, proposing a four-layer taxonomy across 13 vulnerability types driven by architectural coupling.

- Literature review screened 743 records across six databases, retaining 85 papers from 2023 to 2025.
- Perception-layer vulnerabilities dominate the literature at 66%, while action-layer issues (4.7%), tool-augmented agent risks (12%), and code execution security (3.5%) are underrepresented.
- Introduces a four-layer taxonomy covering 13 vulnerability types across perception, brain, action, and interaction layers.
- Identifies architectural coupling and weak isolation as the root causes enabling vulnerability propagation across layers.

**Why it matters:** Current security research disproportionately focuses on perception attacks rather than action-layer risks, leaving autonomous agents vulnerable to unauthorized API calls, code execution, and database modifications.

<small>Md Jafrin Hossain, Mohammad Arif Hossain, Nirwan Ansari</small>

### [From Prompt Injection to Web Exploitation: Revisiting Classic Vulnerabilities in LLM-Integrated Applications](https://arxiv.org/abs/2608.10281v1)

**arXiv cs.CR** · 2026-08-10 · `arXiv:2608.10281v1`

This paper formalizes LLM-mediated web attacks (LLM2X), demonstrating how LLMs act as confused deputies that translate prompt injections into traditional web vulnerabilities like SSRF, SQLi, and Command Injection.

- Systematizes the LLM attack surface into LLM2X variants, including LLM2SQLi, LLM2XSS, LLM2SSTI, LLM2CommandInjection, LLM2IDOR, LLM2CSRF, LLM2XXE, and LLM2SSRF.
- Identifies that LLMs act as a mediation layer or confused deputy, passing attacker influence into unsafe web-application sinks rather than generating novel vulnerability classes.
- Evaluated LLM2SSRF across five attack scenarios using TicketOracle, a Flask-based testbed, finding exploit success varies significantly across seven tested LLMs based on architecture and model behavior.
- Outlines multi-layer defenses spanning prompt, model, application, and network levels.

**Why it matters:** Securing LLM applications requires traditional web security controls at the backend sink level, as prompt-level defenses alone fail to prevent models from executing indirect web exploits.

<small>Spiros Tsigkopoulos, Christoforos Ntantogian</small>

### [Withholding the Completing Chunk: Deterministic Pair-Completion Guardrails for Streaming LLM Output](https://arxiv.org/abs/2608.10279v1)

**arXiv cs.CR** · 2026-08-10 · `arXiv:2608.10279v1`

A deterministic streaming guardrail withholds the exact chunk that completes a two-predicate danger signature, preventing text leakage while matching buffered scanning accuracy.

- Evaluated across four signature families, eight chunk sizes, and 32 mechanism trials, the guard withheld every pair-completing chunk with zero failures.
- In a 512-trial comparison, full-prefix scanning and complete buffering detected 128/128 configured pairs, outperforming a 512-character window (96/128) and chunk-local scanning (38/128).
- Fixed pairs yielded zero false positives on 338 safe responses and zero detections on 394 general unsafe responses, highlighting its role as a narrow policy backstop rather than a semantic moderator.
- Llama Guard 3 1B baseline achieved 310/338 on safe responses and 202/394 on unsafe responses.
- Repeated-prefix scanner overhead ranged from 13.261 ms to 829.640 ms on 16,384-character outputs depending on chunk size.

**Why it matters:** It provides a zero-leakage, deterministic release boundary backstop for known multi-token danger signatures in streaming LLM architectures without requiring full response buffering.

<small>Christopher M. Frost</small>

### [Diversity Matters: Distributional Feature Coverage Sample Selection for Data-Efficient Backdoor Attacks](https://arxiv.org/abs/2608.09047v1)

**arXiv cs.CR** · 2026-08-10 · `arXiv:2608.09047v1`

Distributional Feature Coverage Sample Selection (DFCS) is a training-free, trigger-agnostic backdoor sample selection method that clusters pretrained features to select diverse, representative poison samples at low budgets.

- DFCS clusters fixed pretrained features into distinct semantic regions corresponding to available poisoning slots and selects the centroid-nearest sample per cluster.
- A local first-order theoretical analysis connects the selection approach to feature-coverage and representative-mass terms.
- In evaluations across CIFAR-10, Tiny-ImageNet, and Imagenette with BadNets and Blended attacks, DFCS achieved a 96.30% average attack success rate, outperforming six baseline selectors by an average of 4.60 percentage points.

**Why it matters:** It demonstrates that maximizing feature diversity and coverage allows attackers to execute highly effective dirty-label backdoor attacks at very low poisoning rates without requiring task-specific surrogate training.

**arXiv cs.CR** · 2026-08-10 · `arXiv:2608.09025v1`

SAGE-Fin is a financial authority-handoff contract that enforces runtime governance by evaluating typed, adapter-bound proposal effects against current state, requiring exact-artifact receipts, and rechecking authorization after state changes.

- Compiles proposed agent actions into typed, adapter-bound candidates and tracks unfulfilled institutional obligations as coverage debt.
- Contracts authority using real-time market, account, policy, and dialogue states, re-evaluating validity whenever state changes occur.
- Mandates an exact-artifact receipt matching the consuming adapter's nominal type, preventing evidence or workflow progress from acting as substitute authority.
- Achieved 616/616 binary reference-prototype parity across 3,080 outputs generated from a 616-case catalog and five deterministic specifications.
- Intercepted three de-identified predecessor failure modes: repeated-emission drift, stale account evidence, and missing escalation state.

**Why it matters:** It prevents financial AI agents from executing unauthorized trades, policies, or customer commitments by controlling execution effects rather than relying on textual context or workflow progress.

### [HaloMark: A Spectral Threshold for Embedding-Vector Watermarking under C2PA](https://arxiv.org/abs/2608.08645v1)

**arXiv cs.CR** · 2026-08-09 · `arXiv:2608.08645v1`

HaloMark introduces a cryptographic, C2PA-bound embedding-vector watermark that uses a manifest-stored LSH commitment to maintain verification robustness against vector transformations.

- Composes four primitives: block-diagonal orthogonal rotation, public whitening, an input-dependent LSH commitment, and a per-vector nonce.
- Bypasses brittle recomputation by storing the signed LSH commitment c in the C2PA sidecar, requiring only 24 bytes per vector.
- Identifies an empirical performance threshold at effective rank ratio eff_rank(Sigma)/d ~= 0.19, where AUROC remains >= 0.98 for high-rank encoders but fails below it.
- Achieves a 284 us verification latency when deployed as a Qdrant vector database admission filter.

**Why it matters:** It enables robust content provenance and ownership tracking for vector embeddings using existing C2PA standards without breaking under standard downstream manipulations.
