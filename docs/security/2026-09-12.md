### [Demystifying the Privacy-Utility Trade-off in LLM Interactions](https://arxiv.org/abs/2609.10992v1)

**arXiv cs.CR** · 2026-09-10 · `arXiv:2609.10992v1`

A systematic analysis of LLM privacy-utility trade-offs informs Veilmind-4B, a distilled model driving an intent-driven local extraction-sanitization-restoration pipeline to achieve low data leakage with minimal utility loss.

- Identifies three mechanisms governing LLM sanitization: Context-Dependent Utility (intent dictates if data is critical or noise), Strategic Adaptation (task needs dictate removal vs. replacement), and Combinatorial Interplay (attribute dependencies and redundancies).
- Introduces an intent-driven local protection framework utilizing an extraction-sanitization-restoration pipeline.
- Distills a lightweight, 4-billion parameter model named Veilmind-4B to drive the local protection pipeline.
- Pushes the privacy-utility trade-off toward the Pareto frontier compared to static, context-agnostic privacy baselines.

**Why it matters:** Replacing static privacy rules with intent-driven local sanitization prevents severe LLM output quality degradation while protecting sensitive user data.

### [No-Box Vulnerability Analysis: Description-only Detection of Indirect Prompt Injection Vulnerabilities in MCP Servers](https://arxiv.org/abs/2609.10854v1)

**arXiv cs.CR** · 2026-09-09 · `arXiv:2609.10854v1`

Researchers introduced no-box vulnerability analysis, a paradigm that detects security flaws using only functionality metadata without code access or runtime interaction, demonstrated via a tool called MCPSEC.

- No-box vulnerability analysis identifies flaws by analyzing functionality metadata (inputs, outputs, and side effects) to hypothesize vulnerabilities common across all consistent implementations.
- The prototype implementation, MCPSEC, audits Model Context Protocol (MCP) servers for indirect prompt injection risks using solely tool metadata gathered at server registration.
- Tested on 20 deployed MCP servers (177 tools with 95 human-verified vulnerable tools), MCPSEC identified 143 total tools as vulnerable and provided hypothesized exploitation techniques.
- MCPSEC achieved a 98.9% recall rate (predicting 94 of 95 real vulnerabilities) using metadata alone, outperforming an LLM baseline that achieved an 84.2% recall rate (80 vulnerabilities).

**Why it matters:** It enables third-party security auditing of closed-source, remotely hosted, or commercially gated systems where source code access and dynamic runtime testing are unavailable.

### [Big Enough to Break Out: Tracking the Rising Capability of LLM Penetration-Testing Agents](https://arxiv.org/abs/2609.10780v1)

**arXiv cs.CR** · 2026-09-09 · `arXiv:2609.10780v1`

An autonomous Claude Opus 4.8 penetration-testing agent solved all three benchmark targets, outperforming a legacy human-in-the-loop Kimi K2.5 agent that stalled due to planning limitations rather than memory constraints.

- An autonomous system using Claude Opus 4.8 solved 3 out of 3 public targets, whereas a legacy human-in-the-loop system using open-weight Kimi K2.5 failed to complete 2 of them.
- The legacy system completed approximately 50% of subtasks on failed targets using standard university GPUs without provider guardrails.
- Adding a coverage-memory layer to address long-horizon memory loss failed to improve task outcomes in either system.
- Analysis showed stalled runs were limited by planning and commitment, where agents possessed necessary evidence but failed to form concrete exploitation hypotheses.

**Why it matters:** Offensive LLM agent capabilities are driven primarily by planning ability rather than memory capacity, giving defenders a subtask scoring method to track rising agent proficiency before deployment in the field.

**arXiv cs.CR** · 2026-09-10 · `arXiv:2609.11637v1`

A measurement-only framework for quantum classifiers under Known-Readout Query Access provides finite-sample certified lower and upper bounds on adversarial robustness without requiring circuit details, parameters, or full state tomography.

- Evaluates robustness under Known-Readout Query Access (KRQA), where internal circuits and parameters are hidden but the quantum measurement and finite-shot outcomes are known.

### [Beyond Static Guarantees: Measuring the Static-Pass Dynamic-Fail Gap in Security-Sensitive and LLM-Generated Python Code](https://arxiv.org/abs/2609.10762v1)

**arXiv cs.CR** · 2026-09-09 · `arXiv:2609.10762v1`

Researchers identified the Static-Pass Dynamic-Fail (SPDF) phenomenon, showing that 14.53% of statically clean Python code samples contain dynamically verifiable vulnerabilities.

- Evaluated 1,355 Python samples from SecurityEval, RedCode, and CyberNative using a three-stage pipeline combining static analysis, LLM-driven CWE reasoning, and Docker-isolated exploit verification.
- Out of 654 samples that passed a composite Bandit and Semgrep static gate, LLM detection flagged 394 candidate vulnerabilities across 235 files.
- Dynamic verification confirmed or partially confirmed exploitability in 95 files, demonstrating that roughly 1 in 7 statically clean samples are vulnerable at runtime.
- Exploitability confirmation rates varied across datasets (RedCode: 33.7%, CyberNative: 28.6%, SecurityEval: 5.4%), with frequent dynamic failures in classes unflagged by static tools, such as CWE-338 and CWE-916.

**Why it matters:** Passing static analysis tools like Bandit or Semgrep cannot be treated as proof of security for AI-generated code, necessitating dynamic exploit verification in evaluation pipelines.

<small>Jessica Pourleyli, Maitreyee Das Urmi, Glaucia Melo</small>

### [Sound Debloating of Redundant Checks in Zero-Knowledge Machine-Learning Circuits](https://arxiv.org/abs/2609.10149v1)

**arXiv cs.CR** · 2026-09-09 · `arXiv:2609.10149v1`

A new automated framework uses whole-circuit abstract interpretation and provenance graphs to provably debloat redundant checks in zero-knowledge machine-learning circuits without compromising soundness.

- Redundant constraints such as range proofs, sign lookups, and bit decompositions are identified using global abstract interpretation across circuit gadgets.
- Candidate checks are recorded in a provenance graph and removed only if alternative constraint paths provably entail the same facts, preventing under-constrained forging vulnerabilities.
- Evaluation on ezkl and zkml circuits (MLP, CNN, RNN, Transformer) up to 25.3 million constraints showed constraint removals of up to 48.7%.
- The framework achieved prover execution time reductions of up to 72.8% while maintaining original security guarantees.

**Why it matters:** It significantly cuts ZK-proof generation overhead for deep neural networks while mathematically guaranteeing the debloated circuit remains secure against forged inferences.

### [Atlas: Efficient Verifiable Semantic Search](https://arxiv.org/abs/2609.11841v1)

**arXiv cs.CR** · 2026-09-10 · `arXiv:2609.11841v1`

Atlas introduces the first efficient zero-knowledge proof system for HNSW graph-based semantic search, enabling verifiable vector retrieval at scale without revealing index contents.

- Targets HNSW graph-based retrieval, overcoming data-dependent traversal constraints that previously forced verifiable search systems to rely on lower-recall cluster indices.
- Uses offline preprocessing to decouple per-query proving costs from total database size, scaling proofs strictly with the query traversal path.
- Restructures HNSW into a fixed-size-state procedure and uses timestep-tagged batching to merge per-step traversal arguments into a single proof.
- Proves queries in under 1.0 second on SIFT1M and 2.0 seconds on a 100M vector dataset while matching plaintext HNSW recall.

**Why it matters:** It allows clients using outsourced vector databases and RAG pipelines to cryptographically verify search result correctness without trusting the provider or sacrificing retrieval quality.

### [The Machines Are Calling: Measuring Automated and Synthetic Voices in Unwanted Inbound Calls](https://arxiv.org/abs/2609.11137v1)

**arXiv cs.CR** · 2026-09-10 · `arXiv:2609.11137v1`

A 66-day U.S. voice honeypot study reveals that machine-voiced openings account for at least 26.9% of unwanted calls, with synthetic speech concentrating heavily in lead-generation spam rather than fraud.

- Analyzed 7,233 answered calls using an interactive voice honeypot, finding 13.8% used repeated recordings and 13.1% used unique audio labeled as synthetic by a commercial detector.
- Evaluating the commercial synthetic-speech detector showed that identical waveforms landed on opposite sides of its detection threshold 13.6% of the time, with human listeners confirming 54.4% of its flags.
- Synthetic voice openings were most prevalent in lead-generation spam (33.8%) compared to fraud calls (21.1%), with only 0.44% disclosing automation.
- Call prevalence is driven by number seeding history rather than calendar time (59% for old numbers vs. 19% for new numbers), while campaigns reuse assets across numbers (e.g., one synthetic voice served nine campaigns).

**Why it matters:** It provides the first empirical baseline quantifying automated and synthetic speech in unwanted phone traffic following the FCC's application of TCPA regulations to AI voices.
