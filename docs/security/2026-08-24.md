### [AID-Guard: Stateful Authorization for Delegated Agent Effects](https://arxiv.org/abs/2608.21159v1)

**arXiv cs.CR** · 2026-08-21 · `arXiv:2608.21159v1`

AID-Guard introduces a stateful authorization-to-effect closure protocol that prevents duplicate or unauthorized provider actions during agent retries, races, and crash recovery.

- Revalidates approved requests and provider states at commit, maintaining a single reservation under ambiguity until a terminal result or certified no-effect delivery fence is achieved.
- Blocked 44/44 attacks under complete proposer compromise and 20/20 post-admission lifecycle attacks in a composition study.
- Completed 210 Stripe trials, 40 terminalize-successor schedules, 30 overlapping races, and 10 crash-recovery schedules across Stripe and Resend with zero duplicate effects.
- Evaluated via a Python/SQLite prototype in a loopback Model Context Protocol (MCP) domain where 13 live mutations produced no unauthorized provider effects.
- Replacing a strict exact-manifest profile (which reduced benign utility by 35.4–43.8 percentage points) with a typed frontier recovered 9–10 completions without introducing unsafe effects.

**Why it matters:** It establishes the first evaluated agent-authorization protocol that ensures idempotency and authorization integrity across the complete lifecycle of delegated tool-using AI actions.

<small>Yingzhe Tong, Leyu Dai, Songhui Guo</small>

### [TraceGrant: A Contract-Governed Security Framework for the Task-Effect Lifecycle of Networked LLM Agents](https://arxiv.org/abs/2608.21126v1)

**arXiv cs.CR** · 2026-08-21 · `arXiv:2608.21126v1`

TraceGrant is a security framework that governs networked LLM agent workflows by establishing pre-execution task-effect boundaries via a Contract, constraining runtime tool authority, and verifying post-execution task completion.

- Uses a Contract derived from trusted user requests to define the task-effect boundary before execution begins.
- Restricts runtime evidence and tool calls to instantiating only the specific authority explicitly pre-established by the Contract.
- Verifies final task completion against actual tool execution results to prevent redirected or altered persistent external effects.
- Achieved zero successful attacks on 949 AgentDojo and 400 Agent Security Bench attack cases under fixed benchmark settings with attack rates of 77.32% and 83.00%.

**Why it matters:** It unifies trusted intent, runtime evidence, and tool execution into a single lifecycle framework to neutralize indirect prompt injections in networked LLM agents.

### [ClawSentry: A Progressive Multi-Tier Security Monitor for Safeguarding Autonomous LLM Agents](https://arxiv.org/abs/2608.21101v1)

**arXiv cs.CR** · 2026-08-21 · `arXiv:2608.21101v1`

ClawSentry is an open-source, framework-agnostic security gateway that uses a progressive multi-tier decision engine and session tracking to safeguard autonomous LLM agents across four control loop loci.

- Defends four lifecycle loci: skill admission (FSPR), invocation-time intent (L1-L3 engine), execution-time effect (session anti-bypass), and post-action consequence.
- Employs a three-tier runtime engine combining a deterministic L1 layer, a rule-anchored L2 semantic reviewer, and a read-only L3 evidence-seeking agent.
- Uses an Agent Harness Protocol (AHP) abstraction to enforce uniform policies across Codex, Claude Code, Kimi CLI, and Gemini CLI without altering agent internals.
- Reduces contextual Attack Success Rate (ASR) on SkillInject with Codex/GPT-5.4 from 39.55% to 2.61% with negligible impact on Task Success Rate (83.78% to 83.05%).
- Confines ASR to 9.09-15.03% (down from 33.5-49.7%) across five Work Agents on the SkillsSafety benchmark while maintaining a 98.7% aggregate clean TSR.

**Why it matters:** It provides a cross-framework mechanism to drastically reduce malicious prompt and skill injection attacks in autonomous agents without significantly decreasing task completion performance.

<small>Kai Wang, Zeming Wei, BiaoJie Zeng, Chang Jin, An Wang, Xiaokun Luan, Zhixiao Lin, Jingjing Qu</small>

### [Trustworthy RAG: An Evaluation Agent for Detecting Misinformation and Knowledge Poisoning in Generative AI Systems](https://arxiv.org/abs/2608.21095v1)

**arXiv cs.CR** · 2026-08-21 · `arXiv:2608.21095v1`

An Evaluation Agent middleware mitigates RAG knowledge poisoning using NLI factual verification, five-signal poison detection, and a non-linearly dampened Trust Index to evaluate retrieved context prior to LLM generation.

- Uses a composite Trust Index formula T = 0.4F + 0.35C + 0.25(1 - P) featuring a non-linear dampener designed for high-contamination contexts.
- Achieved 91% accuracy, 100% precision, and 100% recall on instruction injection using Llama 3.3 70B on TruthfulQA, while subtle in-place edits like entity swaps proved harder to detect.
- Demonstrated cross-model discrimination with ROC-AUC scores between 0.73 and 0.81 across three LLMs, indicating generation style impacts performance more than model size.
- Secured an OWASP/CWE software-engineering coding assistant against instruction injection attacks containing unsafe advice with a 92% F1 score.

**Why it matters:** Filtering poisoned or contradictory contexts before LLM generation prevents RAG systems from inadvertently consuming and propagating malicious misinformation.

### [Structured but Fragile: On the Limits of LLMs in Cybersecurity Decision-Making](https://arxiv.org/abs/2608.20966v1)

**arXiv cs.CR** · 2026-08-21 · `arXiv:2608.20966v1`

Researchers evaluated LLMs on budget-constrained defense selection over real-world attack graphs, finding that LLMs can approximate structured security reasoning under explicit representations but remain highly fragile to framing, complexity, and prompt variations.

- Evaluated LLM defense selection strategies across diverse threat scenarios (ransomware, supply-chain, cloud, Kubernetes, POS malware, ICS/OT) against a game-theoretic optimization baseline.
- Providing explicit attack-graph structures enables LLMs to produce strategies near the baseline, but performance degrades as graph complexity increases.
- LLM evaluators exhibit non-monotonic risk judgment, fail to consistently rank near-optimal strategies highest, and are vulnerable to framing bias, such as rating a poor strategy dramatically higher when relabeled as 'optimal'.
- When prompted to generate code solvers for the defense optimization problem, LLMs produce the correct high-level formulation but yield implementations with poor computational scaling relative to purpose-built solvers.

**Why it matters:** Demonstrates that relying on LLMs for autonomous security decision-making is risky because their apparent reasoning capabilities are fragile and easily disrupted by prompt framing and graph scale.

<small>Pasquale Malacaria, Yunxiao Zhang</small>
