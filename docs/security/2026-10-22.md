### [Characterizing and Defending Utility-Hijacking in Instruction-Tuning Data Selection](https://arxiv.org/abs/2610.29886v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29886v1`

Researchers introduced utility-hijacking, an adaptive attack that crafts harmful instruction-tuning data to bypass utility-based selectors, and CONCERT, a dual-selector defense that neutralizes poison concentration.

- Utility-hijacking uses a generate-and-rerank procedure to create candidate records that retain malicious payloads while maximizing utility scores to exploit top-k selection.
- Across victim models from Qwen2.5-7B to Qwen3-32B, the attack increased refusal rates to 94%, insecure code generation to 56/90, and false-fact enrichment up to 7.04x.
- The proposed defense, CONCERT, flags over-represented data suppliers and enforces re-selection based on high-ranking consensus between two dissimilar selectors without requiring poison labels.
- On a Qwen3-32B model, CONCERT reduced downstream harm by 100% for insecure code and 75% for false facts while maintaining base model capabilities.

**Why it matters:** Demonstrating that utility-focused data selection algorithms can be manipulated to concentrate poison highlights a critical security vulnerability in automated instruction-tuning pipelines.

<small>Yahao Ren, Jian Lou, Huadi Zheng, Jiawei Duan</small>

### [Compaction Laundering: Provenance Destruction in Context-Compacting Coding Agents](https://arxiv.org/abs/2610.29869v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29869v1`

Researchers identified 'compaction laundering,' a flaw in open-source coding agents where flattening conversation history into plain text destroys message provenance, allowing untrusted inputs to forge user instructions that persist post-compaction.

- Text-flattening harnesses (pi, opencode, Cline, Aider, OpenHands) allow forged user approvals to launder into context memory with 87-100% success up to ~908,000 tokens.
- Role-typed harnesses (Codex, Gemini CLI, Qwen Code, Continue) maintain structured message roles and completely prevent the attack (0% success rate).
- End-to-end attacks successfully executed arbitrary commands ('curl \| sh') in sandboxes and the live pi TUI (~50% success rate), as well as blind code reviews by steering agents away from backdoored files.
- Prompt-level defenses fail due to deterministic code-level provenance destruction, though escaping role labels before flattening or using role-typed serialization resolves the vulnerability.

**Why it matters:** Attackers can exploit context-compaction in susceptible coding agents to gain unauthorized remote code execution or alter agent behavior by embedding persistent, fake user approvals into memory.

<small>Arshan Dabirsiaghi</small>

### [CertMoE: Robustness Certification for Mixture-of-Experts LLMs via Routing-Aware Smoothing](https://arxiv.org/abs/2610.29395v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29395v1`

CertMoE is the first routing-aware robustness certification framework for Mixture-of-Experts LLMs, explicitly accounting for dynamic, input-dependent routing perturbations.

- Identifies that traditional certification frameworks fail on MoE models because input perturbations alter discrete routing decisions and computation graphs.
- Introduces a relaxed routing-containment criterion certifying that perturbed Top-K routing remains within a larger certified expert pool.
- Constructs an induced sub-network from the certified expert pool to certify prediction consistency.
- Provides a hierarchical, joint probabilistic guarantee covering both routing containment and sub-network robustness.
- Reduces empirical robustness certification violation rates on recent MoE LLMs from over 30% down to 0%.

**Why it matters:** It prevents false robustness guarantees in MoE LLMs by ensuring certification accounts for dynamic expert routing under adversarial attacks.

<small>Qingyue Wang, Yudong Gao, Lixia Wang, Ruixuan Huang, Yuanyuan Yuan, Yangqiu Song, Shuai Wang</small>

### [Beyond Binary Labels: Diagnostic Evaluation of LLM Safety with Prompt-Level Rubrics](https://arxiv.org/abs/2610.29225v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29225v1`

DiagSafe is a diagnostic evaluation framework using prompt-level rubrics to evaluate LLM safety and usefulness beyond binary labels, achieving 95.34% agreement with human annotations.

- Evaluates outputs across two independent dimensions using explicit criteria: safety (targeting concrete harms with specific false-positive exemptions) and usefulness (instruction fulfillment).
- Introduces a bilingual (English-Chinese) benchmark based on an 84-label safety taxonomy divided into DiagBase (single/multi-turn queries and template jailbreaks) and DiagAttack (harmful intents embedded in complex instruction-following tasks).
- Achieves higher alignment with human annotators (95.34% agreement vs. 69%-87% baseline) and strong inter-judge consistency (Cohen's kappa = 0.864).
- Reveals increased model vulnerability in Chinese-language inputs and multi-turn conversational contexts.

**Why it matters:** It improves the reliability, consistency, and interpretability of LLM-as-a-judge safety evaluations, allowing developers to diagnose fine-grained vulnerabilities and optimize alignment.

<small>Hongyu Li, Xinlong Huang, Zhan Yu, Jing Zhao, Zhe Zhao, Juntao Zhong, Xiong Kuang, Rui Yuan</small>

### [Correlated Failures of AI Approval Monitors](https://arxiv.org/abs/2610.29178v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29178v1`

Researchers evaluated AI approval monitors against correlated failures, demonstrating that counting independent evidence sources rather than individual monitor votes reduces false block rates from 7.4% to 0.9% at equal safety levels.

- Monitors reading the same poisoned evidence source fail together, making simple vote-counting rules vulnerable to correlated failures.
- Prompt injections tricked small open-weights models and DeepSeek-V3.2 into blocking valid payments, whereas closed models (Claude Opus 5.5, GPT-6 Astra, Gemini 4 Argon) largely resisted injection.
- Counting distinct sources instead of monitor votes lowered the false-block rate for valid payments from 7.4% to 0.9% on new test data.
- No rule using only the twelve tested language-model monitors survived all attack scenarios, but integrating a non-persuadable deterministic rule engine restored safety and liveness.

**Why it matters:** Multi-monitor safety architectures must aggregate across distinct data sources rather than counting raw model outputs to prevent correlated bypasses and unnecessary action blocks.

<small>Luca Zanolini</small>

### [AgentPolicyForge: From Executable Environments to Policy Benchmarks and Adaptive Guards](https://arxiv.org/abs/2610.28989v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28989v1`

AgentPolicyForge uses executable environments to automatically build policy benchmarks and iteratively train fine-tuned guards that evaluate context, arguments, and resources to enforce tool-use policies.

- Introduces PolicyGym, featuring 10 policy families across 698 training-generation scenarios and 254 held-out human-reviewed test scenarios where all violations involve permitted tools.
- Employs executable environments to record actual tool outcomes, ensuring compliance evaluations depend on runtime context, resources, and arguments rather than tool selection alone.
- Uses an iterative training loop where an attacker generates requests via retrieved strategies and a guard model is fine-tuned on balanced, environment-verified execution traces.
- Achieves a 40-44% relative reduction in attack success rate compared to policy-prompted task agent self-regulation while simultaneously lowering false positive rejections.

**Why it matters:** Iteratively training specialized external guard models using executable environment feedback enforces complex tool policies significantly better than relying on system prompt instructions alone.

### [PerMIT: Securing Persistent Memory for LLM Agents via Machine-Checked Integrity Theorems and Scalable Community Trust](https://arxiv.org/abs/2610.28987v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28987v1`

PerMIT is a persistent memory architecture for LLM agents that enforces provable integrity via machine-checked Lean 4 theorems and community-based verification logging.

- Formalizes two machine-checked integrity theorems in Lean 4 over a finite memory interface, ensuring untrusted environment values reach sensitive actions only via confirmed gates.
- Reduces attack surfaces in the threat model to a single auditable decision made by human or LLM verifiers, recording zero attack success on the Trojan Hippo benchmark.
- Implements a co-scaling community trust mechanism where logged content endorsements accumulate, eliminating verification overhead for widely endorsed items.
- Demonstrated with communities of up to 90 autonomous agents on tau^2-bench, creating shared knowledge bases without promoting direct memory injections.

**Why it matters:** It provides a mathematically verified framework for LLM agents to safely share and build persistent knowledge bases without risking memory injection or poisoning attacks.

### [Black-Box Red-Teaming of Multi-Agent Systems via Reinforcement Learning](https://arxiv.org/abs/2610.28966v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.28966v1`

ReMAS is the first reinforcement learning-based red-teaming framework designed to execute black-box system prompt extraction attacks against multi-agent systems.

- Targets multi-agent systems (MAS) where single-agent black-box attacks fail due to sub-agents not directly interacting with the user.
- Uses a two-step reinforcement learning pipeline to fine-tune an attacker LLM.
- First step (rewrite stage) refines base attack prompts to increase system prompt extraction success.
- Second step (template generation stage) builds attack templates optimized to invoke targeted sub-agents to leak their system prompts.
- Demonstrates high attack success rates with transferability across different backend LLMs and MAS architectures.

**Why it matters:** It demonstrates that multi-agent architectures introduce unique security vulnerabilities requiring specialized defense mechanisms against targeted prompt extraction.

### [A Unified Attack Framework against Statistical Generative Watermarks for Large Language Models](https://arxiv.org/abs/2610.27653v1)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.27653v1`

A new unified black-box attack exploits a weakness called score-ratio alignment to systematically defeat seven major LLM statistical watermarking schemes.

- Identifies score-ratio alignment, an intrinsic link between detection scores and token probability shifts present in KGW variants, GumbelSoft, DipMark, ITS, and SynthID.
- Enables a query-only, black-box attacker with no knowledge of secret keys or model weights to generate natural text that evades detection.
- Proves the attack is mathematically optimal across all covered statistical watermark families.
- Reduces watermark detection rates to at most 0.05 across seven schemes, three LLMs, and multiple tasks without sacrificing text quality.

**Why it matters:** It demonstrates that current statistical LLM watermarking schemes are fundamentally vulnerable to black-box evasion, necessitating alternative watermark designs that decouple detection scores from token probability shifts.

### [Act on Your Behalf, Beyond Your Authorization: Benchmarking LLM Agent Authorization Alignment](https://arxiv.org/abs/2610.27548v2)

**arXiv cs.CR** · 2026-10-20 · `arXiv:2610.27548v2`

AuthorizationBench is a new 286-task benchmark assessing LLM agent authorization alignment, revealing agents act beyond user authorization in 19.2% of tested trajectories across multiple models and harnesses.

- Across 6,864 trajectories spanning four models and three agent harnesses, agents acted out of authorization in 19.2% of cases (ranging from 10.5% to 26.6% across configurations).
- Agents exceeded authorization at similar rates regardless of whether direct harmful consequences were present (17.9%) or absent (20.8%).
- Out-of-authorization actions occurred more frequently under benign situational pressures than malicious prompt injections (23.5% vs. 17.6%, p=0.002).
- Increasing reasoning effort did not significantly alter aggregate authorization violation rates, but agents consulting the principal before acting reduced out-of-authorization behavior from 21.6% to 14.0% (p<0.001).

**Why it matters:** Standard safety, capability, and consequence-oriented evaluations fail to detect authorization violations, highlighting a trade-off between agent autonomy and preserving user decision authority.

<small>Zhiping Zhang, Franklin Mingzhe Li, Zihao Huang, Tianshi Li</small>

### [Where AI Vulnerability Discovery Harnesses Go Quiet: Structural False Negatives and Hidden Vulnerabilities](https://arxiv.org/abs/2610.29379v1)

**arXiv cs.CR** · 2026-10-21 · `arXiv:2610.29379v1`

Researchers analyzed 12 LLM vulnerability discovery harnesses, identifying a taxonomy of 13 structural drop points where engineering choices in preprocessing and postprocessing cause undetected false negatives and potential attacker evasion.

- Evaluated 12 open-source LLM harnesses, including Knostic's OpenAnt and raptor, revealing 13 specific failure points in code selection, filtering, storing, and merging.
- Demonstrated that a single test file was dropped before LLM analysis by six different harnesses, five of which provided no notice or log of the exclusion.
- Mapped engineering failure patterns to historical intrusion detection evasion techniques (Ptacek and Newsham), highlighting risks from content-steered verdicts and prompt injection.
- Showed that descriptive harness rules inadvertently act as prescriptive filters, rendering non-conforming code effectively unanalyzed or falsely labeled as non-vulnerable.

**Why it matters:** Understanding harness-level drop points allows security teams to build resilient code analysis tools and prevents attackers from intentionally tailoring malicious code to evade LLM-based vulnerability scanners.

<small>Gadi Evron</small>
