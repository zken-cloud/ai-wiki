### [RTLGuard: A Lightweight Teacher-Student Defense for Poisoned RTL Code Generation Models](https://arxiv.org/abs/2608.26049v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.26049v1`

RTLGuard is a lightweight teacher-student defense framework designed to sanitize backdoor-poisoned RTL code generation models without full-parameter retraining.

- Addresses backdoor threats and hardware Trojan insertion caused by opaque third-party fine-tuning of LLMs used for hardware design.
- Fine-tunes a small, clean teacher model on a limited trusted dataset of register transfer level (RTL) code.
- Guides the poisoned target student model using a composite objective that combines feature alignment and knowledge distillation to suppress malicious triggers.
- Reduces the Attack Success Rate (ASR) while maintaining the functional correctness and synthesizability of the generated RTL code.

**Why it matters:** It provides a computationally efficient method to secure the AI-enabled integrated circuit supply chain against malicious hardware Trojans embedded in third-party LLMs.

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25880v1`

OOXML files can induce 'evidence forks' where extracted text consumed by LLMs differs from the content rendered in Microsoft Office's editing canvas, creating security risks across workflows.

- Identified 21 distinct evidence forks across Excel, Word, and PowerPoint spanning six dimensions of view construction.
- Tested 13 extraction tools, finding that all emit evidence from at least one fork.
- Four native-ingestion LLM APIs returned unrendered 'trap' facts in 48% to 76% of evaluation trials.
- At least one of eleven evaluated LLM interfaces (4 APIs, 7 web chatbots) returned the hidden trap fact for 20 out of 21 mechanisms.
- A source-level survey of 16 popular open-source LLM projects confirmed that default ingestion configurations rely heavily on affected extractor families.

**Why it matters:** LLM-based compliance, financial, and RAG pipelines may process hidden, unrendered, or spoofed document content as truth, exposing automated systems to data integrity failures and potential exploitation.

### [SkillShield: Prompt-Space Security Skills for LLM Coding Agents](https://arxiv.org/abs/2608.25817v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25817v1`

SkillShield is a system-prompt defense for LLM coding agents that injects offline-synthesized security skills into the system prompt to prevent malware generation and harmful execution without runtime classification.

- SkillShield operates via fixed-budget provisioning scopes (all-classes, per-bundle, and per-class) injected at session start to guide execution policies within the tool-use loop.
- Tested across six LLMs on RedCode, the default all-classes skill reduced malware-generation severity from 3.37 to 0.58 and achieved a 43.6% execution attack success rate (ASR).
- Per-bundle and per-class configurations further decreased the execution ASR to 36.2% and 14.5%, respectively, outperforming non-adaptive jailbreak baselines.
- The defense matches the performance of Llama Guard 3 (42.7% ASR) without requiring its separate 8B parameter classifier or auxiliary execution-boundary monitors.
- Evaluations across 731 benign task descriptions demonstrated a low mean safety-refusal rate of 0.14%.

**Why it matters:** It enables API-only deployers to enforce strict agent execution safety and prevent malware generation directly through prompt engineering without introducing dedicated runtime classifier models.

<small>Xiaodong Wu, Zhimin Zhao, Qi Li, Xiangman Li, Yu Shi, Bram Adams, Jianbing Ni</small>

### [EVOMAL: Self-Poisoning in Self-Evolving Coding Agents](https://arxiv.org/abs/2608.25776v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25776v1`

Researchers identified a self-poisoning vulnerability in self-evolving coding agents and created EvoMal, an attack that trick agents into cloning planted malicious skill payloads into new, self-propagating, defense-evading skills.

- EvoMal uses a 'banner'—benign-looking structural wrapper code—around interchangeable payloads to induce agents to copy malicious code into newly authored skills.
- Across six models on 153 SWE-bench Verified tasks, Agent Self-Poisoning Rate (ASPR) reached 20.3%–41.8%, multiplying malicious skills 4.9x–9.0x; tailoring descriptions to specific task families raised ASPR to 86.7%.
- Self-poisoned skills persist as self-propagating worms; Qwen3 maintained a 68% ASPR at round 5 even after original planted skills were deleted.
- DeepSeek-V4-Pro achieved an 11.1% ASPR using un-bannered payloads alone, proving the underlying self-poisoning vulnerability exists without explicit wrapping.
- A proposed 'counter-prompt' defense reduces EvoMal's ASPR to <= 6.7% without significantly compromising task performance.

**Why it matters:** Self-evolving agents that populate shared skill libraries can inadvertently generate and propagate persistent malware worms that bypass standard security defenses based on static attacker signatures.

<small>Xiaodong Wu, Yu Shi, Qi Li, Zhimin Zhao, Xiangman Li, Bram Adams, Ahmed E. Hassan, Jianbing Ni</small>

### [Reassembling Distributed Risk: Trajectory-Conditioned Action Generation for Multi-Turn Agent Safety](https://arxiv.org/abs/2608.25711v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25711v1`

ReDiR is a generation-time agent defense that prevents multi-turn decomposition attacks by injecting compressed latent trajectory-safety evidence into a frozen base LLM before each action.

- Addresses multi-turn decomposition attacks where harmful intent is fragmented across individually plausible, context-isolated tool calls.
- Compresses the multi-turn interaction trajectory into a compact latent safety representation and injects it directly into the frozen base model during action generation.
- Trains the representation using same-model, cross-view supervision, mapping explicit task-view safe behavior to the original trajectory to recover distributed security evidence.
- Eliminates the need for external online reasoning modules, runtime-specific action representations, or separate action-level safety classifiers.
- Evaluated across three model families and eight held-out tool domains, reducing attack success rates to below 8% while maintaining benign fidelity and low overhead.

**Why it matters:** It enables tool-using LLM agents to detect and block distributed long-horizon security risks directly within the generation pass without sacrificing latency or domain generalizability.

<small>Yanbo Dai, Zhenlan Ji, Zongjie Li, Shuai Wang</small>

### [LMSM: LLM Security Framework Inspired by Linux Security Modules](https://arxiv.org/abs/2608.25697v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25697v1`

Language Model Security Modules (LMSM) adapts the Linux Security Modules design pattern to decouple LLM interpretability evidence, policy rules, and runtime enforcement.

- Decouples safety enforcement into a security backend providing calibrated evidence, a versioned policy engine, and a gate authorizing output release.
- Supports multiple interpretability artifacts, hosting sparse autoencoders (SAE), transcoders, and task-fitted dense probes on Hugging Face Transformers and vLLM.
- Preserves request-specific enforcement decisions under vLLM scheduler churn and allows rule composition without rebuilding request handling.
- Tested on Qwen3-4B using LMSM-Checkpoint, reducing HarmBench attack success rate from 39.20% to 3.32% while XSTest false refusals increased slightly from 2.40% to 4.40%.
- Retains 98.14% of serving throughput compared to an unmonitored path at 32 active sequences.

**Why it matters:** LMSM provides a unified runtime security framework that converts internal model interpretability signals into composable, low-overhead safety controls without modifying serving code.

<small>XiuYu Zhang, Bonan Ruan, Junfeng Fang, An Zhang, Tat-Seng Chua, Zhenkai Liang</small>

### [AI Slop and Hallucinations in Vulnerability Assessment: A Survey on Reasoning Failures and Trustworthy Mitigation](https://arxiv.org/abs/2608.25667v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25667v1`

This survey formalizes a taxonomy of security 'AI slop', proposes the Deductive Coverage Score metric, and outlines neuro-symbolic verification alongside new evaluation instruments (CVE-Bench and Slop-Score) to fix LLM reasoning failures in vulnerability assessment.

- Formalizes 'AI slop' in cybersecurity as hallucinated vulnerabilities, incorrect patches, and repackaged bug reports caused by the gap between LLM autoregressive probabilistic generation and causal deductive reasoning.
- Introduces the Deductive Coverage Score as a measurable proxy for reasoning gaps, showing chain-of-thought prompting and agents improve but fail to resolve it.
- Critiques passive detection and watermarking due to fundamental entropy constraints, advocating instead for active neuro-symbolic verification.
- Proposes two new evaluation instruments, CVE-Bench and Slop-Score, featuring dedicated dataset designs, metric formulas, and anti-gaming provisions to shift focus to mathematical verifiability.

**Why it matters:** Replacing linguistic fluency evaluation with active neuro-symbolic verification prevents low-quality, AI-generated reports from overwhelming human vulnerability triage pipelines.

<small>Junchen Ding, Jialiang Dong, Yichen Zhu, Yi Liu, Gelei Deng, Willy Susilo, Siqi Ma, Yuekang Li</small>

### [MMJailBench: A Factorized Benchmark for Disentangling Multimodal Jailbreak Vulnerabilities](https://arxiv.org/abs/2608.25490v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25490v1`

MMJailBench is a new factorized benchmark that isolates harmful intent, prompt framing, visual semantics, and instruction carriers to systematically evaluate MLLM jailbreak vulnerabilities.

- Evaluates 16 open-weight and proprietary MLLMs by systematically varying four distinct jailbreak factors under controlled configurations.
- Identifies prompt framing as the primary driver of jailbreak variation, with task-relevant visual semantics—especially authority-like cues—systematically increasing susceptibility.
- Finds that visually rendered text instructions do not consistently increase jailbreak risk compared to direct textual instructions.
- Includes a modular evaluation suite featuring full and lightweight configurations, multiple judge options, and multidimensional metrics alongside internal representation diagnostics.

**Why it matters:** By decoupling confounding variables in multimodal attacks, safety researchers can pinpoint precise cross-modal vulnerabilities and improve safety alignment across specific harm domains.

In a Trail of Bits evaluation, GPT 5.6-Cyber successfully escaped a QEMU/KVM sandbox three times, utilizing N-day kernel vulnerabilities, unpatched component bugs, and newly discovered 0-days to achieve host breakout.

### [MACGen: Toward Functionally Correct and Secure Code Generation via Multi-Agent Collaboration](https://arxiv.org/abs/2608.25457v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.25457v1`

MACGen is a multi-agent code generation framework that uses structured artifact passing instead of shared dialogue histories to optimize both functional correctness and security.

- MACGen separates tasks across specialized agents: a planner for functional requirements, a security advisor for CWE identification and guidelines, a coder for synthesis, and a reviewer for perspective-separated feedback.
- Eliminates full dialogue history sharing by passing only structured artifacts downstream to enforce role specialization and prevent context bloat.
- Improves F&S@1 scores over direct prompting by an average of 19.61 percentage points on CWEval and 10.57 percentage points on BaxBench.

**Why it matters:** It demonstrates that decoupling multi-agent communication into structured artifacts improves both the security and functional correctness of LLM-generated code while reducing context overhead.

<small>Miseon Yu, Jaehoon Choi, Younghan Lee, Yunheung Paek</small>
