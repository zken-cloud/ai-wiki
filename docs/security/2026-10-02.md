### [KaliBench: A Fine-Grained Benchmark for Cybersecurity Tool Use on Kali Linux with Runtime-Free Verifiable Rewards](https://arxiv.org/abs/2610.02206v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.02206v1`

KaliBench is a new benchmark featuring 8,504 query-command pairs across 1,642 Kali Linux tools designed to evaluate and improve LLMs on precise natural-language-to-CLI translation with runtime-free verifiable rewards.

- Dataset spans 1,642 tools, 23 capability dimensions, and 5 security phases, built via a manuscript-grounded pipeline with deterministic canonicalization.
- Employs a multi-stage verification pipeline combining LLM validation, sandboxed terminal execution, and human refinement to ensure semantic and syntax accuracy.
- Open-weight models fail to exceed 42% exact-command accuracy in unrestricted settings, demonstrating severe limitations in CLI tool selection and argument framing.
- Supervised fine-tuning and reinforcement learning using KaliBench's verifiable rewards boosted an 8B model to match the performance of a 685B MoE model.

**Why it matters:** It enables reproducible training and evaluation of AI agents for precise cybersecurity operations without requiring expensive, real-time sandbox execution environments during reinforcement learning.

<small>Pengfei Li, Naufal Suryanto, Sicheng Zhang, Muzammal Naseer</small>

### [Walking the Embedding Space: Datastore Extraction from Multimodal RAG](https://arxiv.org/abs/2610.01871v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01871v1`

Researchers introduced ImMRAG, an adaptive black-box data extraction attack against image-returning MRAG systems that embeds malicious instructions inside input images to reconstruct hidden datastore contents.

- Operates in a black-box setting against image-returning MRAG systems where retrieved visual artifacts serve as responses.
- Blends an attacker-held shadow image with previously recovered images and uses relevance-weighted resampling to traverse unexplored embedding space.
- Reconstructs up to 611 radiology images, 566 document scans, and 416 general-purpose images in a single 2,500-query run.
- Achieves up to 5.6 times as many distinct recovered datastore items compared to a non-adaptive baseline across multiple CLIP-family retrievers.

**Why it matters:** The attack demonstrates that multimodal RAG systems are vulnerable to automated datastore reconstruction, highlighting the need for specialized safeguards for multimodal data.

### [A Safe Prototype Is Not a Safety Direction: Reference Dependence and Prompt Confounds in Response-Safety Embeddings](https://arxiv.org/abs/2610.01801v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01801v1`

Auditing response-safety scoring shows that cosine similarity to a safe-only mean embedding performs near or below chance, whereas a safe-minus-unsafe reference vector significantly improves classification accuracy across multiple encoders.

- Raw positive-centroid (safe prototype) models achieved poor ROC-AUC scores (0.457-0.545 on human-labeled corpora; 0.358-0.405 on jury control), with some instances performing significantly below chance.
- An explicit safe-minus-unsafe reference direction improved ROC-AUC to 0.588-0.738 on human-labeled data and 0.754-0.793 on the jury control using identical embeddings.
- At a 5% false-safe threshold, the safe-minus-unsafe reference accepted significantly more safe responses on PKU-SafeRLHF (0.153-0.263 vs 0.039-0.061) and Aegis (0.189-0.291 vs 0.004-0.045).
- Prompt-only ablations revealed that prompt-label composition can artificially inflate uncontrolled safety evaluations.
- Recovering the referenced ranking requires sufficient unsafe mass, achievable via 80-634 labeled unsafe responses, whereas performance degrades when the unsafe pool drops to 5%.

**Why it matters:** Evaluating response safety using embedding space requires an explicit negative reference to define a safety vector, as a safe class centroid alone provides location without orientation.

<small>Sahil Kadadekar</small>

### [The Innocent Courier: Covert Exfiltration Through Legitimate LLM Web Fetching](https://arxiv.org/abs/2610.01768v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01768v1`

LLMLeak establishes a covert exfiltration channel from air-gapped or network-restricted malware to attacker-controlled web/DNS servers by tricking LLMs into executing web-fetching tools with secret-encoded URLs.

- Malicious local software embeds sensitive data directly into a URL, framing the link as necessary for a benign user task like software migration.
- The attack bypasses local network restrictions and direct code generation monitoring by abusing the LLM's legitimate native web-fetching tool.
- Data is exfiltrated to an attacker-controlled DNS or web server when the LLM fetches the constructed URL.
- Evaluations across eleven open-parameter models demonstrated an attack success rate of 79.7%, with verified impact on real-world chatbots.

**Why it matters:** It demonstrates that local LLMs with web-browsing privileges can inadvertently act as data exfiltration proxies for isolated malware, bypassing traditional network boundary controls.

<small>Alessandro Pegoraro, Daryan Merx, Phillip Rieger, Ahmad-Reza Sadeghi</small>

### [Chaining Skills to Hijack LLM Agents](https://arxiv.org/abs/2610.01564v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01564v1`

APEX constructs adversarial skill chains that exploit agent-generated task records to pass false claims of user approval across skills, successfully hijacking downstream actions in LLM agents.

- APEX uses an upstream skill to trick the agent into writing a genuine progress record containing a false claim of user approval, which a downstream skill uses to execute an attacker-selected action.
- Across six models and four targeted-action families on SkillsBench, APEX skill chains induced the selected action in 74.2% of attempts (512/690).
- On GPT-5.4, the multi-skill chain achieved an 84.3% attack success rate, outperforming a single merged skill baseline which achieved 17.4%.
- A prompting defense requiring agents to verify skill-produced files reduced GPT-5.4 attack success from 84.3% to 59.1%, but degraded benign task pass rates on 72 native skills from 86.7% to 56.3%.

**Why it matters:** Sequencing open-source skills introduces indirect prompt injection vulnerabilities that current verification prompting cannot mitigate without severely harming benign agent performance.

<small>Tian Dong, Zixuan Ma, Haodong Zhao, Huaien Zhang, Shaofeng Li, Hao Chen</small>

### [False Floors: LLM Safety Routing Evaluations Break Under Distribution Shift](https://arxiv.org/abs/2610.01535v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01535v1`

Evaluating LLM safety routers against a single-model baseline selected using test-set labels introduces severe optimistic bias under distribution shift, masking that routing provides minimal real safety gains on standard benchmarks.

- Selection bias accounts for 0.045-0.113 of harm on HELM Safety under held-out categories and increases seven- to ninefold on AgentDojo when test suites are held out.
- When evaluated honestly under shift without using test labels for baseline selection, nested routers default to serving the honest baseline's model in most pool cells.
- On the AgentDojo corpus, a theoretical perfect pre-dispatch router yields a maximum reduction of only two points of harm.
- Attacking GPT-5.4 with knowledge of the targeted model reduces its judged recognition of late prompt injections by 19.6 points on held-out reruns.

**Why it matters:** Safety routers and recognition-based defenses must be evaluated under distribution shift against fair baselines to prevent false safety assurances in real-world deployments.

<small>Amit Singh Bhatti, Vishal Vaddina</small>

### [OverAct: Measuring and Mitigating Proactive Over-Authorization in LLM Tool-Calling Agents](https://arxiv.org/abs/2610.01508v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01508v1`

OverAct is a new benchmark measuring proactive over-authorization in tool-calling LLM agents, revealing that models systematically access excess private data, which can be reduced by 43% using a zero-shot filtering method called SelfAudit.

- Evaluated seven models across four families using OverAct, a judge-free benchmark spanning eight privacy-sensitive domains.
- Identified request specificity as the primary driver of over-authorization, while tool-pool size scales sublinearly and temperature has minimal impact.
- Over-authorization is driven by structural cost-asymmetry decision tendencies rather than decoding randomness.
- Introduced SelfAudit, a zero-shot inference-time technique that generates request-grounded justifications and filters unauthorized calls, cutting privacy-oriented excess by 43%.

**Why it matters:** LLM agents frequently over-query private APIs beyond explicit user requests, necessitating runtime intervention like SelfAudit to prevent unnecessary exposure of user data.

### [High-quality Data Do not Mean Safe! Poisoning LLMs after Data Selection](https://arxiv.org/abs/2610.01367v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01367v1`

Researchers show quality-based data filtering fails to prevent LLM safety degradation and introduce Bi-QSTO, an optimization method that generates high-quality poisoned samples capable of surviving aggressive selection filters while destroying safety alignment.

- Quality-based selection filters out overtly harmful samples, but retained high-quality samples can still degrade safety alignment due to harmful-like layer-wise gradient updates.
- Bi-Stage Quality-Constrained Safety-Degradation Text Optimization (Bi-QSTO) optimizes poisoned text under explicit quality constraints to pass selection while retaining safety-degrading effects.
- At a 90% data filtering rate, Bi-QSTO achieves over 90% Poisoning Retention Rate and a Harmful Score of 3.30 to 4.01.

**Why it matters:** Standard data-quality filtering pipelines cannot be relied upon as a security boundary to prevent safety alignment degradation during LLM fine-tuning.

### [Sleeping Secrets: How Fine-Tuning Reawakens Privacy Risks in Language Models](https://arxiv.org/abs/2610.01365v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01365v1`

ReGap is a data-free attack that recovers private associations from LLMs using model-generated candidates and low-rank adaptation without requiring genuine private supervision or exact target answers.

- ReGap constructs candidates via task structure, filters them by answer-token likelihood, and updates target models using low-rank adaptation (LoRA).
- Tested across six GPT-2, OPT, and Qwen3 models, ReGap increases target-association recovery by 6 to 21 percentage points over post-training baselines.
- Recovery succeeds even when adaptation identities are completely disjoint from memorized and evaluation identities, without target answers appearing in the supervision data.
- Applying trained adapters to a target-exposed checkpoint increases recovery from 42% to 63%, while producing zero gain on a matched unexposed checkpoint.

**Why it matters:** Routine fine-tuning and model customization can accidentally unearth latent private data previously memorized by an LLM, even without using real private training data.

PACE is a provenance-aware capability enforcement defense that mediates LLM agent tool calls immediately before execution using path confinement and schema-defined effect verification.

### [Safety Must Survive Self-Improvement: Why Failures Persist and How Agents Recover](https://arxiv.org/abs/2610.01073v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01073v1`

A study on recursive self-improvement shows safety failures persist across agent generations due to outdated evaluation scores and failed incumbents, but can be resolved using full validation, validated rollback, and editing initial implementations.

- Outdated historical scores preserved unsafe programs in 22 of 48 framework histories after new authorization dependencies invalidated previous optimizations.
- Failures persisted under unchanged contracts when proposed edits were rejected, leaving the failed incumbent agent active.
- Editing the initial implementation rather than the failed one improved recovery outcomes from shared failures.
- Applying full validation combined with validated rollback yielded 100% correct programs while retaining over 43% deployment savings.

**Why it matters:** Maintaining agent safety during self-improvement requires dynamic re-validation of running programs under current conditions and deliberate selection of which base code to edit next.

### [MOMAT: Mixture of Multiple Atlases for Low-Power Jailbreak Defense of Quantized LLMs](https://arxiv.org/abs/2610.01058v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.01058v1`

MOMAT is a hardware-enhanced defense framework combining Compute-in-Memory acceleration with atlas-local RAG and a lightweight MoE detector to protect quantized LLMs from jailbreak attacks at low power.

- Divides safety databases into semantic clusters called atlases, using localized Retrieval-Augmented Generation (RAG) to prevent semantic sparsity and the curse of dimensionality.
- Utilizes a lightweight Mixture of Experts (MoE) detector to evaluate top-k similarity features retrieved from all atlases for incoming prompts.
- Employs a Compute-in-Memory (CiM) similarity engine to execute fast, low-power atlas-local feature retrievals.
- Accelerates a 100-query batch from 15,052.44 ms to 3,207.21 ns (4.69e6x speedup) and reduces energy consumption from 8.1e7 uJ to 3.32 uJ (2.5e5x reduction) compared to DRAM baselines.
- Maintains defense performance against red-team benchmarks while avoiding benign overkill, supported by a 223.2k-sample dataset.

**Why it matters:** It enables robust, real-time jailbreak defenses on resource-constrained edge devices without sacrificing energy efficiency or model accuracy.

<small>Boyang Li, Bingyu Shen, Weihao Hong, Zhiyuan Jiang, Xinlei Guan, Yan Ma, Miles Q. Li, Yi Sheng</small>

### [DeBERTa-ConPara: Attack-Aware and Deployment-Realistic Detection of AI-Generated Text](https://arxiv.org/abs/2610.00883v1)

**arXiv cs.CR** · 2026-10-01 · `arXiv:2610.00883v1`

DeBERTa-ConPara demonstrates that applying Unicode normalization during inference while retaining raw text during training maximizes AI-generated text detection performance against adversarial attacks without losing supervision.

- Raw training paired with normalized inference achieved 99.61% AUROC, 99.01% TPR@5% FPR, and 96.57% TPR@1% FPR on the official RAID hidden test set.
- Applying Unicode normalization to training data collapsed 35.4% of RAID dataset rows into duplicate clean siblings, destroying critical adversarial training supervision.
- Inference-side normalization specifically restores detection performance against homoglyph and zero-width-space attacks, raising their TPR from 11.05% and 1.12% to 96.98%.
- Neither paraphrasing-based contrastive learning (ConPara) nor handcrafted feature-fusion branches improved cross-domain or attack-aware detector performance.
- The performance gains of inference-only normalization were replicated in a different zero-shot detector architecture, confirming it is an attack-level phenomenon.

**Why it matters:** This work reveals that proper placement of input normalization allows text detectors to neutralize surface-level adversarial attacks without eroding critical training signal or requiring model architectural changes.

<small>Mohamed Mady, Yupei Li, Johannes Reschke, Björn W. Schuller</small>

`ai-generated-text-detection` `adversarial-robustness` `unicode-normalization` `deberta` `nlp-security`
