### [Backdooring Open-Weight AI Models](https://www.schneier.com/blog/archives/2026/10/backdooring-open-weight-ai-models.html)

**Schneier on Security** · 2026-10-16

Researchers demonstrated that modified open-weight AI models, including popular abliterated builds, can easily hide persistent backdoors that exfiltrate data when activated by hidden triggers.

- Open-weight modifications like abliteration, which subtracts refusal directions from model weights, create unverified supply-chain risks on platforms like Hugging Face.
- A proof-of-concept backdoor was built using an open base model, public dataset, and rented GPU, scaling from a 1.5B parameter model to a 7B parameter model.
- The backdoored model embeds a URL pointing to a remote payload, allowing attackers to modify malicious post-deployment behavior without retraining.
- When integrated into OpenAI's Codex CLI, the 7B model passed standard evaluations and executed normal tasks, but exfiltrated project credentials upon encountering a specific trigger phrase.

**Why it matters:** Using untrusted open-weight model builds exposes AI pipelines and autonomous agents to silent supply-chain attacks that evade standard evaluations.

### [My Credentials, Please: Detecting Filesystem Capability Laundering in MCP Servers at Scale](https://arxiv.org/abs/2610.22301v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.22301v1`

Researchers introduced MCP-FSD to detect filesystem capability laundering in Model Context Protocol servers, discovering vulnerabilities across 787 servers and securing 13 advisories including two CVEs in Anthropic's Git MCP Server.

- Filesystem capability laundering occurs when AI tool calls execute with broad host permissions beyond their declared contracts and deployment scopes.
- The vulnerability gap was analyzed across server-category screening (L1), per-tool contract analysis (L2), and bypassable path-validation checks (L3).
- MCP-FSD evaluated 21,097 servers across nine registries, identifying 787 of 4,806 triaged servers (16.4%) with undeclared filesystem capabilities.
- Dynamic execution confirmed 150 vulnerable instances under tested sandbox policies, resulting in 13 security advisories.

**Why it matters:** Client-side tool approvals in MCP deployments can silently grant AI agents unchecked host filesystem access, bypassing intended tool boundaries and sandbox containment.

<small>Zeqian Huang, Mingyue Tang, Aonan Guan, Qiming Sun, Pengzhou He</small>

### [Language Is a Security Surface for Agent Guards](https://arxiv.org/abs/2610.22244v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.22244v1`

Researchers created LinguaGuardBench to show that step-level agent guards frequently change safety verdicts when user requests are translated out of English, despite identical tool trajectories.

- Evaluated 19 guards using LinguaGuardBench (built from 1,220 TS-Bench AgentDojo-Traj steps) translated into French, German, Turkish, Swahili, and Amharic while holding tool actions and observations constant.
- For guards under 13B parameters, mean placebo-adjusted verdict flip rates rose with language rarity, from +1.5 percentage points (pp) on French to +4.4 pp on Amharic, with purpose-built guards proving most sensitive.
- Guard size dictates failure modes: 12-30B open models suffer up to +5.0 pp higher false positives, while guards under 10B exhibit recall drops up to -7.4 pp.
- Frontier models shift minimally (at most ~1 pp), with Gemini 3.8 Flash returning identical verdicts regardless of request language.
- Post-hoc analysis indicates verdict shifts concentrate on steps where the agent's reasoning restates the original English request, suggesting guards react to cross-channel inconsistency.

**Why it matters:** Using multilingual inputs against English-centric agent safety guards creates a security vulnerability, exposing smaller or purpose-built guards to elevated false positive rates and severe recall drops.

<small>Hasan Demirkiran, Jens Ernstberger</small>

### [Shortcut Sensitivity in Agent-Safety Evaluations](https://arxiv.org/abs/2610.22243v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.22243v1`

A three-level shortcut-auditing framework reveals that benchmark representations and spurious cues bias safety guard decisions and artificially inflate evaluation metrics.

- Identifies shortcut risks across three levels: label predictability, observational guard association, and paired decision sensitivity.
- Demonstrates severe metric degradation under domain holdouts (AgentDojo-Traj exact-tool F1 drops from 0.901 to 0.495) and equal interaction weighting (TS-Guard F1 drops from 0.902 to 0.719).
- Establishes causal decision sensitivity in Haiku: rewriting a safe-row marker lowers false-positive blocking by 8.33 percentage points, whereas opaque tool aliases increase blocking by 11.46 points.
- Observes that Haiku-sized intervention effects do not reproduce in Luna or deterministic Q8 TS-Guard.
- Recommends evaluating safety guards using domain group holdouts, evaluation-unit metrics, and placebo-controlled paired interventions.

**Why it matters:** Spurious benchmark shortcuts cause safety evaluation metrics to misrepresent actual guard efficacy, leading to unpredicted guard behavior when deployed in real-world environments.

<small>Hasan Demirkiran, Jens Ernstberger</small>

### [BiShield-TEE: On the (In-)Security of Unilateral Weight Obfuscation in On-Device TEE-Shielded LLM Partition](https://arxiv.org/abs/2610.21565v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21565v1`

Researchers identified the Solution Determinacy Property vulnerability in unilateral TEE weight obfuscation schemes and developed BiShield-TEE, a bilateral framework that restores security to the black-box baseline with higher inference efficiency.

- Unilateral matrix transformations in TEE-based parameter obfuscation methods like GroupCover and ArrowCloak exhibit a Solution Determinacy Property (SDP) that allows attackers to uniquely determine the secret key.
- Exploiting SDP allows attackers to recover model functionality, achieving attack accuracy over 2.4x higher than the full-shielding black-box baseline.
- BiShield-TEE addresses the flaw by jointly obfuscating both input and output dimensions, creating Ambiguous Solutions that hide the true key among multiple valid candidates.
- Hardware evaluation demonstrates that BiShield-TEE limits attack accuracy to the full-shielding black-box baseline while outperforming prior unilateral methods in inference efficiency.

**Why it matters:** It demonstrates that current unilateral parameter obfuscation techniques in on-device TEE deployments are insecure and provides a provably stronger, more efficient bilateral obfuscation mechanism.

<small>Zhiyuan Wang, Yuezhi Zhou, Ziqi Zhang, Zhu Zhang, Zhixing Tan, Yongheng Deng</small>

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21464v1`

- Introduces a Hub-Satellite structure where Satellite documents act as entry points across semantic regions and Hub documents enhance local cohesion to trigger cascading retrieval.

**Why it matters:** It demonstrates that large-scale RAG systems using HNSW indexes are inherently vulnerable to graph-topology-exploiting attacks that bypass current security defenses.

### [What Survives Self-Evolution: Provenance Marks in Copied Agent Harnesses](https://arxiv.org/abs/2610.21458v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21458v1`

Researchers evaluated provenance mark survival under covert rewriting attacks from self-evolution tools and introduced a game-action keying scheme robust against naive harness rewriting.

- Published provenance marks fail under covert rewriting attacks: prompt-based KGW survived 0 of 12 GEPA evolvings, and AgentMark survived 5 of 12.
- Mark survival varies by two orders of magnitude depending on LLM proposer habits and requires sufficient games per selection decision.
- A novel provenance mark based on the ordering of near-tied entries in an object-location table was detected in 62 of 76 rewritten harness copies based on external actions alone.
- A scheme-aware adversary can bypass the novel mark by reshuffling ties at no performance cost or by prompting the LLM proposer for more general code (75-100% removal rate).

**Why it matters:** Existing agent harness provenance marks are easily erased by standard LLM self-evolution workflows, complicating intellectual property protection for agentic software.

<small>Jieyu Li, Jingya Li, Sheng Li, Xinpeng Zhang, Zhenxing Qian</small>

### [Trigger Value Selection in Clean-Label Malware Backdoors: An Effectiveness-Detectability Analysis](https://arxiv.org/abs/2610.21269v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21269v1`

Researchers evaluated trigger value selection strategies in clean-label malware backdoor attacks, demonstrating that value choices directly dictate the trade-off between attack success rate and detectability.

- Evaluated trigger value selection strategies using LightGBM classifiers on the EMBER 2018 dataset and a Win64 PE subset of EMBER 2024.
- Compared rare-value, SHAP-based, frequency-bounded, co-occurrence-aware, and quantile-based value selectors under random and distribution-based benign sampling.
- Aggressive selectors like MinPopulation and CountAbsSHAP yield high attack success rates under distribution-based sampling but are vulnerable to Isolation Forest detection.
- Balanced selectors like CorrCountAbsSHAP and Quantile95 preserve attack effectiveness while reducing poison recall by sanitization tools.

**Why it matters:** Demonstrates that trigger value selection is a primary design factor that security researchers must consider when evaluating the stealth and defense mechanisms of clean-label malware backdoors.

A critical survey of Differential Privacy (DP) in Retrieval-Augmented Generation (RAG) that establishes a three-dimensional framework to properly interpret epsilon claims across multi-query systems.

- Identifies that a single-response privacy budget does not accurately reflect privacy loss across repeated user queries.
- Categorizes current DP-RAG approaches into three distinct paradigms: query-time privatization, multi-query accounting, and one-time corpus privatization.

DAR is a support-persistent backdoor attack using feature-subspace clustering and label-only poisoning that survives clean-data knowledge distillation.

- Identifies abundant natural patterns in low-dimensional feature subspaces via subspace clustering and applies label-only poisoning to samples matching the discovered rule.

ExecWeave is a local-first system that materializes application-level provider semantics and OS-level telemetry into a unified, typed execution graph for accurate agentic software attribution.

- Retains separate source artifacts and distinguishes logical occurrences from repeated evidence while recording causal-status and attribution metadata.
- Uses an optional command-to-process correlator that emits non-causal inferred bridges only when a bounded search yields exactly one compatible process.

### [Stronger Judges Do Not See More: Deployment-Integrity Blindness in LLM Evaluation](https://arxiv.org/abs/2610.21135v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21135v1`

DIB-Bench reveals deployment-integrity blindness in LLM evaluation, showing that stronger LLM judges accept tampered runtimes at higher rates than rule-based evaluators.

- DIB-Bench evaluates deployment-integrity blindness across 7,560 scored examples, six tamper types, and evaluators ranging from regex rules to GPT-5-nano.
- Mean acceptance of tampered outputs increases with evaluator strength, rising from 88.6% for rule-based evaluators to 94.1% for GPT-5-nano.
- A PAC-style bound proves zero-output-shift tampers are impossible to detect from outputs alone at any sample size, whereas a manifest-hash identity channel detects them with zero samples.
- Behavioral fingerprinting identifies the model component above chance (76.7%), but only covers one of six system stack components.
- Evaluation-invisible trigger-conditional tampers yield 48% to 100% harmful outputs during execution, scaling upwards with model capability.

**Why it matters:** Relying strictly on output-based LLM evaluations allows compromised runtime stacks to pass benchmark checks while remaining vulnerable to conditional deployment attacks.

<small>Jianchang Su, Dawei Xiang, Yifan Zhang, Wei Zhang</small>

### [Approve What, Exactly? Effect Binding and Trusted Rendering for Agent Step-Up Authorization](https://arxiv.org/abs/2610.21063v1)

**arXiv cs.CR** · 2026-10-15 · `arXiv:2610.21063v1`

Researchers evaluated AI agent step-up authorization vulnerabilities across existing protocols and introduced Agent Step-Up (ASU), a gateway using canonical effect descriptors, local passkey signing, and trusted rendering to eliminate post-approval execution tampering.

- Defined 12 attacks on approval paths and evaluated them against AP2, Microsoft action-bound approval, and MCP elicitation; audited 10 runtimes, finding post-approval argument modification in 4 out of 8 measurable systems.
- Engineered ASU, a reference gateway that renders cards from canonical effect descriptors, collects phone passkey signatures on their digests, and executes solely the stored call.
- Formally verified ASU using Tamarin across 53 lemmas to prove binding, single-use, and key-level non-repudiation properties.
- Demonstrated across 27,108 trials and 609 AgentDojo attack pairs that trusted rendering reduced forged-narration attack success from 0.54 to 0.03 for human subjects and increased LLM automated approver attack catch rates from 0.30 to 0.98.

**Why it matters:** Standard user approval steps in agentic systems can be bypassed or spoofed without cryptographic effect binding and trusted rendering, leaving critical actions vulnerable to post-approval argument manipulation.

<small>Sai Varun Kodathala, Prashanth Pollishetty, Jaylen Cargill</small>

### [Screwtape: Adversarial Transcript Editing for Monitor Red-Teaming](https://arxiv.org/abs/2610.20941v1)

**arXiv cs.CR** · 2026-10-14 · `arXiv:2610.20941v1`

Screwtape is an adversarial pipeline that edits real LLM agent transcripts to produce offline, action-consistent attacks that evade action-only safety monitors without requiring access to a developer's execution infrastructure.

- Screwtape uses an LLM attacker to edit existing transcripts to insert harms (e.g., API key leaks, spawning unmonitored agents) alongside an LLM verifier that filters out inconsistent or low-severity edits without executing code.
- The attacker iteratively revises edits until the target monitor fails to flag the transcript.
- Evaluated on 94 Claude Code and Codex transcripts across 252 runs, the pipeline generated 35 verifier-passed attacks that evaded internal monitors.
- Human review confirmed valid attacks, six of which successfully evaded a held-out, third-party monitor provided by a frontier model developer.

**Why it matters:** It enables external red-teamers to uncover critical blind spots in action-only LLM monitors without needing direct infrastructure access or live execution environments.

<small>Gosha Kozhevnikov, Tyler Tracy</small>
