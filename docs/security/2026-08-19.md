### [COMA: A Compositional Misleading Attack Class on Security-RAG, and a Causal Counterfactual Defense](https://arxiv.org/abs/2608.17960v1)

**arXiv cs.CR** · 2026-08-18 · `arXiv:2608.17960v1`

COMA introduces a RAG attack where factually correct, benign documents compose to mislead security copilots, alongside a Causal Counterfactual Defense (CCD) that isolates adversarial influence.

- COMA uses action-corruption to steer correct vulnerability diagnoses to flawed remediations and verdict-flips to destabilize exploitability verdicts via reachability chains.
- Action-corruption successfully compromised all five tested models, including frontier reasoning models, across synthetic domains and real-world CVE-2021-33813.
- Attacks succeed specifically when the disambiguating fact must be inferred by the model rather than directly read from the retrieved documents.
- CCD uses leave-one-out causal influence measurement to flag answers relying on low-trust documents, identifying attacker-controlled documents without false positives on tested benign controls.

**Why it matters:** Security-RAG systems can be reliably manipulated using entirely true, non-contradictory retrieved documents, necessitating causal auditing defenses like CCD.

<small>Chinmay Gondhalekar, Urjitkumar Patel</small>

### [The Model's Tell: Measuring Context-Leakage Attack Signals with Behavior Gauges](https://arxiv.org/abs/2608.17829v1)

**arXiv cs.CR** · 2026-08-18 · `arXiv:2608.17829v1`

LeakGauge detects context-leakage attacks in LLMs by appending a content-agnostic behavior-gauging suffix and computing an attack-risk score from its prefill token probabilities.

- Appends a content-agnostic suffix verbalizing leakage behavior to gauge model responses before decoding.
- Achieves an AUROC range of 0.944 to 0.996 across 11 LLMs, including GLM-5.2 (753B) and Kimi-K3 (2.8T), on unseen attacks.
- Demonstrates signal stability across language changes and shifts from verbatim to semantic disclosure.
- Enables an input detector with under 0.5K additional parameters and an added latency of 10.34 ms.
- Validates via activation-steering interventions that the risk score correlates with internal leakage-related representation directions.

**Why it matters:** It provides a lightweight, highly accurate method to detect context-leakage risks without needing internal hidden-state extraction or access to LLM activations during deployment.

<small>Maosen Zhang, Jianshuo Dong, Boting Lu, Wenyue Li, Xiaoping Zhang, Tianwei Zhang, Jie Zhang, Han Qiu</small>

### [KeyPooling: Measuring Where LLM API Relay Paths Collapse Prompt Cache Isolation](https://arxiv.org/abs/2608.17485v1)

**arXiv cs.CR** · 2026-08-18 · `arXiv:2608.17485v1`

KeyPooling is a measurement method that identifies where LLM API relays collapse prompt cache isolation, revealing that shared upstream credentials enable cross-account cache reads across major open-source gateways and commercial services like OpenRouter.

- Tested five open-source gateways using OpenAI and Anthropic, finding none bound individual customers to upstream credentials by default, exposing cross-customer cache reads under shared credentials.
- Audited OpenRouter's weekly frame (covering 80.5% of eligible token volume) and found cross-account cache reads occurred in 12 of 28 provider labels, representing 33.7% of volume.
- Demonstrated side-channel risks by recovering eight consecutive target positions on a production route without direct access to the target.
- Proposed a defense contract requiring provider-enforced customer domains or authenticated namespaces, which preserves most prompt reuse at a 1.7–2.5% cost increase when placed after shared public prefixes.

**Why it matters:** LLM API aggregators and gateways that multiplex requests onto shared upstream credentials inadvertently destroy prompt cache isolation, enabling cross-tenant side-channel attacks and data leakage.

<small>Bowen Sun, Yixi Cai, Xiaogeng Liu, Zhengyue Zhao, Yinzhi Cao, Chaowei Xiao</small>

### [Fair ASR: Re-Evaluating Black-Box Jailbreaks under Shared Target-Call Budgets](https://arxiv.org/abs/2608.17360v1)

**arXiv cs.CR** · 2026-08-18 · `arXiv:2608.17360v1`

Fair-ASR introduces a target-call budget protocol for black-box LLM jailbreaks, exposing budget-dependent ranking shifts and enabling ReCode, a compositional attack achieving 85% ASR on GPT-5 within 20 target calls.

- Fair-ASR establishes a standardized evaluation protocol using target-model calls as a uniform comparison axis, while tracking attacker calls independently to measure operational efficiency.
- Re-evaluating 11 black-box attacks demonstrated that attack success rankings fluctuate significantly across target-call budgets, with simple stochastic perturbations and hand-crafted templates outperforming complex LLM-driven methods under equal access.
- ReCode combines desensitization rewriting with two low-cost primitives identified via Fair-ASR, achieving an 85% ASR on GPT-5 using a 20 target-call budget and an average of 7.19 attacker calls per request.

**Why it matters:** Standardizing jailbreak benchmarking around explicit query budgets prevents misleading safety claims and guides the development of compute-efficient red-teaming methods.

### [Fool's Gold: Defensive Deception Against Safety-Removal Attacks on Open-Weight Models](https://arxiv.org/abs/2608.17202v1)

**arXiv cs.CR** · 2026-08-17 · `arXiv:2608.17202v1`

"Fool's Gold" is a defensive deception method for open-weight models that yields confident, falsified decoy responses to hazardous requests after safety alignment is stripped via abliteration attacks.

- Trains decoys inside a differentiable simulation of abliteration attacks, using a refusal pin and benign leash to preserve original clean-state capabilities.
- Evaluated on seven dense and MoE models (9B–122B); six passed efficacy gates, yielding decoy responses on 0.51–0.90 of attacked-state requests with no detectable clean-state degradation.
- Falsified answers are observationally indistinguishable from correct ones without independent ground truth, driving error rates on a 122B model's CBRNE-adjacent benchmark slice to 0.82–0.86 (vs. <= 0.10 undefended).
- Repeated sampling (K=64 element-wise consensus) reduces usable procedure reconstruction to 0.083–0.625 (vs. 0.58–0.96 undefended), leaving users with no label-free method to verify correctness.
- Applies exclusively to initial open-weight releases against post-release safety-removal attacks, and does not mitigate in-context jailbreaks.

**Why it matters:** It renders abliterated open-weight models unreliable for malicious operational requests by poisoning the outputs with indistinguishable, falsified details rather than attempting to prevent weight modification.

**arXiv cs.CR** · 2026-08-17 · `arXiv:2608.17148v1`

A model-neutral invariant called "authorization before context" prevents cross-audience memory leakage in agentic systems by filtering memory items against current channel viewers before context assembly.

- Applies an anti-monotone audience-membership rule at the memory-to-context transition, admitting memory items only if all current viewers belonged to the item's original recording audience.
- Reads the current viewer set from channel metadata, falling back to public when metadata is ambiguous or inconsistent.
- Enforces security by exclusion prior to model invocation, rendering the boundary model-neutral and resilient against poisoned memories attempting to widen their audience.
- Evaluated on a synthetic Contextual-Integrity suite where the boundary completely eliminated forbidden facts from assembled contexts compared to unscoped baselines, failing closed on all audited read paths.

**Why it matters:** It deterministically guarantees data privacy in agentic memory retrieval by removing unauthorized context before LLM processing, eliminating reliance on non-deterministic model compliance.

### [LLMs and Contextual Integrity](https://www.schneier.com/blog/archives/2026/08/llms-and-contextual-integrity.html)

**Schneier on Security** · 2026-08-18

Two papers show frontier LLMs frequently violate contextual integrity by inappropriately leaking persistent memory attributes, but training models to explicitly reason about CI using RL significantly reduces leakage without sacrificing utility.

- Evaluations using the CIMemories benchmark revealed frontier models exhibit up to 69% attribute-level information leaks, with GPT-5 violations escalating from 0.1% to 25.1% across repeated runs and multiple tasks.
- Privacy-conscious prompting fails to fix CI violations, causing LLMs to overgeneralize by either withholding all data or leaking everything.
- Explicitly prompting LLMs to reason about contextual integrity, combined with an RL framework trained on 700 synthetic examples, substantially decreased unauthorized disclosures while preserving task performance.
- The reasoning and RL approach successfully transferred performance improvements to human-annotated CI benchmarks like PrivacyLens.

**Why it matters:** As autonomous AI agents rely on persistent user memory, scaling and basic prompting are insufficient to prevent privacy leaks, requiring specialized reasoning and RL training frameworks to enforce context-dependent data protection.
