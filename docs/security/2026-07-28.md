### [Does Runtime Topology Context Improve LLM-Generated Kubernetes Security Patches?](https://arxiv.org/abs/2607.25995v1)

**arXiv cs.CR** · 2026-07-28 · `arXiv:2607.25995v1`

Integrating live runtime topology context into LLM prompts using the KuTIE framework increases Kubernetes security patch correctness for topology-dependent findings from 11.1% to 78.0%.

- KuTIE builds runtime context from Istio call edges, Trivy KSPM findings, and service-account bindings to condition LLM patch generation.
- Evaluated across 248 trials on VulnCare, a 36-deployment cluster featuring 31 findings across seven dependency classes.
- Topology context improved patch correctness across six of seven dependency classes, with the largest delta in credential and network-policy classes (Δ = 0.95) and RBAC (Δ = 0.31).

**Why it matters:** Automated LLM security remediation requires live cluster topology data to prevent valid security patches from breaking hidden runtime service dependencies and causing cluster outages.

IH-Benchmark evaluates LLM instruction-hierarchy robustness across system-user (S>U) and user-tool (U>T) conflicts using a human-authored taxonomy of 44 constraint families and a binary pass/fail predicate DSL protocol.

- Evaluated 37 models, finding instruction-hierarchy compliance rates ranging from 98.2% down to 20.5%.
- High S>U compliance does not guarantee U>T robustness, as models preserving system constraints against direct user input often degrade when conflicting instructions appear in tool outputs.
- Models resist high-impact actions like unauthorized purchases better than subtle overrides like injected disclaimers or minor factual distortions.
- Constraint hardening with stronger warnings resolves failures in some models, while in others, failures persist regardless of strictness levels.

**Why it matters:** Instruction-hierarchy robustness cannot be inferred from system-level compliance alone and must be benchmarked separately across diverse attack vectors and tool-mediated surfaces.

### [Evaluation of Adversarial Robustness in Arabic Language Models](https://arxiv.org/abs/2607.25814v1)

**arXiv cs.CR** · 2026-07-28 · `arXiv:2607.25814v1`

A study evaluates five Arabic language models against multi-granularity adversarial attacks, finding diacritics insertion causes up to 92% accuracy drops, while adversarial training improves resilience, particularly in MARBERT and AraBERT.

- Character-level attacks using diacritics insertion reduced model accuracy by up to 92% while maintaining a low perturbation distance.
- Word-level attacks manipulating Arabic conjunctions lowered accuracy by up to 58% while preserving low perturbation distance and high semantic similarity scores.
- Sentence-level paraphrasing attacks reduced victim model performance by an average of 76%.
- Adversarial training improved overall resilience, yielding the highest absolute robustness in MARBERT and the largest relative gains in AraBERT, though character-level noise vulnerabilities remain.

**Why it matters:** The high vulnerability of Arabic language models to subtle, morphology-specific perturbations underscores the need for tailored adversarial defenses in non-English natural language processing deployments.

**arXiv cs.CR** · 2026-07-28 · `arXiv:2607.25451v1`

Researchers evaluated verbatim data extraction across quantized Pythia models, finding that quantization reduces memorization faster than capability but fails to act as a reliable privacy defense.

- Evaluated verbatim extraction and perplexity across Pythia model sizes (up to the largest tested) and five precision levels down to 4-bit precision.
- Tested two distinct quantization algorithms and two evaluation corpora using known memorized sequences.
- Quantization acts as a selective forgetter, dropping verbatim memorization faster than general model capability across all tested sizes.
