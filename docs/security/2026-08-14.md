### [Concept Drift Detection and Adaptive Retraining of Malware Classification Models](https://arxiv.org/abs/2608.13465v1)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.13465v1`

A novel One-Class Support Vector Machine (OCSVM) approach effectively detects concept drift in malware classification models, matching periodic retraining accuracy while significantly reducing computational overhead.

- Evaluated OCSVM-based concept drift detection against Minibatch K-Means (MK-Means) and Maximum Mean Discrepancy (MMD) statistical methods.
- Tested performance across four baseline classifiers: Multilayer Perceptron, Random Forest, Support Vector Machines, and eXtreme Gradient Boosting (XGBoost).
- Compared static, periodic, and drift-aware retraining scenarios using Pareto Front analysis to measure the tradeoff between accuracy and training efficiency.
- Drift-aware retraining with OCSVM matched the classification accuracy of continuous periodic retraining while reducing the total number of retrained models, generally outperforming MK-Means and MMD.

**Why it matters:** Drift-aware retraining via OCSVM allows cybersecurity systems to maintain high malware detection accuracy against evolving threats without incurring the heavy compute costs of constant periodic retraining.

<small>Christofer Washington Berruz Chungata, Martin Jurecek, Katerina Potika, William B. Andreopoulos, Mark Stamp</small>

### [LLM-Assisted Dynamic Threat Analysis for Attacker-Reachable Software Weaknesses in Autonomous Vehicles](https://arxiv.org/abs/2608.13450v1)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.13450v1`

Researchers evaluated LLMs for generating dynamic exploitability test harnesses in the Autoware autonomous driving stack, finding that build integration and dependency wiring failures constitute the primary bottleneck rather than logic generation.

- Compiler-precise static analysis of 185 Autoware packages identified 1,375 decision rules, 2,274 validation checks, and 482 input-to-safety-output flows.
- Evaluating LLM generation across 740 sampled reachable sites yielded 3,700 artifact sets, where 80% of initial compilation failures stemmed from dependency wiring rather than program logic.
- The tested reasoning model achieved a 64% first-shot compilation rate compared to 6% for the code-specialized model.
- Full object-compileability required extensive stubbing, resulting in under half of the harnesses reaching the fuzzer and 37 observed crashes originating entirely in stubbed code rather than Autoware.
- Zero candidate weaknesses were dynamically confirmed within the evaluation budget.

**Why it matters:** Automating software safety and security verification for autonomous vehicles using LLMs requires solving dynamic build integration and dependency resolution before LLM-generated fuzzing harnesses can successfully confirm vulnerabilities.

<small>Md Wasiul Haque, Sagar Dasgupta, Mizanur Rahman, Md Rayhanur Rahman</small>

### [Does Fixing Break Security? An Empirical Study of Security Degradation in Iterative LLM-Driven Infrastructure-as-Code Repair](https://arxiv.org/abs/2608.13404v1)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.13404v1`

An empirical study of 5,968 IaC-Eval timelines reveals that iterative LLM repair causes true security regressions in 3.3% of scenarios, primarily driven by resource restructuring and high code churn.

- Analyzing 4,440 iteration transitions showed a standard regression rate of 13.8% of scenarios, but strict detection isolates true regressions to 3.3% of scenarios (5.2% of transitions) by filtering out multi-resource artifacts.
- Resource restructuring accounts for 79.0% of root cause security regressions during LLM repair attempts.
- Regression transitions exhibit 2.6x higher code churn (Cohen's d=0.90) and 4.9x higher strict-mode check volatility (d=1.49).
- 36.6% of standard-mode regressions self-correct within an average of 1.2 iterations, making iteration 3 the optimal stopping point.

**Why it matters:** It demonstrates that non-monotonic security degradation occurs during iterative LLM code repair, highlighting the need for security-aware feedback loops and optimal iteration budgets.

<small>Benjamin Agyekum, Fabio Santos</small>

### [RAGSieve: Self-Referenced Local Contrast for Knowledge-Poison Detection in Retrieval-Augmented Generation](https://arxiv.org/abs/2608.13010v1)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.13010v1`

RAGSieve is a self-referenced framework that detects knowledge-poisoning in RAG systems via query-local and corpus-local contrast without requiring poison labels, external reference corpora, or global thresholds.

- RAGSieve-Query (RSQ) measures query-local contrast by scoring top-5 retrieved candidates against ranks 6-20 to identify answer-anchor concentration and carrier transitions at inference.
- RAGSieve-Graph (RSG) evaluates corpus-local contrast during ingestion, comparing semantically similar but lexically distinct neighbors against local baselines to spot coordinated document density.
- Evaluated across three QA datasets and six attack types, RSQ achieved 95.2% AUROC and RSG achieved 93.3% AUROC, outperforming existing baselines like GMTP and CleanBase.
- Joint deployment of RSQ and RSG reduced attack success rates from 67.4% to 14.0% while preserving a 41.3% F1 score on clean retrievals.

**Why it matters:** It enables practical, two-tier defense against retrieval poisoning attacks at both corpus ingestion and query execution without depending on clean reference datasets.

<small>Xinlong Xu, Yoshua Y. Li</small>

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.12880v1`

An audit of an MCP agent security evaluation revealed direct treatment leakage in the historical grader, where treatment metadata artificially gated attack labels without corresponding behavioral changes.

- Audited 10,200 execution rows down to 180 model-bound requests and 15 observable stimuli, discovering that the planned payload-family corpus was never delivered.
- A treatment-blind reconstruction reclassified 58 historical ATTACK_SUCCESS or HIJACK_ATTEMPT labels as authorized benign completions.
- The corrected locked v2 census contained zero ATTACK_SUCCESS records, preserving only three verified protected-data transfers and one unauthorized-forwarding case.
- A dual-reviewer blinded concordance review matched reviewer-consensus classes across 96 interpretable requests, but diverged from the locked codebook on four construct-boundary cases.
- Introduced a seven-link Integrity Chain and an executable, scope-bounded endpoint-integrity linter to validate agent evaluation integrity.

**Why it matters:** Equating stored evaluation labels with actual agent behavior can lead to false security assessments if treatment metadata leaks into grading logic.

A novel LLM watermarking method co-embeds robust and fragile signals into each token using independent keys and seeding windows, enabling concurrent provenance tracing and tamper detection.

- Co-embeds a robust signal resilient to edits alongside a fragile signal sensitive to reader-visible changes within each generated token.
- Employs unbiased tournament reweighting across multiple rounds to preserve the expected generation distribution.

### [Privacy-Preserving RAG by Concealing Sensitive Information from External LLMs](https://arxiv.org/abs/2608.12675v1)

**arXiv cs.CR** · 2026-08-13 · `arXiv:2608.12675v1`

Researchers developed the Sensitive Entity Alias Generator (SEAG), a framework that obfuscates private entities in queries and retrieved documents using generated alias tables before sending them to third-party LLMs.

- SEAG uses a lightweight model to identify sensitive entities, construct an entity replacement table, and swap sensitive words in queries and retrieved documents before external transmission.
- Evaluating the framework on user accuracy (providing correct responses while hiding sensitive data) yielded over 80% accuracy across all tested models.
- In evaluating complete entity hiding across documents, SEAG implemented with Qwen-3, LLaMA-3.2, and Phi-4 achieved total accuracies of 77.83%, 76.73%, and 74.91%, respectively.
- Two new datasets were specifically constructed to fine-tune SEAG models and evaluate the end-to-end framework.

**Why it matters:** This approach enables organizations to leverage high-performing external LLM providers for Retrieval-Augmented Generation without exposing confidential query data or document contents to third parties.

### [AI Guardrail Survival under Single-Cycle Agentic Self-Summarization](https://arxiv.org/abs/2608.11392v2)

**arXiv cs.CR** · 2026-08-11 · `arXiv:2608.11392v2`

Single-cycle agentic self-summarization often degrades safety rules into non-functional textual residues, causing significant behavioral violations even when constraints appear textually intact.

- Textual presence of a safety rule does not guarantee execution; degraded residues increased prohibited actions by 34 and 57 percentage points over intact rules across two replay models.
- Rule-form items are retained in context summaries substantially more often than prominence-matched facts, creating false assurance during audits.
- Textual loss regimes depend on context budgets, exhibiting weld-or-drop with single rules and degraded predicate-loss under tighter budgets, while pure textual severing was not observed.
- Silent runtime degradation requires external ground truth (like a constraint registry) to detect loss, though registries fail to detect if a surviving rule still fires.
- Evaluation reliance on LLM-judge labels alone produced inaccurate conclusions that would have reversed experimental findings.

**Why it matters:** Auditing agent memory summaries for the mere presence of safety rules creates false assurance, as context compaction silently neutralizes guardrails without removing their text.

<small>Ted Kwartler, Alan Aqrawi, Arian Abbasi</small>
