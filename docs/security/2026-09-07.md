### [When LLM Decompilers Recompile More and Preserve Less](https://arxiv.org/abs/2609.05370v1)

**arXiv cs.CR** · 2026-09-04 · `arXiv:2609.05370v1`

Researchers introduce Decompile-Diverge, a fuzzing-based behavioral comparison oracle, revealing that LLM decompilers frequently generate recompileable, test-passing code that diverges from original binary behavior or removes security vulnerabilities.

- Evaluated eight LLM decompilation systems across nine configurations using synthesized drivers and reference-grown fuzzing corpora to detect behavioral divergence.
- Found that candidates passing all shipped tests still diverge from original binaries on expanded inputs 4.9% of the time overall, and up to 13% for individual systems.
- Applying an LLM refinement step to Ghidra output increased the build rate from 75% to 90%, but reduced the behaviorally Matched rate from 74% to 62%.
- Up to 10% of tested CVE-grounded functions exhibited Crash Absence, where disclosed vulnerabilities disappeared from the recompiled code without trace.
- Source-level analysis revealed divergences are caused by LLMs hallucinating fields, types, callees, and guards instead of leaving explicit placeholders like traditional decompilers.

**Why it matters:** Evaluating LLM decompilers solely on recompilability and passing static tests masks semantic errors and security risk alterations, making them unreliable for vulnerability detection and malware analysis.

<small>Chang Liu, Edward Raff, Kristopher Micinski</small>

**arXiv cs.CR** · 2026-09-04 · `arXiv:2609.05269v1`

CONTINUITY is a framework using assume-guarantee contracts and signed security context to prevent context discontinuity and secure instruction-to-effect paths in composable LLM agent systems.

- Identifies security-context discontinuity, where security controls fail when context is dropped, widened, or rebound across component boundaries.
- Carries authenticated context using signed root grants, provenance commitments, transition receipts, bounded releases, transformation witnesses, and effect-bound execution permits.
- Formalizes end-to-end consequence integrity to ensure every external effect maps to a valid authorization witness covering principal, task, provenance, delegation, policy, action, and finality boundary.
- Tested via a reference verifier and a fault-injection suite covering 32 fault classes across 2,560 parameterized attack instances, resulting in zero harmful external effects while completing 700 benign tasks.

**Why it matters:** It proves that individual agent security controls are insufficient unless linked by explicit contracts that prevent authority escalation during component transitions.

### [Engineered Persuasion: Evaluating Personalized Pretexts in LLM-Generated Spear Phishing](https://arxiv.org/abs/2609.04410v1)

**arXiv cs.CR** · 2026-09-03 · `arXiv:2609.04410v1`

A study of 180 working adults evaluated AI-generated phishing emails, finding that each added level of personalization increased convincingness by 2.40 points and click intention odds by 28%, provided details fit the recipient's work context.

- Evaluated four cumulative levels of LLM-generated personalization: workplace (L1), recipient name/title (L2), job responsibilities (L3), and coworker/shared-project context (L4) across 1,436 valid evaluations.
- Higher personalization levels increased convincingness by 2.40 points per level (on a 0-100 scale) and increased the odds of expressing click intention by 28% per level.
- Messages originating from a named individual referencing a supplied coworker yielded higher convincingness and click intention than messages from a generic department or entity.
- Non-clicking participants shifted behavior as personalization increased: reporting declined while deletion increased and investigation remained common.
- Qualitative analysis revealed a double-edged effect: role-matched details enhanced credibility, whereas incorrect, vague, or channel-inappropriate details triggered suspicion.

**Why it matters:** Cybersecurity training must move beyond teaching employees to spot generic personalized details and focus on evaluating whether pretext context and channels match real-world workplace routines.

<small>Jerson Francia, Derek Hansen, Benjamin Schooley, Shydra Valynn Murray</small>

### [Privacy Failure in Split-LLM Training, The Returned Gradient Nullifies the Decoys](https://arxiv.org/abs/2609.04382v1)

**arXiv cs.CR** · 2026-09-03 · `arXiv:2609.04382v1`

A two-node split-LLM training system's decoy-based privacy defense fails because zero-value gradients returned from the Trusted Local Node deterministically expose the private, non-decoy rows to the Untrusted Cloud Node.

- In the evaluated split-LLM system, decoy activations are added to forward frames but ignored by the loss, causing their returned gradients to be exactly zero.
- Across nine seeds, gradient zero-patterns identified 100% of real activation rows (4,096 of 4,096 per run) while passing initial forward-channel privacy and model quality checks.
- An attack on frame contents recovered +0.65 to +1.50 percentage points more tokens over baseline, while shuffled-label controls recovered zero.
- Clipping and adding noise to individual gradient rows mitigated the leak at a loss of ~0.01 nats of held-out cross-entropy, though multi-step accumulation attacks remain unmeasured.

**Why it matters:** Evaluating privacy solely on the forward activation channel creates a false sense of security, as backward gradient returns can completely compromise decoy-based obfuscation schemes.

<small>Georgios Politis, Evangelos Pappas</small>

### [Why Is SHAP Not a Reliable Standalone Explanation Framework for Malware Detection?](https://arxiv.org/abs/2609.04626v1)

**arXiv cs.CR** · 2026-09-04 · `arXiv:2609.04626v1`

A theoretical and empirical evaluation demonstrates that SHAP is unreliable as a standalone explanation framework for malware detection due to feature dependencies and off-manifold coalition queries.

- SHAP explains a user-defined feature-coalition game dictated by choices in background distribution, missing feature rules, and input mappings rather than actual malware behavior.
- Theoretical proofs show conditional SHAP dilutes feature credit by a factor of 1/m across m-1 redundant features, assigns importance to unused features, and can reverse an unused feature's attribution sign under distribution shifts.
- Interventional SHAP evaluates off-manifold feature coalitions that produce synthetically invalid executables not found in real-world data.
- Experiments validating these structural failure modes were conducted on EMBER-2018, EMBER-2024, and BODMAS benchmarks using fixed LightGBM and XGBoost models.

**Why it matters:** Security analysts cannot rely on SHAP alone to verify if a machine learning detector has learned true malicious functionality versus dataset artifacts without explicit domain validation.

<small>Seyedreza Mohseni, Edward Raff, Manas Gaur</small>

`malware-detection` `shap` `explainable-ai` `machine-learning` `cybersecurity`
