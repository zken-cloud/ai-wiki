### [Quantization-Tolerant Gradient Auditing for Active Inference-Attack Detection in Federated Learning](https://arxiv.org/abs/2610.13311v1)

**arXiv cs.CR** · 2026-10-09 · `arXiv:2610.13311v1`

A federated learning server audit uses secret challenge batches and quantized gradient fingerprints to detect active model-tampering attacks with high accuracy.

- The server sends secret challenge batches to clients, who return gradient checksums and timing data to reveal unauthorized model state mutations, such as GAN-based active attacks.
- Quantized gradient fingerprints accommodate cross-platform floating-point non-determinism, achieving a 1.0 true-positive rate with zero false positives across up to 50 clients and up to 40% malicious client ratios.
- The protocol introduces minimal overhead, requiring 32 ms of server computation time and 4.35 kB of bandwidth per response.
- Passive attackers are only detectable via timing under low-jitter conditions, and attackers that run challenges on an un-tampered model replica completely evade detection.
- The mechanism is designed to compose with differential privacy, evaluated on the Texas100 dataset, rather than fully replacing it.

**Why it matters:** It offers a lightweight, low-overhead defense against active federated learning attackers without incurring the severe model utility loss typical of heavy differential privacy noise.

<small>Michael Kuehne-Schlinkert</small>

### [PVBRF-ID: Private, Verifiable and Byzantine-Robust Federated Intrusion Detection for Oilfield Enterprise Networks](https://arxiv.org/abs/2610.12704v1)

**arXiv cs.CR** · 2026-10-08 · `arXiv:2610.12704v1`

PVBRF-ID is a two-server federated learning protocol that combines secret sharing, norm and cosine similarity checks, and homomorphic audits to achieve private, Byzantine-robust, and publicly verifiable intrusion detection.

- Uses a two-server model where sites secret-share updates to evaluate norm limits and cosine similarity against a clean root set reference, outputting a single accept bit per site.
- Ensures public verifiability of accepted update inclusions through commitments, Merkle roots, and homomorphic auditing.
- Achieves a 0.696 macro-F1 score under sign-flip attacks compared to FedAvg's 0.091, and 0.641 under an adaptive attack controlling 30% of sites on a 15-class Edge-IIoTset benchmark.
- Prevents update-inference attackers from recovering a site's class mix (which succeeded in the plaintext baseline with a Spearman correlation of 0.81), though backdoors remain a limitation.

**Why it matters:** It enables distributed industrial enterprise networks like oilfields to collaboratively detect network intrusions without compromising site data privacy or vulnerability to malicious update poisoning.

<small>Mustafa S. Aljumaily, Ali Ataeemh Allami, Mustafa N. Mnati, Nawar S. Alseelawi, Shahab Abdulla</small>

### [Organizational Context for the Enterprise Security Brain](https://arxiv.org/abs/2610.12540v1)

**arXiv cs.CR** · 2026-10-08 · `arXiv:2610.12540v1`

Researchers introduce organizational context as a structural layer for enterprise security brains, bridging the gap between live machine state and unstructured human-recorded security data.

- Defines an organizational context model where claims carry single meanings, attestations track source assertions, claim strength is calculated dynamically at read time, and claims resolve directly to an asset graph.
- Addresses four core operational challenges: heterogeneous claim extraction, stale claim detection, live policy checking, and binding architecture diagrams to live cloud/identity resources.
- Achieved 0.80 recall and 0.87 precision on a ground truth of 1,355 claims extracted across production AWS, Okta, Google Workspace, and GitHub data, with a 0.5% unsupported claim rate.
- Demonstrated security agent performance of 0.97 in raising conflicts on stale-finding tasks, 0.83 answer correctness on policy-alignment tasks, and 0.86 on architecture-binding tasks.

**Why it matters:** It enables automated security agents to make accurate risk and policy judgments by linking human knowledge to live multi-cloud infrastructure.

<small>Eden Yavin, Ariel Zadok, Gal Engelberg, Elad Elouz, Leon Goldberg</small>
