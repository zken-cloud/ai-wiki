### [Prompt Structure Redistributes, Not Reduces: An Empirical Analysis of Security-Weaknesses in LLM-Generated Python Code](https://arxiv.org/abs/2608.24857v1)

**arXiv cs.CR** · 2026-08-25 · `arXiv:2608.24857v1`

An empirical study reveals that structured and security-focused prompts do not reliably reduce overall code weaknesses in LLMs, but instead redistribute risk from high-severity to low-severity flaws.

- Evaluating 424 security-sensitive Python tasks across GPT-4o and LLaMA 3.1-8B using Bandit and CodeQL showed that structured prompts drastically cut output refusals (GPT-4o invalid outputs dropped from 338/424 to 37-52).
- Security-oriented refinements redistributed GPT-4o risks rather than eliminating them, shifting high-severity findings down from 20.8% to 13.6% while low-severity findings increased from 32% to 43.5%.
- LLaMA 3.1-8B exhibited weaker, less consistent security shifts across prompt variants compared to GPT-4o.
- Stricter prompt variants induced security-driven semantic drift, causing models to silently alter or omit explicitly requested unsafe constructs.

**Why it matters:** Prompt engineering cannot replace traditional code auditing and security controls, as security-focused prompts merely alter the distribution of vulnerabilities rather than preventing them.

<small>Maitreyee Das Urmi, Jessica Pourleyli, Fabio Santos, Glaucia Melo</small>

### [StepGuard: Learning Step-Level Guardrails with Scalable Supervision and Safety-Utility Balancing](https://arxiv.org/abs/2608.24777v1)

**arXiv cs.CR** · 2026-08-25 · `arXiv:2608.24777v1`

StepGuard is a step-level guard model trained via the StepGen data engine and Balance-GRPO to audit tool actions before execution, maintaining high agent utility while mitigating security risks.

- Audits completed trajectories and pre-execution tool actions to catch security risks like unauthorized actions and information leakage before execution.
- Uses StepGen, an automated data engine that creates paired safe and unsafe trajectories sharing identical contexts up to the risky step.
- Employs Balance-GRPO, a reinforcement learning approach that dynamically balances learning between safe and unsafe actions using real-time accuracy metrics to minimize over-defense and under-defense.
- Reduces the mean attack success rate on AgentDojo and AgentDyn by 77.3% relative to an unguarded baseline, with a utility loss of only 2.8 percentage points.

**Why it matters:** It enables proactive, real-time security interventions for tool-using LLM agents without significantly degrading their functional task completion capabilities.

### [Do System Prompts Leave Behavioral Fingerprints? A Large-Scale Empirical Study of Clone Detection via Output Similarity](https://arxiv.org/abs/2608.24461v1)

**arXiv cs.CR** · 2026-08-25 · `arXiv:2608.24461v1`

Black-Box Behavioral Fingerprinting (BBF) uses model outputs via API access to detect prompt clones, achieving an overall cross-model AUC of 0.725 and up to 0.889 AUC against non-adaptive prompt paraphrasing.

- BBF registers behavioral signatures from black-box LLM API outputs to compare suspect deployments against baseline outputs.
- System prompt selection accounts for 24.4% of output variance, enabling same-model clone detection to achieve 0.876 AUC.
- Cross-model detection performance varies by detector identity, yielding an average cross-model AUC of 0.725 (ranging from 0.845 for Claude to 0.665 for Qwen).
- Simple style modifications, such as adding a single-sentence formal-tone prefix, degrade detection performance on short structured outputs (e.g., MNLI AUC dropped from 0.978 to 0.547).
- Diagnostic Query Optimization improves cross-model detection performance by +0.120 AUC at zero cost.

**Why it matters:** BBF enables prompt creators to detect stolen or cloned system prompts via black-box API queries, though its effectiveness remains vulnerable to simple stylistic modifications.

<small>Linghan Chen, Yudong Gao, Jiyao Wang, Kaiyan Ji, Honglong Chen</small>

### [Not All Tokens Are Equal: Region-Aware Consistency Repair of Backdoors in MLLMs](https://arxiv.org/abs/2608.24354v1)

**arXiv cs.CR** · 2026-08-25 · `arXiv:2608.24354v1`

RACER is a model-level backdoor repair framework for MLLMs that uses region-aware layer-wise inconsistency normalization and adversarial fine-tuning on 100 clean samples without prior trigger knowledge.

- Identifies that backdoors cause a modality-dependent 'layer-wise inconsistency anomaly' concentrated in token regions encoding trigger features.
- Decomposes representations into visual and textual token regions, normalizes layer-wise inconsistency separately, and recomposes them via modality-aware weights over a deep-layer window.
- Uses a min-max optimization loop to synthesize worst-case perturbations and fine-tune the model to suppress backdoor-inducing representational shifts.
- Requires only 100 clean samples and no prior knowledge of the trigger, attack objective, or model infection status.
- Evaluated on three open-source MLLMs across 36 backdoor settings, reducing average Attack Success Rate (ASR) to 1.1% and achieving 0% ASR in 32 settings.

**Why it matters:** It enables model owners to permanently remove latent multimodal backdoors directly from model weights prior to deployment using minimal clean data, rather than relying on inference-time input filtering.

### [TrustShiftProbe: Characterizing, Benchmarking, and Defending Staged Trust Attacks on MCP Servers](https://arxiv.org/abs/2608.23763v1)

**arXiv cs.CR** · 2026-08-24 · `arXiv:2608.23763v1`

TrustShiftProbe characterizes temporal TrustShift attacks on MCP servers—where compromised endpoints act benignly before deploying malicious payloads—and introduces SHIELD, a zero-oracle runtime defense that audits server responses against learned baselines.

- TrustShift attacks exploit the MCP tool channel through a two-phase lifecycle: a benign conditioning phase that builds reliance followed by adversarial defection at a trust horizon.
- The framework establishes a taxonomy of nine TrustShift variants across three execution mechanisms (structural violation, semantic corruption, scope expansion) and three objectives (disruption, exfiltration, combined).
- Pre-deployment static analysis and runtime middleware filters fail against these attacks because schema-valid payload manipulations preserve outer protocol compliance.
- Evaluated on frontier proprietary and open-weight models, TrustShift attacks achieved a 69.5% mean attack success rate, which the SHIELD runtime defense reduced to 42.7%.

**Why it matters:** This research reveals that trusted MCP server endpoints can bypass static pre-deployment checks and schema-based runtime filters by delaying malicious behavior, necessitating stateful, baseline-auditing defenses at the transport boundary.

An exact algorithm and Lean-mechanized checker that evaluate agent execution edits—Checkpoint, Fork, Restore, and Merge—to determine all safe continuation paths or prove that no safe option exists.
