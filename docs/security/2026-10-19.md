### [Agents are your newest insiders. Security must move at their speed.](https://www.microsoft.com/en-us/security/blog/2026/10/19/agents-are-your-newest-insiders-security-must-move-at-their-speed/)

**Microsoft Security Blog** · 2026-10-19

Microsoft has extended Project Perception to secure the "agentic insider" by wrapping non-deterministic agent intelligence in deterministic security controls.

- Enforces the principle of separating the supply of intelligence from security authority, placing controls outside the model so they cannot be bypassed.
- Project Perception integrates with Microsoft Agent 365 via a unified registry to share signals, context, and risk views across IT and security teams.
- Deploys Guardian Agents alongside sensors, context, and actuators to continuously monitor agents, minimize authority, and adjust runtime access boundaries.
- Executes four continuous security responsibilities: knowing agent identity/ownership, containing pre-action scope, protecting systems in the agent's path, and dynamically adapting policies.

**Why it matters:** It establishes an architectural blueprint for managing agentic risk by treating autonomous AI agents as non-deterministic insiders that require external, continuous machine-speed containment.

### [From Billion-Scale to Million-Scale Language Models: Operational Capabilities for Embedded Post-Exploitation](https://arxiv.org/abs/2610.23534v1)

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.23534v1`

Researchers evaluated seven small language models (20M-1.5B parameters) on post-exploitation tasks, demonstrating that sub-billion parameter models can reliably generate functional malware code under specific prompting and task formulations.

- Evaluated seven open-source SLMs across two post-exploitation tasks: Directory Enumeration and Backdoor Generation in Python and Lua.
- Offensive code-generation capability does not scale linearly with model size; task formulation has a greater impact on success than prompt engineering alone.
- Using algorithmic task formulation with few-shot prompting, Qwen2.5-Coder 1.5B achieved a Pass@5 of 100% for Directory Enumeration (Python/Lua) and Backdoor Generation (Python), and 99.2% for Backdoor Generation (Lua).
- Evaluated techniques included iterative reasoning, grammar-constrained decoding, and execution-feedback loops to assist low-resource language generation.

**Why it matters:** The findings highlight the feasibility of integrating compact, local SLMs into future autonomous malware, reducing reliance on cloud-based LLM inference during post-exploitation.

<small>Gabriel Hortea, Simon Pietro Romano, Juan Tapiador, Mario Varlese</small>

### [Monitor-Validity Failures: LLM Safety Evidence Paths at Evolving Framework Boundaries](https://arxiv.org/abs/2610.23362v1)

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.23362v1`

Researchers defined monitor-validity failures in LLM frameworks, where generated safety evidence is correctly identified by detectors but fails to reach downstream enforcement points due to boundary, schema, or stream disconnections.

- Identified a distinct failure mode where safety evidence is valid and recognized (e.g., a regex detector match) but stranded before reaching the execution block decision.
- Developed a canary contract protocol using parent/fixed confirmation units to test evidence surface visibility and track downstream action-boundary outcomes.
- Validated 18 evidence-path failures across 11 LLM/agent safety project groups and 4 ecosystems, with 14 reaching E1 enforcement boundaries (7 native, 6 configured, 1 synthetic).
- Categorized failures into carrier, adapter, authority, and surface families, demonstrating that application functionality often stays intact while safety-specific paths fail silently.

**Why it matters:** LLM safety guardrails can silently fail during framework evolution, requiring deterministic regression testing at adapters, streams, and schemas rather than relying solely on detector accuracy.

<small>Junchi Liao</small>

### [Ignored, Not Refused: What Low Prompt-Injection Success Rates Hide in Small Tool-Using Agents](https://arxiv.org/abs/2610.23254v1)

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.23254v1`

Auditing 33,000 trajectories across eleven 2-14B open-weight agents reveals that low indirect prompt injection (IPI) attack success rates (ASR) stem primarily from agents ignoring instructions rather than actively refusing them.

- Label-blind LLM judge evaluations show 76-80% of failed IPI attacks are silently ignored, while only 17-18% are actively refused.
- System prompt modifications alone, using identical model weights, shifted InjecAgent ASR from 0.2% to 43%.
- The Attack-Task Outcome Matrix (ATOM) demonstrated that in 21.7% of AgentDojo episodes, the agent avoided the injection but failed to complete the original user task.

**Why it matters:** Evaluating safety via ASR alone hides task failure rates and system prompt sensitivity, masking whether an agent is genuinely secure or merely failing to follow instructions.

### [Trojan Horse: Automated Repository Poisoning against Coding Agents](https://arxiv.org/abs/2610.23109v1)

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.23109v1`

Researchers introduced TrojanForge, the first automated framework for repository poisoning against coding agents, along with TrojanBench, a multi-language evaluation benchmark of 384 poisoned repositories.

- TrojanForge maps agent execution traces to abstract syntax tree (AST) nodes and uses a security review agent to select low-conspicuity payload locations.
- The framework employs adversarial play against target agents to iteratively refine payload disguise strategies and transfers successful attack patterns across repositories.
- Benchmarking across 4 harnesses and 12 models yielded a poisoning success rate over 60% and a backdoor injection rate exceeding 90%.

**Why it matters:** The findings demonstrate that current autonomous coding agents, including commercial models, are vulnerable to automated, realistic repository-level backdoor attacks.

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.23077v1`

Researchers demonstrated an authorization-grounded workflow attack where a tool-using agent obtains a legitimate local approval token to bypass document access restrictions without using explicit policy-override instructions.

- The attack operates by guiding an agent to request a standard approval token from a local approval service after a document request is denied, then supplying that token to the authorized_by parameter.
- Tested in the OpenClaw Agent Security Attack Competition environment, the attack succeeded on three Enterprise OA document targets.
- Controlled validation showed the original configuration reached the token transition in 9/9 reruns and completed the target operation in 8/9 reruns.

### [Stealthy Poisoning Attacks via Reused KV Cache of Reasoning](https://arxiv.org/abs/2610.22873v1)

**arXiv cs.CR** · 2026-10-16 · `arXiv:2610.22873v1`

R2ECAP is a novel black-box attack that poisons LLM reasoning KV caches via standard chat interactions, outperforming white-box methods while evading detection.

- R2ECAP uses a two-trace construct: a preceding trace that steers the model toward an adversarial target, and a retained trace that carries the target into the cached state.
- The attack exploits residual adversarial influence preserved in the retained trace's KV cache, which persists even after discarding the preceding trace and its cache entries.
- R2ECAP achieves up to a 79% attack success rate (ASR) on open-weight LLMs, outperforming the white-box HijackKV attack in 8 out of 9 resource-constrained settings.
- The attack demonstrated a 46% ASR in a realistic reasoning-trace retrieval setup and maintained high stealth, with only 1% of retained responses flagged by a standard prompt injection detector.

**Why it matters:** Systems optimizing LLM inference by caching and reusing reasoning traces are vulnerable to persistent, stealthy manipulation entirely through public chat interfaces.

<small>L. Zhu, Y. Jung, S. Szyller</small>

`llm-security` `kv-cache` `poisoning-attack` `adversarial-machine-learning`

### [Training AIs to Solve CAPTCHAs](https://www.schneier.com/blog/archives/2026/10/training-ais-to-solve-captchas.html)

**Schneier on Security** · 2026-10-19

Researchers developed an adaptive CAPTCHA solver using a confidence-based router between YOLOv8 and an open-weight VLM, allowing the system to learn new CAPTCHA classes autonomously from screenshots without human annotation or DOM access.

- Operates entirely via OS-level inputs and screenshots, achieving 85.4% overall and 84.2% macro accuracy across 16 classes.
- Combines a specialized YOLOv8 detector for high-speed inference with an open-weight VLM for handling low-confidence or novel inputs.
- Uses VLM outputs as pseudo-labels to train the detector on unseen categories after only one or two encounters.
- Recovers automatically from adversarial image perturbations designed to zero out detector accuracy using a ~70%-accurate VLM teacher in a simulated year-long arms race.

**Why it matters:** Visual CAPTCHAs relying on static defense assumptions fail against adaptive agents that continuously self-improve and recover from perturbations without human intervention.
