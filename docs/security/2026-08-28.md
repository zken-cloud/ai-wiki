### [Do User-Authored Permission Policies Improve Protection Against AI Agent Overreach?](https://arxiv.org/abs/2608.27443v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27443v1`

A study shows user-authored permission policies using 'allow', 'ask', or 'never' rules block significantly less AI agent overreach than per-action human approval or automated model reviews.

- Evaluated 113 non-software-professional participants across 18-action simulations comparing per-action human-in-the-loop (HITL), automated model review (AUTO), and user-authored consequence policies (POLICY).
- POLICY blocked 20.1 percentage points less overreach than HITL (95% CI (-32.1, -8.1)) and 14.5 percentage points less than AUTO (95% CI (-25.8, -3.2)).
- POLICY reduced runtime prompts from 18.0 to 10.9, but total intervention time was not reliably lower when rule setup duration was included.
- Participants selected 'ask' for 114 of 140 POLICY rules, deferring decisions to runtime where 133 of 148 executed overreach actions were manually approved.
- Out of 148 executed overreach actions in POLICY, 15 ran automatically due to 'allow' rules, leading to POLICY having the highest overall approval rate across all overreach actions.

**Why it matters:** Pre-authored user access control policies fail to reduce AI agent overreach because users default to case-by-case approvals rather than setting restrictive advance rules.

<small>Ting Yan</small>

### [Beyond F1: Evaluating Coverage and Failure Recovery in AI Model Security Scanners](https://arxiv.org/abs/2608.27424v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27424v1`

A benchmark of 170 machine-learning artifacts evaluates static security scanners beyond F1 score by separating judgment accuracy from scanner coverage, analysis completion, and tool redundancy.

- ModelAudit achieved 100% definitive security decisions across 135 labeled artifact families, compared to Fickling at 81.5% (110) and ModelScan at 49.6% (67).
- ModelScan achieved 100% precision, recall, and F1 on the subset of artifacts where it made a definitive judgment, but failed to complete analysis on 48 malicious families.
- ModelAudit and Fickling successfully generated accurate detections for all 48 malicious families that caused ModelScan analysis failures.
- Fickling provided no unique true-positive family detections beyond the combined detections of ModelAudit and ModelScan.

**Why it matters:** Evaluating AI security scanners purely on traditional F1 scores hides analysis completion failures, making multi-metric benchmarks necessary to assess real-world scanner reliability and redundancy.

<small>Qianlong Lan, Vinothini Pandurangan, Anuj Kaul, Indranil Sanyal</small>

### [When Context Gets Root: Privilege Escalation in LLM Harnesses](https://arxiv.org/abs/2608.27299v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27299v1`

Researchers identified instruction privilege escalation, a vulnerability where LLM agent harnesses inadvertently promote low-level untrusted context to higher-privilege instruction levels during context construction.

- Instruction privilege escalation occurs when an agent harness places low-level malicious content into context spaces that the model treats as high-privilege instructions.
- Attacks evaluated across six coding-agent harnesses achieved 13 distinct objectives covering confidentiality, integrity, availability, and remote code execution.
- The attack succeeded 100% of the time under both unrestricted action execution (6/6 harnesses) and automatic permission review modes (3/3 harnesses).
- Vulnerabilities were successfully reproduced using persistent goals, multi-agent mechanisms, and scheduled tasks provided by the harnesses.

**Why it matters:** Model-side instruction hierarchy defenses can be completely bypassed if the surrounding agent harness mismanages context levels during execution.

<small>Xingbang He, Yuanwei Chen, Yi Qian, Haiyang Wei, Ligeng Chen, Zenan Fu, Linzhang Wang, Hao Wu</small>

### [SPA: Securing Persistent LLM Agents Across Queries with Plan-First Information-Flow Control](https://arxiv.org/abs/2608.27234v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27234v1`

SPA is a plan-first architecture that uses a declarative domain-specific language and dual-lattice information-flow control to secure persistent LLM agents against cross-query data flow and control attacks.

- Invokes the planner once per query to generate an executable plan in a declarative domain-specific language.
- Applies dual-lattice information-flow control (IFC) to track confidentiality and integrity across explicit data flows and control dependencies.
- Stores execution results as labeled artifacts, exposing only semantic metadata during subsequent planning to prevent untrusted payloads from re-entering the planner.
- Introduces AgentDojo-MQ, a multi-query benchmark extension designed to measure secure state reuse and delayed security attacks.
- Reduces 'tool_knowledge' attack success to 0% on AgentDojo and 0.2% on AgentDojo-MQ, though strict integrity enforcement reveals a security-utility tradeoff.

**Why it matters:** SPA demonstrates that combining single-pass declarative planning with label-preserving state persistence can effectively prevent indirect prompt injection and control-flow hijacking in multi-query LLM agents.

<small>Dylan Girrens, Guangjing Wang</small>

### [Safety Does Not Compose: Non-Decaying Loop State for Autonomous LLM Agents](https://arxiv.org/abs/2608.27141v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27141v1`

Researchers demonstrate that trajectory-scoped safeguards fail against multi-iteration agent attacks, and propose LoopHarness, a loop-level framework using non-decaying state to bound unauthorized irreversible actions independent of horizon length.

- Trajectory-scoped safety monitors perform no better than random guessing (true-positive rate equals false-positive rate) when attack evidence is fragmented across iterations.
- Carrying a geometrically decaying risk score is ineffective because an adversary only needs to wait a constant cooling-off period regardless of horizon length N.
- LoopHarness maintains persistent, non-decaying state to bound expected unauthorized irreversible actions to B + m - 1 + m/δ_M, a constant relative to horizon N.
- The bound's B + m - 1 component relies on a model-free rule that remains resilient even against a fully colluding verifier.
- Evaluation includes an outer-state attack suite on Agent-SafetyBench, module ablations, and adaptive white-box red-teaming.

**Why it matters:** Autonomous LLM agents operating in multi-step loops require persistent safety state across iterations, as traditional single-trajectory guards cannot detect distributed adversarial attacks.

<small>Chenhao Wu, Haoxuan Jia, Yang Liu, Yingguang Yang, Yuhan Lin, Chongyang Zhang, Hao Zheng, Yulin Huang</small>

### [The Framing Gap: Indirect Prompt-Injection Exfiltration Defeats Surface-Level Defenses in Tool-Using Agents](https://arxiv.org/abs/2608.27092v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27092v1`

Researchers identify the framing gap in tool-using LLM agents, where reframing data exfiltration as legitimate operations increases gpt-4o secret leaks from 0% to 100% despite surface-level prompt injection defenses.

- Reframing exfiltration as integrity signatures, config fields, or look-alike hosts bypasses alignment, driving gpt-4o attack success from 0% to 100%.
- Ablations show the failure stems from instruction/data confusion rather than defeated alignment policies, as removing confidentiality rules leaves base attacks at 0%.
- Payload-blind architectural defenses, specifically destination allow-lists and planner/reader capability isolation, successfully reduced exfiltration rates to 0%.
- Existing defenses like SecAlign fine-tuning (32.5%), channel separation (38.8%), and output-normalizing guards (defeated 100% by ROT13) fail to prevent the attack.

**Why it matters:** Robust agent security cannot rely on the acting model detecting attacks, requiring architectural controls like destination allow-lists and capability isolation instead.

<small>Md Habibur Rahman, Jaeho Kim</small>

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.27009v1`

Researchers created Cautious Bench, a policy-grounded benchmark revealing that agent guardrails suffer from a name-superstition effect, over-refusing safe actions when presented with scary-looking object names.

- Cautious Bench evaluates guardrail over-safety by codesigning sample actions and labels with explicit authorization policies, using a build-time gate to certify label correctness.

### [PLCBench: Can Autonomous LLM Agents Turn PLC Access into Sustained Physical Impact?](https://arxiv.org/abs/2608.26882v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.26882v1`

PLCBench is the first hardware-in-the-loop benchmark designed to evaluate whether tool-using LLM agents can exploit network-reachable commercial PLCs to cause sustained physical impact.

- Evaluates five LLM agent families across 240 real-PLC episodes combining four commercial PLCs with four closed-loop workloads.
- Achieved sustained physical impact objectives in 31.3% (75/240) of overall episodes, with 98 failing before a valid native read and 62 failing after a process-linked write.
- Utilizes a deterministic evaluator with six hidden diagnostic flags tracking native interaction, process-linked manipulation, and sustained physical impact.
- Demonstrates that richer process observation increases the conditional objective attainment rate after a process-linked write from 44.2% to 64.0%.

**Why it matters:** It demonstrates that evaluating cyber attacks purely at the software exploitation or write-access level mischaracterizes physical risk, establishing a realistic baseline for ICS defenses.

### [Daydreaming: Stealing Hidden Agent Skills through Black-Box Task Interaction](https://arxiv.org/abs/2608.26733v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.26733v1`

Daydreaming is a novel execution-only attack that functionally steals multi-file LLM agent skills using adaptive task interactions under strict black-box output constraints.

- Operates at the Output threat level where the attacker only observes final responses and returned files, bypassing direct disclosure defenses.
- Uses attacker-controlled shadow agents and local execution checks to adaptively generate tasks, test specific behaviors, and reconstruct skill files.
- Achieves 86.8% capability recovery of original skills across 7 skills and 4 victim models, outperforming SigLeak by nearly 4x.
- Requires a median of only 32 victim calls per skill to produce fully installable reconstructed skills.

**Why it matters:** It demonstrates that hosted LLM agent services cannot rely on hidden skill files and prompt-filtering defenses to protect proprietary intellectual property from functional theft.

### [Beyond Vector Hiding: Breaking and Mitigating Shared-Direction Weight Obfuscation in TEE-Offloaded Large Language Models](https://arxiv.org/abs/2608.26651v1)

**arXiv cs.CR** · 2026-08-27 · `arXiv:2608.26651v1`

Researchers broke ArrowCloak's TEE weight obfuscation scheme using two attacks, SpectralLeak and LatticeLeak, and proposed a new defense called ButterflyCloak.

- ArrowCloak's reuse of scalar multiples of a hidden direction across weight vectors creates a rank-one relation in the accelerator-visible matrix.
- SpectralLeak targets the real-valued scheme, achieving surrogates with 87.98% mean accuracy compared to 89.85% for victims across 12 task settings.
- LatticeLeak targets the modular (mod-Q) scheme by exploiting the hidden lattice to exactly reconstruct every fixed-point parameter for BERT-Base and GPT2-Base without queries, labels, or fine-tuning.
- ButterflyCloak is proposed as a replacement defense, using a keyed maximal-rank butterfly mask to eliminate shared-direction reuse while maintaining fast TEE correction.

**Why it matters:** It demonstrates that shared rank-one components in model obfuscation allow untrusted accelerators to fully reconstruct protected LLM weights without active querying.

<small>Menghui Zhang, Aoying Zheng, Guoxiao Liu, Zizhuang Deng, Jiejing Wen, Jincheng Zhuang, Ran Tao</small>

### [SILK: Closing the Time-of-Check-to-Time-of-Use Gap in RoT-Protected AI Systems](https://arxiv.org/abs/2608.26402v1)

**arXiv cs.CR** · 2026-08-26 · `arXiv:2608.26402v1`

SILK closes the TOCTOU gap in RoT-protected AI systems by repurposing quantized-weight LSBs as secret-keyed integrity bits and verifying weight streams with commit gating at the final pre-compute boundary.

- Repurposes LSBs of quantized weights as secret-keyed integrity bits and chains byte dependencies to detect post-verification tampering across DRAM, DMA, and interconnect paths.
- Uses a lightweight streaming checker with commit gating to recompute checks without separate authentication tags, causing forgery probability to drop exponentially under a secure PRF.
- Demonstrates zero missed detections across a functional attack suite, with INT8 quality impact under 0.76 pp for evaluated CNNs and 0.17 perplexity across eight LLMs.
- FPGA synthesis on a Xilinx ZCU102 achieves 756 MB/s at 1.00% of the area cost of a Caliptra 2.x RoT, or 678 MB/s at 6.15% RoT cost for a 2^-128 forgery bound.

**Why it matters:** SILK protects neural network weights against physical and interconnect tampering between load-time authentication and execution without needing separate storage tags or substantial hardware overhead.

<small>Ruichen Qi, Xinting Jiang, Ema Dimitrova, Junyi Luo, Quan Cheng, Mehdi Saligane</small>
