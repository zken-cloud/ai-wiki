### [Signed, Sealed, Leaked: Trust Beyond Signature for MCP Toolchains](https://arxiv.org/abs/2611.06585v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06585v1`

Germline execution prevents data exfiltration in signed Model Context Protocol (MCP) tools by executing invocations in ephemeral process copies containing only destination-authorized data.

- Signed and policy-compliant MCP tools can successfully exfiltrate sensitive data to policy-allowed destinations, bypassing state-of-the-art runtime defenses like MCPGuard-Dynamic.
- Germline execution forks ephemeral process copies from a data-free germline process, strictly bounding what a tool can disclose to the specific data provided to its copy.
- Proves sink noninterference under assumptions of copy confinement and a data-free germline, and proves deterministic releases establish flow violations via verified witnesses.
- Across 153 attack trials, germline execution allowed 0 unauthorized disclosures, outperforming baseline defenses which allowed exfiltration in 5.9% to 74.5% of runs.
- Single-copy execution completes in 10-49 ms, achieving a 2-28x speedup over conventional full tool restarts for clearing state.

**Why it matters:** It proves that digital signatures and network policies are insufficient to stop data leaks in AI agent toolchains, offering a mathematically proven, low-latency execution model for runtime isolation.

<small>Yichiet Aun, Mohammed A. Alhartomi, Jing Jie Tan, Waqas Nadeem, Adeb Salh, Shankar Karuppayah, Sin Chee Tan</small>

### [Signed but Steerable: Measuring and Closing the Text-Vector Integrity Gap in Offline Retrieval-Augmented Generation](https://arxiv.org/abs/2611.06498v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06498v1`

Researchers identify a security vulnerability in offline RAG systems where signed text-vector packs allow attackers to steer queries, and propose a deterministic quantisation verification method to close the integrity gap.

- Recomputing vectors and validating via cosine tolerance fails due to the margin law: an idealised tolerance at floating-point noise levels exposes up to 5.5% of queries (1.2% excluding exact duplicates), while an INT8-FP32 calibrated threshold leaves 98-100% exposed.
- On a Raspberry Pi 5 running a local LLM, tampering with signed vectors reduced correct RAG answers from 0.75 to 0.39, while an audit on a 57,638-document FAISS product-quantisation index placed attacker documents first for 25% of targets.
- Standard floating-point and dynamic-INT8 inference pipelines were demonstrated to lack bit-reproducibility across different batch sizes and hardware architectures.
- Verification of quantisation codes using verifier-resolved ambiguity, a calibrated guard band, and canonicalisation accepted all honest vectors across three platforms while eliminating attacker steering capability.

**Why it matters:** Edge devices using offline RAG cannot rely on cryptographic signatures alone to ensure precomputed vector embeddings accurately represent signed text, exposing local LLMs to silent retrieval hijacking.

<small>Georgios Feretzakis, Alexandros Papaspyridis</small>

### [A.S.E 2.0: Understanding How Repository Context Impacts the Security of LLM-Generated Code](https://arxiv.org/abs/2611.06294v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06294v1`

Researchers created CASE-Bench to evaluate how repository context affects LLM code security, finding that functionality-focused contexts and insecure exemplars significantly reduce the generation of secure code.

- CASE-Bench evaluates 145 repository-level tasks from real CVEs across 51 projects using Docker, functional tests, and bidirectional PoC exploits.
- Functionality-oriented context improves the functional pass rate by up to 8.2 percentage points (pp), but only increases the secure pass rate by up to 3.7 pp.
- Withholding security safeguards lowers secure pass rates by up to 8.1 pp, while inserting a single insecure exemplar increases correct-but-exploitable code by 6.3 pp.
- Analysis of six LLMs and 13 context construction methods shows coding agents observe relevant security safeguards in only 27% to 36% of execution trajectories.

**Why it matters:** Context construction algorithms must explicitly prioritize security safeguards, as current functionality-driven methods frequently expose LLMs to insecure patterns or omit critical defense mechanisms.

<small>Jiongchi Yu, Keke Lian, Junqing Wang, Zhikang Fan, Zhaoxuan Li, Yongheng Huang, Ziming Zhao, Dong Zhang</small>

### [Analysis of Local Open-Weight LLM Agents on Vulnerability-Reproduction Tasks](https://arxiv.org/abs/2611.06257v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06257v1`

Researchers evaluated 12 local open-weight LLM configurations on CyberGym vulnerability-reproduction tasks, showing smaller 4B models solve simpler tasks while 27B models are required for harder ones.

- Evaluated 12 model configurations spanning three generations, two architectures, and three quantization levels across ten CyberGym tasks with three runs each.
- All configurations down to 4B parameters solved most of the six easier tasks, but solving the four harder tasks required the 27B model.
- Quantization did not alter which tasks were solved in matched pairs, but it affected speed; mixture-of-experts models achieved identical scores in less wall-clock time.

**Why it matters:** Local, consumer-GPU-compatible open-weight LLMs can execute sensitive automated vulnerability reproduction tasks locally without exposing source code to external cloud APIs.

### [KVGuard: A KV Cache Safety Checker for LLM Serving Systems](https://arxiv.org/abs/2611.06138v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06138v1`

KVGuard is the first systematic memory-safety checker for LLM KV caches, using shadow blocks to detect PagedAttention memory safety bugs with minimal overhead.

- Tracks per-request permissions and per-entry initialization using compact shadow blocks for each physical KV block.
- Performs five safety checks across CPU allocation, block table construction/translation, GPU lookup, and KV entry access.
- Detects double-free, use-after-free, out-of-bounds access, uninitialized reads, and permission violations at the boundary of occurrence.
- Successfully reproduced 29 historical bugs and uncovered 8 previously unknown safety violations in vLLM and SGLang with zero false positives.
- Introduces low overhead: 3.0% (vLLM) and 7.4% (SGLang) geomean TPOT overhead on Qwen 2.5 14B, using under 0.11% of KV cache memory.

**Why it matters:** It enables developers to catch silent, isolation-breaking KV cache bugs during development without the severe performance and memory penalties of traditional GPU sanitizers.

<small>Jonguk Cheong, Myungbin Hwang, Eulgyu Kim, Byoungyoung Lee</small>

### [Securing Web Agents with the Compile-Then-Execute Paradigm](https://arxiv.org/abs/2611.06039v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.06039v1`

Baya introduces a compile-then-execute paradigm for web agents, compiling user requests into Python programs before accessing live web content to structurally prevent prompt-injection attacks.

- Baya compiles user requests into executable Python programs that interact with a Trusted Website API, decoupling the planning model from runtime website observation.
- Untrusted web data can only influence runtime program values or pre-defined branches, preventing it from redefining tasks or synthesizing new operations.
- The Trusted Website API provides a unified view of the website's action space, enabling ahead-of-time planning without stepwise reactive action discovery.
- On 581 WebArena Verified tasks, Baya achieved 77.8% utility, outperforming browser-only ReAct (55.1%) and API-enabled ReAct (66.7%).
- On the WASP security benchmark, Baya achieved a 0% attack success rate, compared to 16.2% for API-enabled ReAct and 25.5% for browser-only ReAct.

**Why it matters:** Separating plan compilation from runtime untrusted web data eliminates prompt-injection control-flow hijacking while simultaneously improving task execution success rates.

### [When File Ingestion Misleads Language Models: Measuring and Mitigating Divergences in Office Documents](https://arxiv.org/abs/2611.05806v1)

**arXiv cs.CR** · 2026-11-04 · `arXiv:2611.05806v1`

Researchers identified extraction divergence in Office Open XML (OOXML) parsers as an attack surface for LLMs, demonstrating five instruction-free attacks and proposing a lightweight defense called Prism.

- Analysis of widely used document extractors revealed 19 OOXML channels containing invisible content read by parsers and 12 channels where visible content is dropped.
- Extractors frequently ignore display formatting and visual reading order, allowing adversaries to manipulate model interpretation (e.g., swapping text box processing order) without changing visual appearance.
- Tested attacks successfully misled four major chat assistants (ChatGPT, Claude, Gemini, Microsoft 365 Copilot) and four coding agents (Codex, Claude Code, Antigravity, GitHub Copilot CLI).
- The proposed defense, Prism, mitigates these vulnerabilities by reconstructing the visual human view directly from the OOXML specification prior to model ingestion.

**Why it matters:** Discrepancies between human-visible document layouts and extractor outputs allow adversaries to secretly manipulate LLM processing and downstream agent behaviors without modifying the visual document.

**arXiv cs.CR** · 2026-11-03 · `arXiv:2611.04941v1`

Researchers evaluate text de-identification privacy metrics by introducing a prior-normalised clipped leakage score and demonstrating how evaluation interfaces alter editor rankings and obscure residual attribute leakage.

- Evaluations of de-identified text depend directly on the chosen interface, including the queried person, answer choices, prior distributions, adversary models, and scoring rules.
- A stress-test editor that inserts opposite-sex forms into redacted spans ranked first under attack accuracy and proper scoring rules despite misleading adversaries, but dropped to sixth of eight under a relabelling-invariant AUC metric.
- Rule-aware adversaries successfully recovered attributes from text modified by the misleading editor.
- Across ordinary releases, varying the adversary model caused metric comparison reversals in 5 out of 124 observed changes.
- The authors introduced SACC, a traceable editor instrument, to ablate two core editing principles and identify the limits of its privacy advantages.

**Why it matters:** Standard privacy evaluations can falsely score misleading redaction techniques as secure, showing that robust auditing requires accounting for adversary awareness and interface-level metric choices.
