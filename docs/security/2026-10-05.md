### [Threat-Preserving Representation Sensitivity in Agent-Security Benchmarks](https://arxiv.org/abs/2610.03585v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03585v1`

Researchers introduce Threat-Preserving Representation Sensitivity (TPRS) to demonstrate that altering agent-visible tool names without changing underlying task mechanics significantly swings LLM agent Attack Success Rates.

- TPRS measures ASR variation when changing agent-visible representations while keeping tasks, harmful actions, security policies, ground truth, environments, and evaluation criteria fixed.
- Replacing threat-related tool names with neutral names on Agent Security Bench (ASB) increases committed ASR by 11.67 percentage points for GPT-5-mini and 13.21 points for Claude Haiku 4.5.
- Adding explicit threat names to neutral tools on MCPTox lowers ASR by 11.00 percentage points on GPT-5-mini and 4.11 points on Claude Haiku 4.5.
- A length-, token count-, and casing-matched neutral name reproduced 8.54 of the 11.00 point ASR drop on GPT-5-mini on MCPTox.
- Modifying tool names with threat-related wording on AgentDojo shifted ASR by only 0.50 percentage points on GPT-4o-mini, but decreased benign utility by 5.36 points on tasks utilizing that tool.

**Why it matters:** Single-representation security benchmark scores fail to generalize, requiring evaluations across controlled threat-preserving representations to substantiate agent robustness claims.

<small>Neeraj Karamchandani, Piyush Nagasubramaniam, Xinhong Xie, Sencun Zhu, Dinghao Wu</small>

### [CorrectGuard: Eyes-Off Correctness Estimation for Black-Box Security Guardrails](https://arxiv.org/abs/2610.03470v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03470v1`

CorrectGuard estimates black-box security guardrail decision correctness in human and machine eyes-off settings using independent external evaluators trained solely on labeled eyes-on data.

- Evaluated in-context learning, embedding, and finetuning methods across 13 safety/security datasets and open-weight guardrails treated as black boxes.
- Achieved up to a 25 percentage-point increase in macro accuracy for error identification using in-context learning, and nearly 15 points using finetuning.
- Reduced Area Under the Risk-Coverage curve (AURC) from 0.33-0.44 down to 0.17-0.22 across three guardrails using correctness score rankings.
- Retained 37.5-52.0% of guardrail decisions at a target threshold of 15% observed risk via decision abstention.
- Implemented machine eyes-off evaluation using privacy-preserving input fingerprinting without requiring internal access to the guardrail.

**Why it matters:** It enables continuous privacy-preserving auditing and risk-based decision abstention for black-box guardrails without exposing sensitive user inputs or model internals.

<small>Adam Faulkner, Nil-Jana Akpinar, Matthew Dressman</small>

### [Passing the Test You Trained On: Re-evaluating Prompt-Injection Detectors for LLM Agents](https://arxiv.org/abs/2610.03448v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03448v1`

Evaluating 15 prompt-injection detectors across BIPIA, AgentDojo, and tau-bench reveals that benchmark detection rankings transfer poorly to agent tool outputs, driven largely by differences in training input structure.

- Benchmark rankings show poor transfer: the top detector on BIPIA caught only 2% of AgentDojo injections at a 1% false-positive rate, while a detector catching 72% on AgentDojo caught only 15% on tau-bench.
- False-positive rates on tool outputs ranged from 0% to over 90% and transferred consistently between the two agent benchmarks.
- Exposing detectors to short attack strings during training failed to generalize to detecting injections embedded inside full agent tool outputs, whereas training on agent-style inputs yielded the best performance across agent benchmarks.

**Why it matters:** Standard prompt-injection benchmarks fail to predict detector performance in deployment, requiring teams to evaluate detectors using low false-positive thresholds on actual agent tool outputs.

<small>Zhuowen Liu</small>

### [Defense-in-Depth at the Perception-Reasoning Interface of LLM-Centric Agentic UAV Swarms](https://arxiv.org/abs/2610.03319v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03319v1`

Researchers implemented and evaluated a five-layer defense-in-depth architecture at the perception-reasoning interface of LLM-centric UAV swarms, using analytical boundaries and deterministic fallbacks to prevent adversarial manipulation of sensor report inputs.

- The defense architecture features five distinct layers: provenance verification, physical admissibility checks, spatial-historical consistency validation, schedule starvation prevention, and fallback to a deterministic scheduler.
- Detection boundaries for the three input-side validation layers were derived in closed form using pre-attack deployment parameters, matching empirical results across 30 simulation runs.

- The safety check layer reduced attack-induced operational costs by 37.5% without directly detecting the underlying attacks.

**Why it matters:** It demonstrates that architectural input-validation defenses can secure LLM-driven autonomous swarms against data poisoning attacks, while quantifying the operational cost trade-offs of fail-safe mechanisms.

### [Securing Computer-Use Agents Against Branch Steering Attacks](https://arxiv.org/abs/2610.03089v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03089v1`

Researchers identified branch steering attacks that exploit dynamic planning in Dual-LLM Computer Use Agents (CUAs), introducing STEER-Bench to evaluate the vulnerability and COBRA, a capability-constrained architecture that mitigates it.

- Computer Use Agents (CUAs) using the Dual-LLM pattern rely on branching plans for dynamic web content, making them vulnerable to branch steering attacks that coerce agents into executing pre-approved hazardous paths.
- STEER-Bench comprises 101 tasks across 9 domains to evaluate branch steering vulnerabilities in CUAs.
- Standard CUAs and vanilla Dual-LLM CUAs demonstrated high attack success rates on STEER-Bench, reaching 94.4% and 89.5% respectively.
- The proposed COBRA architecture combines trusted branching plans with ahead-of-time capability constraints on parameters and destinations, dropping the attack success rate to 0% while preserving 97% benign utility.

**Why it matters:** COBRA provides a secure system-level architecture that prevents adversaries from manipulating CUA execution paths through indirect prompt injection without compromising task performance.

### [Beyond Predefined Sinks: Security-Aware Dependency Analysis for LLM Agents](https://arxiv.org/abs/2610.03014v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.03014v1`

AgentSecGraph is a static analysis framework that generates candidate-centered Security-Aware Agent Dependency Graphs (Security-ADGs) to evaluate LLM agent operation context beyond static predefined sinks.

- Constructs Security-ADGs by enriching operation identity with agent relevance, source/dependency evidence, trust-boundary context, guard evidence, and external-effect semantics.
- Introduces AgentSecBench, a benchmark of 67 real-world LLM-agent repositories covering 11 ecosystems and 37,542 source files.
- Identified 23,866 static security-sensitive operation candidates across 65 repositories, processing the corpus in 50.8 minutes.
- Extracted source-to-operation dependency evidence for 41.15% of candidates and guard evidence for 12.88%, establishing 22 security-sensitive behaviors (1 confirmed vulnerability, 1 pending disclosure, 20 guarded).
- Preserved 91.1% of reference context and 100% of observed guards in nine held-out cases, outperforming sink-only (20.0%) and simplified ADG (40.0%) approaches.

**Why it matters:** Evaluating contextual dependency and guard evidence allows security tools to accurately differentiate between safe and vulnerable operations in LLM agents, which static sink identification alone misses.

### [Frequency Is Not Sensitivity Identifying Safety-Sensitive Experts in Sparse MoE LLM](https://arxiv.org/abs/2610.02910v1)

**arXiv cs.CR** · 2026-10-02 · `arXiv:2610.02910v1`

Router-gradient sensitivity identifies safety-critical experts in sparse MoE LLMs more effectively than activation frequency, enabling targeted expert suppression that significantly reduces model refusal rates without retraining.

- Evaluated across five MoE architectures using 500 benign and 500 malicious prompts, suppressing experts selected by router-gradient sensitivity reduced refusals on held-out prompts more than activation frequency in 24 of 25 conditions.
- On OLMoE, suppressing gradient-selected experts under nominal traffic budgets reduced refusals from 34/100 to 9/100 (a 73.53% relative drop) while maintaining coherent text generation.
- Controlling for layer distributions by matching expert counts per layer, gradient-based selection outperformed activation frequency in 23 of 25 conditions, with two ties.
- Exploratory analysis revealed a strong correlation (Spearman's rho = 0.90, p = 0.083, n = 5) between larger malicious-versus-benign expert concentration gaps and higher peak gradient-driven refusal reduction.

**Why it matters:** Using router-gradient sensitivity instead of routing frequency exposes critical security vulnerabilities in MoE models, demonstrating how targeted expert suppression can bypass alignment guardrails without requiring model retraining.

<small>Md Nurul Absar Siddiky, Liuwan Zhu, Yingfei Dong</small>
