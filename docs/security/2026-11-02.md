### [Inside a malicious Claude Code-branded extension and its persistent SSH backdoor](https://www.microsoft.com/en-us/security/blog/2026/10/30/inside-malicious-claude-code-branded-cursor-extension-persistent-ssh-backdoor/)

**Microsoft Security Blog** · 2026-10-31

A malicious Claude Code extension (versions 2.1.312 and 2.1.313) was briefly distributed on the Cursor marketplace to deploy a persistent reverse SSH backdoor.

- The malicious JavaScript loader runs via Node.js APIs upon module load, prior to normal extension execution.
- The payload appends an embedded public SSH key to authorize access, enables the local SSH service, and configures OS startup persistence.
- It establishes an outbound reverse SSH tunnel using an embedded identity to forward connections to the local SSH port and transmits host reconnaissance data.
- The incident was isolated to the Cursor marketplace; the official npm package (@anthropic-ai/claude-code) and Microsoft Visual Studio Marketplace were unaffected.

**Why it matters:** Developer tool marketplaces present a supply-chain attack vector capable of dropping persistent remote access backdoors onto developer workstations.

### [How Much Can Tool Calls Reveal About You? Privacy Leakage from Tool-Call Traces](https://arxiv.org/abs/2610.41885v1)

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41885v1`

Researchers introduced PrivacyTrace to demonstrate that protocol-valid Model Context Protocol (MCP) tool-call traces serve as behavioral side channels for inferring user profiles without reading conversation texts.

- Introduced PrivacyTrace, a benchmark consisting of 1,000 synthetic user profiles and 4,000 agent trajectories spanning four domains and using real MCP tools from 25 servers.
- Evaluating four mainstream LLM attackers demonstrated a 26.25% attack success rate for user profile inference from tool traces, outperforming the 17.97% baseline from prior-based guessing.
- Tool arguments and returned execution results serve as the primary trace-grounded evidence, with cross-session trace linking further increasing profiling accuracy.

**Why it matters:** Exposing tool-call traces via protocols like MCP creates privacy vulnerabilities by allowing third-party observers to profile users even when direct conversation content is protected.

<small>Donghang Duan, Qingyu Liu, Yifei Liu, Na Zou, Xia Hu, Dongrui Liu</small>

### [What Standard Evaluations Hide About Detectors of Hijacked LLM Agents: Rare Attacks, Unseen Tools and Benchmark Transfer](https://arxiv.org/abs/2610.41803v1)

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41803v1`

An audit of LLM agent hijack detectors reveals that current evaluations mask severe failures under realistic conditions, including low attack prevalence, unseen tools, and cross-benchmark transfer.

- Standard audits overrepresent attacks (16% to 86% of test samples); at a realistic 2% attack rate, a detector with 0.879 AUROC drops to a precision of 0.076.
- Detector rankings reverse when test tool coverage falls below 50% due to unseen tool inputs, though applying dropout to tool inputs mitigates this reversal.
- Detectors trained on AgentDrift perform no better than random chance when evaluated on AgentDojo (AUROC 0.47 to 0.52), demonstrating a severe lack of benchmark transfer.
- The zero-shot monitor AlignmentCheck achieves a 0.930 AUROC on AgentDojo, but its default decision rule yields a low precision of 0.096 at a 2% attack rate.

**Why it matters:** Relying on standard evaluation metrics overstates the real-world reliability of LLM agent detectors, leading to high false-alert rates and complete failure when encountering novel tools or environments.

<small>Mahmoud Abbasi, Juan M. Núñez V., Amin Shahraki</small>

### [When Safety Checks Become Privacy Risks: A Privacy-Preserving Paradigm for LLM Agent Safety Auditing](https://arxiv.org/abs/2610.41401v1)

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41401v1`

Researchers introduced a privacy-preserving safety auditing paradigm for LLM agents that uses encrypted computation to prevent third-party auditors from reading sensitive task histories and tool arguments.

- Separates delegated audit computation from plaintext access using a three-domain model: trusted representation construction, encrypted audit computation, and trusted execution control.
- Instantiated via SealCall, which integrates learned audit representations with CKKS homomorphic encryption for similarity scoring.
- Achieves a mean F1 score of 0.840 across 1,252 public binary candidates under grouped nested evaluation.
- Executes individual encrypted scoring operations in 0.176 seconds while preserving plaintext audit decisions in all tested cases.

**Why it matters:** It allows LLM agent operators to outsource pre-execution safety checks to external vendors without exposing sensitive user inputs or execution histories.

### [Erase the Injected Region: Multimodal Prompt-Injection Defense with On-Policy Self-Distillation](https://arxiv.org/abs/2610.41307v1)

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41307v1`

ERASE is an on-policy self-distillation defense against multimodal indirect prompt injections that replaces injected regions with modality-appropriate blank content, providing token-level feedback from a frozen base model to preserve task utility while blocking attacks.

- ERASE constructs reference inputs by erasing injected media regions in place using modality-appropriate blank content while preserving surrounding context.
- The student model processes attacked media and receives full-distribution token-level feedback generated from its own rollouts against a frozen base model processing the erased media.
- Evaluated across image, audio, and video modalities, ERASE achieved near-zero attack success while maintaining task utility close to clean-input levels.
- On a 3B audio model, ERASE achieved 60.1% attacked-input accuracy (compared to ARGUS's 33.1%) and reduced injection dependence from 6.26 to 0.0095.
- Out-of-domain accuracy and erased-input performance remain close to the undefended base model.

**Why it matters:** It enables multimodal models to successfully defend against indirect prompt injections without sacrificing performance on legitimate user tasks embedded in the same media.

<small>Shuo Hong, Jiaxin Ma, Xidi Cai, Qianli Ma</small>

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41272v1`

REEF and ANGLER introduce a verifier-grounded web agent benchmark across 9 environments and an adaptive red-teaming framework that uses state-based execution feedback to evolve multi-level adversarial attacks.

- REEF spans 9 executable web environments across 5 domains, pairing benign tasks with malicious objectives across 5 attack types at user and environment levels.
- ANGLER uses real state-change feedback from prior rollouts to drive LLM-based attack mutation, prioritizing near-miss seeds during candidate selection.

### [When AI Investigators Cannot Trust Their Tools: Conflict-Aware Evidence Verification for Cyber Threat Investigation](https://arxiv.org/abs/2610.41191v1)

**arXiv cs.CR** · 2026-10-30 · `arXiv:2610.41191v1`

Conflict-Aware Evidence Verification (CAV) restores LLM threat investigator accuracy under corrupted detector outputs by using an equal-weight vote, an evidence-conflict gate, and an independent nearest-neighbor trust check.

- Unverified LLMs (3B to 14B parameters) fail under tool corruption: a single corrupted detector drops accuracy to 0.50-0.72, three lower it to <=0.13, and honest tool disagreement causes up to 63% abstentions on CIC-IDS2017.
- CAV combines an unweighted vote ignoring tool-reported confidences, a conflict gate, and an independent nearest-neighbor verification step on leading candidates.
- CAV-LLM achieves 0.84-0.88 accuracy with three corrupted detectors (versus <=0.08 for naive LLMs) while executing LLM calls on only 0.4% of clean traffic.
- Verification performance relies on the integrity of the independent check: if the nearest-neighbor channel becomes noisy, CAV inherits its error profile.

**Why it matters:** It demonstrates that automated LLM security agents cannot naively trust detector outputs and provides a lightweight mechanism to maintain high triage accuracy under corrupted context.

<small>Yuchen Zhang</small>

### [Accept Changes, Reject Attacks: Robust Memory Management for LLM Agents](https://arxiv.org/abs/2610.41056v1)

**arXiv cs.CR** · 2026-10-29 · `arXiv:2610.41056v1`

A new framework formalizes LLM agent memory robustness against both outdated information and memory poisoning attacks, evaluating performance via Evidence-Conditioned Accuracy (ECA) and offering a synthetic fine-tuning recipe to double ECA scores.

- Identifies two opposing memory failure modes: failure to overwrite outdated facts and vulnerability to storing memory poisoning attacks or injected instructions.
- Introduces Evidence-Conditioned Accuracy (ECA), a metric requiring selected memory records to contain all required, updated evidence while remaining attack-free.
- Proposes a one-shot fine-tuning recipe using synthesized episodes built from a single conversation augmented with inserted updates and attacks.
- Demonstrates that existing defenses underperform, while the proposed fine-tuning method improves scores across all categories and more than doubles overall ECA across three model backbones.

**Why it matters:** It enables LLM agents to safely update long-term state over extended interactions without becoming vulnerable to malicious injections or relying on stale information.

### [Characterizing Recoverable Expert-Utilization Signatures in Fine-Tuned Mixture-of-Experts LLMs](https://arxiv.org/abs/2610.41039v1)

**arXiv cs.CR** · 2026-10-29 · `arXiv:2610.41039v1`

Researchers identified structural memorization in fine-tuned Mixture-of-Experts (MoE) LLMs, where expert routing pathways create distinct fingerprints recoverable via unconditional generation logits.

- Fine-tuned MoE models exhibit structural memorization, retaining specific internal routing pathways from as few as a few training samples.
- Adversaries can extract memorized expert pathways using routing and output logits during unconditional generation, requiring no prior knowledge of the fine-tuning data.
- Routing exposure across federated aggregation points, edge-cloud interfaces, and multi-tenant monitors amplifies vulnerability in distributed deployments.
- Traditional membership inference metrics fail on structural pathways, requiring new composite metrics that combine reference model tail likelihood with complexity-aware normalization.
- Recovered routing signatures allow attackers to target specific dominant or dormant experts for router manipulation or backdoor injection.

**Why it matters:** Exposing MoE routing information in distributed or multi-tenant deployments allows adversaries to identify fine-tuned expert pathways and execute targeted backdoor or manipulation attacks without access to training data.

<small>Fei Wang, Baochun Li, Bo Li</small>
