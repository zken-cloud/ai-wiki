### [AgentLSD: Evaluating AI Security Agents Under Adversarial Task Contamination](https://arxiv.org/abs/2609.19140v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.19140v1`

AgentLSD is a benchmark framework that evaluates AI security agents under adversarial task contamination by injecting non-instructional trap artifacts into web Capture the Flag (CTF) challenges without altering valid solution paths.

- Task contamination expands beyond prompt injection to include non-instructional evidence like fake flags, misleading hints, and decoy endpoints.
- Evaluated across six models on 11 web CTF challenges, clean condition agents achieved a 41% base flag capture rate.
- Even when successfully recovering flags, task contamination increased agent workload by an average of 20 turns and 2,000 reasoning tokens.
- Contamination impact on solve rates was heterogeneous, causing certain model-challenge pairs to follow decoys or submit incorrect flags while others remained unaffected.

**Why it matters:** Standard clean CTF performance metrics overestimate AI security agent robustness by ignoring how deceptive environment evidence increases operational overhead and causes task deviation.

<small>Matteo Golinelli, Idilio Drago, Matteo Boffa, Francesco Bergadano, Bruno Crispo</small>

### [When Agents Look Like Beacons: NIDS Evasion by Model Context Protocol Traffic](https://arxiv.org/abs/2609.19091v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.19091v1`

Researchers demonstrate that Model Context Protocol (MCP) traffic mimics C2 beaconing patterns but evades detection by current NIDS signatures and RITA behavioral scoring across multiple TLS inspection conditions.

- Tested MCP JSON-RPC traffic across 11 traffic profiles and three TLS conditions (Opaque, TLS-Inspected, and Cleartext) in a Docker testbed.
- MCP traffic consistently yielded a 0.0 behavioral beacon score in RITA and generated near-zero content alerts using Suricata with the Emerging Threats Open ruleset.
- NIDS heuristics failed to flag the lognormal inter-arrival distributions of agent reasoning loops, leaving MCP exposed to flow-level temporal analysis when TLS is opaque.
- Authors propose an agent-native network indication standard featuring Agent-Native ALPN and standardized out-of-band headers to resolve the detection gap.

**Why it matters:** Enterprise defenders cannot rely on traditional C2 beacon-scoring tools to detect potential threats, as legitimate AI agent traffic over MCP mimics malware polling without triggering existing IDS alerts.

<small>Muhammad Abdullah Sohail</small>

### [ASLEval: Measuring Privacy Exposure Displacement in LLM Agent Sessions](https://arxiv.org/abs/2609.18864v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18864v1`

ASLEval is an authorization-aware evaluation framework designed to capture privacy exposure displacement in multi-step LLM agent sessions by measuring all declared visible exits against a pre-registered hidden target set.

- Privacy exposure displacement describes the mismatch between localized evaluation proxies (e.g., final responses or attacker self-reports) and actual session-level privacy exposure.
- Evaluating only the expected outlet misses 46.9% of total privacy exposure identified by analyzing the union of all visible exits.
- Attacker self-reports introduce omissions alongside high false discovery rates, whereas schema-aligned internal trace evidence typically precedes visible external exposure.
- Restricting model-visible returns alters disclosure paths but can completely eliminate normal task utility and success.

**Why it matters:** Evaluating LLM agent privacy solely through final outputs or attacker reports severely underestimates data leaks, necessitating comprehensive, boundary-wide monitoring paired with utility tracking.

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18862v1`

CASHEWS is a JavaScript preprocessor that uses iterative deobfuscation, static slicing, and module extraction to shrink code size and improve LLM-based malicious npm package detection.

- CASHEWS applies iterative decoding, extracts bundled modules and dynamic code, computes backward slices to malicious sinks, and abbreviates long literals and identifiers.
- Improves LLM analysis coverage on 512 large package files from 69.1-85.7% up to 98.8-100%.

**Why it matters:** By removing token-dense obfuscation and irrelevant code, CASHEWS prevents threat actors from evading context-limited LLM scanners while reducing the overall financial cost of registry-wide security analysis.

### [Normal Alignment: Improved Cryptanalytic Sign Recovery on Hard-Label Networks](https://arxiv.org/abs/2609.18751v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18751v1`

Normal Alignment improves hard-label neural network extraction by using statistical normal-signature alignment to achieve polynomial-time full sign recovery where prior methods required exponential enumeration.

- Carlini et al.'s prior 'Future Toggle' sign-recovery method suffered from high-confidence wrong predictions in deep layers, causing exponential enumeration overhead.
- Normal Alignment infers neuron signs by evaluating the expected length difference between projected normals of adjacent decision facets at dual points.
- Combining Normal Alignment with the hard-label SOE extension (eSOE + Alignment) pushes errors to low-confidence ranks and enables exact polynomial-time full sign recovery.
- Successfully recovered full signs in polynomial time for CIFAR-10 (192-64x8-10) and MNIST (64-96x3-32-10) architectures, bypassing previous requirements of 2^52 and 2^82 sign guesses.

**Why it matters:** It removes the bottleneck of exponential-time sign enumeration, making complete model extraction practical and efficient for deep hard-label neural networks.

<small>Shi Tang, Zirui Chen, Yongjia Su, Zhengchao Gao, Lingyue Qin, Xiaoyang Dong</small>

CaMeLoT extends the CaMeL defense framework by adding a static pre-execution verification layer that uses CTL model checking to audit LLM agent plans before tool execution.

MiST introduces 8B and 32B cybersecurity LLMs adapted via a mid-training stage using synthetic data generated from a compact, expert-vetted seed corpus.

### [The Verifiable Action Card: Trustworthy Human-in-the-Loop Control for Secure Autonomous Agents](https://arxiv.org/abs/2609.18411v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18411v1`

The Verifiable Action Card (VAC) is an architectural defense for agentic browsers that enforces human-in-the-loop approval by rendering out-of-band, ground-truth action descriptors and re-verifying intent provenance directly at dispatch.

- Combines five security mechanisms: provenance fencing, ground-truth action descriptors, default-deny confirmation, provenance-aware risk gating, and execution binding.
- Renders confirmation prompts out-of-band in the trusted browser chrome to prevent indirect prompt injection and dialog forging from manipulating approval text.
- Binds user approval directly to the final action re-verified at the point of execution.
- Evaluated on a 24-scenario benchmark where it reduced attack success rates from 68%-100% down to 0% across tested LLMs, maintaining a 78% legitimate task completion rate and 0% false-block rate.

**Why it matters:** Grounding confirmation in actual browser-level execution state prevents untrusted web content or compromised LLMs from tricking users into approving malicious actions.

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18272v1`

A new framework formalizes agentic AI auditing by grading auditor independence across three orthogonal axes—principal, substrate, and evidence—and combining them using a common-cause failure beta-factor model.

- Independence is graded on three axes: principal control, shared substrate (foundation models, toolchains, or guardrails), and evidence attestability versus self-reporting.
- Overall audit independence is aggregated by the weakest link among the three axes and evaluated using a seven-step third-party verifiable protocol.
- Employs a reliability engineering beta-factor model to quantify common-cause failures between auditor and auditee agents.
- A Monte Carlo simulation showed conventional internal audits surfaced only 5.9% of observable faults, failing to detect any faults in half of the fault classes.
- Maps the three-axis framework directly to the amended EU AI Act, ISO/IEC 42006, and UK public-sector risk-management guidance.

**Why it matters:** Binary independence models fail to capture common-cause AI failures, leaving organizations vulnerable to undetected risks when using internal or structurally coupled agents as auditors.

### ["Your Robot Was Trained on a Lie": Collision Mesh Poisoning Attacks on Robotic Manipulation](https://arxiv.org/abs/2609.18122v1)

**arXiv cs.CR** · 2026-09-16 · `arXiv:2609.18122v1`

Collision Mesh Poisoning (CMP) exploits the Visual-Collision Gap in 3D simulator assets by altering only collision meshes, causing policies trained in simulation to fail or create safety risks in the real world.

- Introduces Collision Mesh Poisoning (CMP), the first data poisoning attack delivered via the 3D asset supply chain for robotic manipulation.
- Exploits the Visual-Collision Gap (V-C Gap), where coarse collision meshes used for simulator efficiency deliberately differ from visual meshes.
- Poisoned assets pass standard simulation evaluations and asset reviews (malware, copyright, format checks) but cause policy degradation or physical safety risks upon real-world deployment.
- Evaluated existing defenses and demonstrated that current mechanisms are insufficient to counter CMP attacks.

**Why it matters:** Robotic policies trained safely in simulation can be covertly compromised through standard 3D asset supply chains, leading to unexpected failures and physical safety hazards during real-world execution.

Researchers demonstrate a modern 'Trusting Trust' attack by poisoning self-evaluation benchmarks in self-modifying AI coding agents, forcing them to self-evolve into writing vulnerable code on clean, held-out tasks.

- Reinterprets Ken Thompson's compiler backdoor attack for self-improving AI coding agents using poisoned benchmarks during self-evaluation.
- Validated against three agent architectures: Darwin Gödel Machine, Self-Improving Coding Agent, and Hyperagents.
